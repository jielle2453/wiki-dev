| `tools/release.py` | 發行程式（開發用、不進 zip，D-213、D-216～D-218）：`build <tag>`（git archive → 照 D-213 清單含 `agents/` 打可重現的 zip 到 `dist/`；最後檢查：只有清單上的、`plugin.json` 與 `hooks.json` 引用的路徑都在、版本等於 tag、CHANGELOG 最新一段有給客戶的一句話、`skeleton_history.json` 有這版且對得上；小修跟上一個 tag 比不准動骨架檔、各 SCHEMA／TEMPLATE 版本常數、`_lib/migrate.py`；印 sha256）、`build --prepare`（在發行 commit 裡把這版骨架指紋追加進 `config/skeleton_history.json`）、`publish <tag> --public <clone> (--for <id>…｜--all｜--none) [--wait 15]`（`gh release create` → 更新 `marketplace.json` 推 → 每 30 秒抓清單到抓得到新版才改 `rollout.json` 推；超過停下來、名單沒改；中途失敗直接重跑，release 已經有了就 `gh release upload --clobber` 補傳同一個 zip、上次沒推的 commit 一起推）、`rollout <版本> --public <clone> …`（只改名單，撤回是 `--none`）；publish 與 rollout 開頭擋公開 clone 有沒 commit 的改動（`_require_clean`，沒加進 git 的檔不算），commit 只收清單或名單那個檔；版本與 tag 跟客戶端同一套嚴格比對；git、gh、抓清單、等待都經 `_run`、`_fetch`、`_sleep`、`_clock` 給測試換替身；不建、不動任何 GitHub repo 由人決定；測試後修正：publish 的清單與名單網址、一句話都從 tag 讀（兩個網址都要是 https），origin 只認 github 標準寫法（帶帳密或別家一律拒、不印網址），小修規則多抓名稱含 SCHEMA 的常數與字面的 `"schema_version": N`，名單 id 整串比對，build 回並印略過的頂層，`--repo`／`--out` 一律轉絕對路徑；換版前先驗新版（D-230）：`build` 多兩項最後檢查——每個 .py `ast.parse(feature_version=(3, 10))`（「<檔> 第 N 行：Python 3.10 不認得這種寫法」）、打好的 zip 解開跑它的 `kb selftest --json`（`_selftest` 給測試換替身）；zip 先寫暫存名，全部過了才改名，有問題不留、不動先前同名的那份（裁定 16）；小修一批：字面的 `"schema_version": N` 改用 ast 認（`_schema_literals`：dict 字面的鍵與呼叫參數 schema_version=N），docstring、註解、一般字串不算，讀不懂的檔退回正規式（B-448）；Obsidian首頁（#22，D-258）：`ALLOW_DIRS` 多 `obsidian`；最後檢查多 `_obsidian_problems`（三個檔都在、manifest.json 合法 JSON、版本等於 tag） |
