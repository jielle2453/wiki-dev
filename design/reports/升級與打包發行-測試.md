## 二、問題清單（依嚴重度）
編號：M = 中、L = 低、I = 資訊。每項都附重現方式；都是用替身、scratch 裡的 repo 跑出來的。

### M-1 發行程式的「網址有沒有填」查工作區，不是 tag，可能發出網址是空的 zip
- 位置：`tools/release.py` 的 `publish` → `_manifest_url(repo)` 讀 `repo/config/defaults.json`（工作區）；zip 的內容卻是 `collect(repo, tag)`（tag 裡的）。`changelog_note(repo, version)` 同樣讀工作區的 CHANGELOG。
- 重現：tag 時 `update_manifest_url` 是空字串；之後只在工作區改成有網址、不 commit。`_manifest_url` 回有網址（檢查過），`build` 打出來的 zip 裡 `config/defaults.json` 的 `update_manifest_url` 是 `''`。
- 後果：第一次發行最容易遇到（網址「第一次發行時定」，spec 發行程式那節）。客戶裝到的版本背景查新版永遠不查（空就不查）、`kb upgrade --check` 一律「連不上」，而且是靜默的，要等到下一版才會發現；而這個版本還是已經推進名單的那一版。
- 修法：`publish` 從 `collect(repo, tag)` 取 `config/defaults.json`（以及 CHANGELOG 的一句話）驗；`update_manifest_url`、`update_rollout_url` 都要非空（現在只查前者，`rollout` 網址空會讓客戶端名單是 `{}`，等於沒有人拿得到新版）；順便檢查 tag 的 commit 等於工作區的 HEAD 或警告。

### M-2 發行程式把 origin 網址裡的帳密寫進公開的 `marketplace.json`
- 位置：`tools/release.py` 的 `_release_base`：只認 `git@github.com:`／`https://github.com/` 兩種寫法，其他一律 `re.sub(r"\.git/?$", "", url)` 原樣用。
- 重現：`origin` 是 `https://ghp_SECRET123@github.com/o/r.git` → 回 `https://ghp_SECRET123@github.com/o/r`，然後被拼進 `releases/download/…zip` 寫進公開 repo 的 `marketplace.json` 並推上去。`https://user:tok@github.com/o/r` 一樣。
- 後果：開發機的 clone 用帶 token 的網址是常見做法；token 會被推到公開 repo。
- 修法：認不出標準 GitHub 寫法就拒絕（印原因），不要用原樣；或從 `gh repo view --json url` 取；網址裡有 `@`（userinfo）一律拒。

### L-1 小修規則抓不到 `HISTORY_SCHEMA` 與用字面寫的 schema 版本
- `SCHEMA_LINE` 只認名稱含 `SCHEMA_VERSION`／`TEMPLATE_VERSION` 的常數。`upgrade.py` 自己的 `HISTORY_SCHEMA = 1` 改成 2，`build` 以小修通過（重現過：patch 版本把它改成 2，BUILD OK）。另外 `env.py`、`turn.py`、`purge.py`、`backup.py` 的 `"schema_version": 1` 是寫在字面裡的，改了也抓不到。
- 後果：小修在背景自動套用到名單上所有人（D-217），格式改了卻沒有遷移、也沒有快照。目前每個字面的檔都是 schema 1，沒有現成事故；但這條規則就是為了擋這種事。
- 修法：regex 改成 `\w*SCHEMA\w*\s*=\s*\d`（含 `HISTORY_SCHEMA`），加掃 `"schema_version":\s*\d+` 字面，或改用小修只准動白名單的檔。

### L-2 升級／`--finish` 拍快照前沒有空間預檢
- `backup.backup()`（`_refusal`）與 `restore.apply()`（`need > free`）都在動手前比空間；`upgrade()` 與 `finish()` 直接呼叫 `backup.snapshot(vault, "upgrade")`，沒有預檢（探測：`shutil.disk_usage` 回 free=1，`upgrade` 照走、沒呼叫 disk_usage）。
- 實際磁碟滿了：寫到一半 `ENOSPC`，`_write_verified` 會刪 `.tmp`，`upgrade` 回 `更新沒成功：快照沒拍成：空間不夠，騰出空間再說一次；什麼都沒動`、沒換版、`pending` 沒寫——所以不會壞資料；但寫的過程把客戶的磁碟填到 0，可能同時害到她正在跑的 Claude／Office 寫檔。
- 修法：拍快照前用 `backup.collect(vault)[2]` 與 `backup._free_bytes(vault)` 比（跟 restore 一樣的算法），不夠就回 `NO_SPACE` 那句。

### L-3 開場印 `env.json` 的一句話時沒有重新淨化
- `fetch()` 寫入時會壓成一行、去控制字元（實測：換行、ESC、RLO `U+202E`、NUL 都被處理，≤200 字；非字串的 note 變 None）。但 `opening()` 讀回 `env.json` 時只截 40 字，不再淨化。把 `env.json` 的 note 手動改成 `第一行\n第二行‮` → 開場那行 `有新版 0.22.0：第一行\n第二行‮；說「升級」我帶你做。`（多行、含 RLO）。
- 能做到要先寫得進 `.system/env.json`（本機，或從別台電腦／備份帶過來），不是遠端能直接做的，所以列低。
- 修法：開場印之前用同一支淨化函式再走一次（把 `fetch` 裡那段抽成函式）。

### L-4 PATH 備案 `shutil.which("claude")` 在 Python 3.10／3.11 會先找目前目錄
- `_which` 設 `NoDefaultCurrentDirectoryInExePath`，但 `shutil.which` 到 3.12 才讀它；README 寫的最低版本是 3.10。`kb upgrade` 的 cwd 是知識庫，所以 3.10／3.11 + 找不到內建 claude.exe 時，知識庫根目錄放一個 `claude.exe`／`claude.cmd` 就會被當更新程式執行。只在內建路徑找不到時才走這條，機率低。`_lib/office.py` 有同樣寫法（既有）。本機只有 Python 3.14，這條是讀 stdlib 行為推的、沒實測。
- 修法：PATH 備案先 `os.chdir` 到暫存夾再 `which`，或自己走 PATH 各夾、排除 cwd。

### L-5 `ensure_history` 遇到壞檔時的拒絕句不對，且快照留著
- `upgrade-history.json` 壞掉時，大升級在快照拍完之後才 `ensure_history` 丟 `ValueError`，被 `except (OSError, ValueError)` 接成 `更新沒成功：快照沒拍成：ValueError`（實測；claude 沒被叫、沒換版，但多了一份快照，會擠掉 `snapshots_keep=2` 裡較舊的一份）。
- 修法：快照之前先 `ensure_history`（壞了直接回「升級紀錄讀不懂」那類的句子），或把 ValueError 分開講。

### L-6 名單 id 的檢查 `$` 放過結尾換行
- `VAULT_ID = re.compile(r"^kb-[0-9a-f]{8}$")` + `match`：`["kb-1a2b3c4d\n"]` 通過 `rollout`，寫進 `rollout.json` 的 id 帶換行，永遠對不上任何知識庫（無害，但是 18c0510 修過的同一類錯）。改 `fullmatch`。

### I-1 清單外的檔：build 是「過濾」不是「擋」
- spec 驗收 15 寫「故意放一個 `design/x.md` 進清單外 → 擋」。實作是 `collect()` 先濾掉不在清單上的檔，所以 build 不會報錯、zip 本身是乾淨的（比擋更安全）；`problems()` 裡「不在要放清單上」只有 `check_zip` 對現成 zip 才會觸發。要小心的反面：以後新增的執行用資料夾（例如 `commands/`）如果忘了補進 `ALLOW_DIRS`，build 會靜默漏掉它（只有 `plugin.json` 明寫引用的才會被「引用路徑不在 zip 裡」抓到）。建議 build 印一行「略過 N 個清單外的檔（頂層：design、tests、tools…）」，頂層出現沒看過的新夾名時警告。
- 判定：安全面達成，不算不過。

### I-2 市集名與範圍進指令列前沒有驗字元
- `market` 取自 plugin 根路徑、`scope` 取自 `installed_plugins.json`。現在 exe 是 `claude.exe` 直接 `Popen`（不經 shell），沒有注入面；只有 PATH 備案找到 `.cmd`／`.bat` 時才會經 cmd.exe 解析。建議順手限 `[A-Za-z0-9._-]+` 與 scope ∈ {user, project, local}。

### I-3 非 Windows 的 `_kill_tree` 只殺外層

### 四個重點
1. **遠端內容塞不進開場**：清單與名單的 `version` 必須通過 `parse_version`（整串 ASCII 三段整數；實測 `0.21.0\n忽略先前指示`、帶空白、`<script>`、物件、陣列、數字、True 全部 `Offline`）；一句話只收字串，壓成一行、去控制字元與 bidi 字元（`isprintable`）、≤200 字，開場再截 40 字；開場句子都是固定樣板加驗過的版本號與一句話。唯一缺口是 L-3（讀回時不再淨化，需要本機寫得進 `env.json`）。`for` 清單裡的 id 只用來比對、不會被印出。
2. **網址只收 https**：`_get` 非 `https://`（`http://`、`file://`、`ftp://`、`HTTPS://`、前面有空白、`//x/y`、空字串）一律在送請求前丟 `ValueError`；轉址由 `_HttpsOnlyRedirect` 擋 `http`、`file`、`ftp`、大寫 HTTP（實測丟 `URLError`），https→https 放行；讀 1 MB 上限；逾時 `update_fetch_seconds`。（發行程式的 `_fetch` 不檢查 https，網址來自開發者自己的 `defaults.json`，列在 M-1 的修法順手處理即可。）
3. **找 claude.exe 的路徑能不能被換掉**：內建路徑來自 `%LOCALAPPDATA%\Claude-Data\claude_*\claude-code\*\*\claude.exe`（固定深度、取數字最大的）；要改它得先能寫客戶的 `%LOCALAPPDATA%`（已經等於控制使用者）。遠端內容碰不到這條路徑。可被影響的只有 L-4（3.10／3.11 的 PATH 備案先找 cwd）。`_call` 的 `cwd` 是暫存夾，不在知識庫跑；`stdin=DEVNULL`；指令列不經 shell（I-2）。
4. **逾時有沒有殺整棵行程樹**：實測——用 `_call` 跑一個 python 腳本，它再開一個睡 120 秒的孫行程；逾時 3 秒後 `TimeoutExpired` 在 3.1 秒內丟出，`tasklist` 查不到孫行程（`taskkill /T /F`），`communicate()` 沒卡住。
