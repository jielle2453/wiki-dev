## 問題清單（依嚴重度）

### 高

**T-1 還原舊備份後 hidden 排除沒有真的清掉（驗收 14 不過）**
- 位置：`scripts/kb/_lib/restore.py` 的 `_reapply_hidden`（約 375～410 行）。
- 證據：照 manage 第二版的做法組一個有私人夾（含一張卡）的知識庫 → 備份 → 排除成 hidden（`folders exclude` 當場清完，快照也刪了）→ `restore check` 的 `hidden_reapply` 有那夾 → `restore apply` 舊備份。結果：`sources.json` 有那條 hidden 排除、`purge` 欄位寫成已完成日期、輸出說「也再清了一次」；但 `檔案索引/…/<卡>.md` 還在，內文獨特字串還在，`.system/inventory.json` 還有那個編號。接著 `inventory scan`、`cards sync` 後仍在（掃描只把原檔記成「不見」、清冊條目沒標 excluded、卡沒拿掉），`pending.json` 還多出來一筆；`purge` 已經標完成，沒有後續會再清。
- 原因：`_reapply_hidden` 寫回排除列後直接叫 `purge.purge`，沒有做 `folders exclude` 那條路的對帳（`inventory.reconcile` 把還原回來的清冊條目標成 excluded、拿掉那些條目的檔案卡、重寫總目錄與綜合卡快取）。`purge` 找要清的編號時扣掉 active 的條目，還原回來的條目都是 active，所以找不到東西可清，卻回報完成。
- 影響：D-174 的核心承諾（不想讓 AI 看到的夾，清乾淨）在「還原一份比排除舊的備份」這條路上破功，而且回報說已清。AI 讀卡不經守門，卡裡的內容會被讀到。
- 建議：還原後寫回排除時，走跟 `folders exclude --kind hidden` 同一支程式（對帳、拿卡、重寫索引與綜合卡、purge），或至少在 purge 前先 `inventory.reconcile`；`purge` 回報「找不到要清的編號」但清冊裡有那夾的 active 條目時不要標完成。重測用同一個腳本情境，卡檔、清冊、全庫 grep 都要是 0。

**T-2 換位置、換電腦的偵測在真實起點不會觸發**
- 位置：`scripts/kb/_lib/moved.py:31`（`state`）、`hooks/session.py` 的 `line_moved`；`env.set_vault_path` 只在 `moved.apply` 裡被叫。
- 證據：用了幾個月的知識庫（沒有 `env.json`）開場 → 不印任何東西、也不寫 `vault_path`；用檔案總管把整個資料夾搬走再開場 → `state` 仍是 `first`、開場沒有換位置那句；`kb moved --check` 回 `first`、`sources_rewritten` 是空的；`kb changes` 只說「這台電腦找不到來源：…」。相對位置的來源全找不到，卻沒有東西認得是搬家。換電腦同理：別台要有 `vault_path` 才算「別台有紀錄」，舊電腦沒記就是 `first`。
- 原因：spec 起點表寫「第一次跑任何這題的指令或開場：位置記下來當沒換過」，但釐清第 2 點又寫「開場只讀、不寫 `vault_path`（`kb moved` 做完才寫）」，而 `first` 狀態開場不印任何一行，所以沒人會跑 `kb moved`。`kb backup`、`kb restore`、`versions clean`、`kb init` 也都沒記位置。這是 spec 兩處互相打架，實作照其中一處，沒有人補上另一處。
- 影響：驗收 15、17 只在人為先寫好 `env.json` 時過；桌面版確認步驟 7（剪下貼上後開場那句）、8（複製後提醒舊位置）、9（刪掉整個知識庫再還原）會失敗，除非先做一次 `kb moved` 或在舊位置跑過會記位置的指令。`references/ops.md` 說「開場多半多一行」也跟著不成立。舊的知識庫沒有 `vault.json` 時，複製後 `old_copy` 也認不出來（`moved.apply` 在新位置才補編號）。
- 建議（交設計定）：`kb backup`、`kb restore apply`、`versions clean`、`kb init`（或任何一支這題的指令）成功時記 `vault_path`（不是開場記）；或開場在 `first` 時印一行讓 AI 跑 `kb moved` 記位置；`ensure_vault_id` 也在這些指令第一次跑時補。同時改正 spec 的兩處說法。

### 中

**T-3 還原中途的非 `OSError` 例外會遺失還原前的資料**
- 位置：`restore.py` 的 `_swap_in`（361～372）與 `apply`（453～474）。
- 證據：在第 16 次搬動丟 `RuntimeError`／`KeyboardInterrupt`：還原前的 20 個檔案在知識庫裡不見（`.claude/settings.json`、`.system/agenda.json`、`entities.json`、`inventory.json` 等），`restore-old` 已被刪，知識庫處於換到一半的狀態；只剩剛拍的快照。另測最後一次搬動失敗又有一個倒不回（替身）：`_undo` 吞掉失敗、`apply` 的 `except BaseException` 仍 `rmtree(restore-old)`，還原前的一個檔（新卡）永久不見，而句子仍說「什麼都沒動」。
- 原因：`_swap_in` 只在 `OSError` 時倒回；其他例外與 `_undo` 失敗時，外層一律刪 `restore-old`。
- 建議：`_swap_in` 對 `BaseException` 都倒回；倒不回時不要刪 `restore-old`，把它的位置寫進那一句（「有東西沒移回，在 .system/temp/restore-old-…」）；`apply` 的 `except BaseException` 只刪 `extracted`，不刪 `old_dir`。

**T-4 還原時 hidden 排除被降成 unused**
- 位置：`restore.py:382`（`have` 只比 `(別名, spec)`，不看 kind）。
- 證據：現在是 hidden（`purge` 已完成）、備份裡同 spec 是 `unused`；`restore check` 印「你設成不想讓 AI 看到的「X」會留著，還原後再清一次」，`restore apply` 後 `sources.json` 的排除變成 `unused`，沒有 purge，那夾的卡回來。
- 建議：`have` 要看 kind，現在是 hidden 而還原後是別的 kind 就換成 hidden（同 T-1 的路徑清）。

**T-5 修改時間早於 1980 的檔讓備份與還原永遠失敗**
- 位置：`backup.py:150`（`z.write`）。
- 證據：知識庫裡一個檔的 mtime 設成 0 → `kb backup` 印 `備份沒有做成：ValueError`、備份夾沒有任何檔；每次都這樣。還原先拍快照，同一支寫 zip，所以這種知識庫也還原不了（`還原沒有做成：ValueError`）。
- 建議：`ZipFile.write` 前用 `ZipInfo.from_file(..., strict_timestamps=False)` 或 `z.write` 改成 `ZipFile(..., strict_timestamps=False)`；`write_zip` 也要接 `FileNotFoundError`（走訪到寫入之間檔案不見）。

**T-6 拿較舊的快照當來源會被輪替刪掉；所有 `OSError` 都說「有檔案開著」**
- 位置：`restore.py:458～468`、`backup.py:392～413`。
- 證據：快照有兩份時 `restore apply <較舊那份>` → 先拍新快照，輪替把來源刪掉，`_unpack` 開不到檔，回 exit 3「有檔案開著（快照….zip），關掉再說一次；什麼都沒動」，之後來源已不在。（最新那份當來源沒事，驗收 10 走的是這條。）同一個 `except OSError` 也把磁碟滿（拍快照與解壓縮都沒有空間檢查）、找不到 zip 都說成「有檔案開著」，客戶關了程式再試也沒用。
- 建議：來源是快照時，輪替要跳過來源（或先解壓再拍快照）；`apply` 前做跟 `backup` 一樣的空間檢查；`except OSError` 依 `errno` 分「檔案開著」「空間不夠」「找不到」。

**T-7 B-425 (a) 的前提不成立：Glob 單一檔名會往下找**
- 位置：`scripts/kb/guard.py` 的 `_single_filename` 與 `decide` 的 Glob 分支。
- 證據：用這個 session 的 Glob 工具實測，目錄 `globtest/sub/deep/target.txt`，`path=globtest`、`pattern=target.txt` → 回傳 `globtest\sub\deep\target.txt`。所以 `Glob(path=<含不讀夾的來源>, pattern="報價.xlsx")` 被放行後，工具會把不讀夾裡同名檔的完整路徑也列出來。
