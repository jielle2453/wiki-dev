## plugin-dev 審查

- `hooks.json` 與 hook 程式沒改（`git diff main...HEAD -- hooks` 空）。依 `plugin-dev:hook-development` 審 selftest 給 hook 的 payload 與判讀：PreToolUse 的輸出判讀（`hookSpecificOutput.permissionDecision`）、SessionStart 的 `additionalContext`、exit code 判讀（0 成功）都跟該指引一致；每個 command 不經 shell、用 `${CLAUDE_PLUGIN_ROOT}` 展開後的 `hooks/<檔>.py`、`sys.executable` 加 `WIKI_WITH_WILLY_NO_BACKGROUND`。
- payload 欄位：該指引寫 `user_prompt`、`tool_result`、通用欄位 `transcript_path`、`permission_mode`；selftest 用的是 `prompt`、`tool_response`，也沒有後兩個通用欄位。我 grep 了 `hooks/*.py`：`turn.py` 讀 `prompt`（備援 `user_prompt`），所有 hook 都不讀 `transcript_path`、`permission_mode`、`tool_response`，所以現在不影響判讀；以後有 hook 讀這些欄位，selftest 的 payload 要跟著補。

## security-review

`security-review` 技能只看目前分支的未提交變動，我在 main checkout 叫它，它看到的是空 diff，所以我自己讀 `main...HEAD` 的 `scripts/`、`tools/`、`config/` 差異當依據，逐項如下，沒有新增攻擊面的發現：

- **zip slip**：`verify` 解壓前用 `backup._unsafe_member`（跟備份還原同一套）；實測六種路徑（見驗收 3）都擋、暫存夾外沒有新檔。zip 在 Windows 上沒有符號連結的項目；解壓大小沒有上限（下載上限 100 MB，但解壓後無上限），來源是清單帶 sha256 的檔，風險低，沒列發現。
- **sha256 核對**：比的是自己算的 hexdigest 與清單的值（轉小寫），在解壓之前；清單與 sha256 同來源，這層只擋傳輸損壞與 zip 被單獨換掉。
- **子行程與逾時**：全部 argv 清單，不經 shell；`hooks.json` 的 command 只取 `hooks/` 後面符合 `[A-Za-z0-9_]+\.py` 的檔名；逾時 `taskkill /T /F` 殺整棵，實測沒有殘留 python 行程；殘留暫存夾見 #6。
- **執行新版的程式**：驗證要執行新版的程式（selftest 會 import、跑 hook），這跟換版後她本來就會執行的是同一份程式、同一個 sha256，沒有新增的信任；環境變數整份繼承。
- **有沒有碰到她真的知識庫**：selftest 的 hook、`kb upgrade --background` 的 cwd 一律是暫存小知識庫；`CLAUDE_PROJECT_DIR` 這類環境變數沒有程式使用（grep 過）；清單網址在小知識庫的 `.system/config.json` 設空，背景升級不連網；實測 cwd 放假知識庫前後完全相同。唯一的假設是 `%TEMP%` 本身不在她的知識庫裡面。
- **暫存夾清理**：`verify`、`selftest` 都用 `mkdtemp`（隨機名）加 `finally`，被外層殺掉的路徑會漏（#6）。
- **輸出**：`clean_why` 把絕對路徑換成「…」並遮值；`verify` 轉述新版回報時沒有再清一次（#9）。
