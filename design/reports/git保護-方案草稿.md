## 一、為什麼

守門只看得到 AI 用哪個工具、下什麼指令，AI 換個寫法就繞過去，保證不了「刪掉、蓋掉前留一份」（D-306 的前提）。git 是事後看結果：不管 AI 用什麼方法動了檔，動之前的樣子都在。守門可以縮到很小，AI 用自己的方法做也安全（D-319「不用一定用 willy 的方法」）。

## 二、架構：個人的在 willy、團隊的在 GitHub

| | 保護用（個人的） | 同步用（團隊的） |
|---|---|---|
| 誰有 | 每台電腦都有，單人多人都一樣 | 只有多人共用（#5，D-285） |
| 存在哪 | 這台電腦本機、willy 的區域，**不在知識庫裡、不在雲端同步夾裡** | 知識庫的 `.git`，遠端是 GitHub 或自架（D-302） |
| 誰寫 | willy，AI 動檔前與答完各照一次 | Obsidian 外掛定時 commit、推、拉（D-302） |
| 蓋到哪 | 知識庫全部＋每個登記的來源（含雲端同步夾），連 `.gitignore` 排除的、`_個人` 都照 | 只有要共用的（D-292） |
| 舊的 | 定期清（排程，B-522） | 不刪；誤推機密才改寫歷史，服務人員處理 |
| 誰看得到 | 只有這台 | 全隊 |

保護用的放在知識庫外面，是因為：(1) 單人知識庫常放在 OneDrive／Dropbox 裡，`.git` 放裡面會有幾千個小檔跟著同步、容易壞；(2) 登記在知識庫外的來源（雲端同步夾，D-292、D-301）也要保護，一個 git 只管得到一個資料夾，所以每個來源一份，都放在本機；(3) 跟外掛那條完全分開，外掛怎麼推都推不到保護紀錄。

使用者與同事都不會看到 git，全部由 willy、外掛與 AI 做。

一般團隊用 git 的做法套進來的：自己電腦隨便 commit、推上去才算共用（保護紀錄不推）；個人的寫 `.gitignore`（D-292）；開工先拉（D-293）；大檔放雲端（D-301）；誤推機密改寫歷史、換密碼。不套的：每人開分支、發 PR 給人審（客戶不懂、同事要等很久才看得到）；資料夾權限（git 只能整個 repo 給或不給，屬 #5 情境 7）。

## 三、什麼時候照

- **AI 這句第一次要動檔前**照一次（PreToolUse，會寫檔的工具）。只是查、只回答的句子不照。
- **答完**再照一次，有變才存（Stop）。
- 每次只存有變的檔，沒變的沿用上次存的；整句沒變不用存，只花「看一下」的時間（B-527 同量級，3000 份約 0.1 秒，git 的要 spike 量）。

兩次照的差別自然分出誰動的：
- 上一句答完 → 這句動檔前：**使用者自己動的**（Finder、Obsidian 手改、搬檔）→ 丙的偵測與 D-311 用這段。
- 這句動檔前 → 答完：**AI 這句做的** → 退回與日誌用這段。

這段可以取代丙的 `detected.jsonl`（甲的 `shell_writes.jsonl` 11-01 已拿掉，丙的兩次比對就分得出誰動的）。

## 四、照哪些、不照哪些

照：知識庫全部與每個來源。
不照：
- **大檔**（界線待定，見第八節）：git 歷史刪不掉單一檔的舊版，大檔每改一次多一整份。改成 willy 在它被刪、被蓋前另外留上一版一份（沿用現在的備份程式，只剩這個用途）。
- 密碼與憑證樣式的檔（`credentials.py` 那套）、Office 暫存 `~$`、`.git` 本身。
- Obsidian 一直在寫的：`.obsidian/workspace*.json`、`.obsidian/cache`、`.obsidian/plugins/wiki-with-willy/data.json`（最近開過的）——每句都變，拍了只是雜訊（11-01 Obsidian 那題）。改回時使用者正在 Obsidian 打同一頁，AI 說一聲是哪一頁。

缺口：大檔被 AI 用自己的方法刪掉，事後才發現就來不及留。所以大檔的刪、蓋，守門照 D-306 現在的規則擋（叫 AI 改用 `kb source-edit trash`）。

## 五、守門剩下擋什麼

- 動到保護紀錄：刪它、改它、AI 自己下清理指令。
- 危險的 git 指令：`git reset --hard`、`git clean`、`git checkout -- .`、`push --force`、刪 refs（共用 repo 被弄壞，同事都受影響）。
- 大檔的刪、蓋（第四節）。
- 原本就要留的 A 類擋（`放寬限制-審查.md` 第三節：密碼與憑證、plugin 本身等），不受這題影響。

其他「刪掉、蓋掉而留不了一份」的擋（D-306 的主體）都拿掉。

## 六、退回

照保護紀錄一件一件改回（D-321 的做法不變，來源從「日誌＋備份」換成「日誌＋保護紀錄」）：日誌記意思（搬了什麼、為什麼），保護紀錄有內容。可以只改回某一項。多人時同事之後改過的，照 D-296 先問。

## 八、待討論（建議順序）

1. **方向本身**：個人的在 willy（本機、知識庫外）、團隊的在 GitHub。
2. **照的時機**：動檔前＋答完（第三節）。
3. **大檔界線**：多大以上不照、只留上一版。我推薦先抓 50 MB，spike 後再調。
4. **保護紀錄留多久**：我推薦 30 天，排程清。
5. **守門剩什麼**：第五節。
6. **共用 commit 要不要寫做了什麼**：willy 寫「小王：把報價單搬到 01 案子」，取代外掛一律的「自動備份」。可做可不做。
7. **對使用者怎麼說**：「我都有留一份，30 天內說一聲就能改回」，跟 D-311 做完講三件事一起。

## 八之一、多人共用怎麼跑

每台電腦有三樣：知識庫的檔、團隊的 `.git`（外掛每 5 分鐘 commit、推、拉，D-302）、willy 的相簿（保護紀錄，不上傳）。

| 哪種檔 | 團隊 git（GitHub） | 相簿（這台） |
|---|---|---|
| 共用的（卡、原檔、口述等，D-292 甲乙） | 有，永遠留，約 5 分鐘一版、混好幾句 | 有，一句一張，留 30 天 |
| 不共用的（`_個人` 若不共用、這台的狀態，D-292 丙） | 沒有 | 有 |
| 大檔 | 沒有（放雲端夾，D-301） | 沒有，只留上一版 |
| 密碼、憑證 | 沒有 | 沒有 |

共用的檔兩邊都有，相簿還是要：外掛的版混好幾句與手改，分不出哪句做的（D-296 不用 git 歷史退的理由）。

走一遍：小王說「把報價單搬到王宅」→ 小王那台動檔前拍、答完拍，日誌記小王 AI 做的 → 外掛推上 GitHub → 小李那台外掛拉下來 → 小李下一句動檔前拍，比上一張多了「報價單搬了」：這是**同事推來的**，不是小李自己動的，不能照 D-311 當成小李的動作處理 → 要靠團隊 git 認出哪些是拉進來的（D-293 對帳）。小王後來說「改回去」→ 從小王的相簿拿回 → 外掛推出去，全隊都改回；小李之後動過報價單就照 D-296 先問。

## 八之二、可能的問題

空間與速度：(1) 第一次拍等於整個知識庫多一份，多人時共用的檔在每台存三份（檔、團隊 git、相簿），要 spike 能不能共用 git 物件；(2) 每句動檔前多等，沒量；(3) 雲端「只在線上」的佔位檔一讀就整份下載，要跳過，跳過的沒保護（現在比指紋可能也有這問題，一起查）；(4) Windows 路徑太長、防毒掃相簿變慢。
保護不到：(5) 大檔不在相簿，守門還要擋大檔的刪、蓋；(6) 只保護拍那一刻，同一句裡中間版沒留；(7) 知識庫外沒登記的地方沒相簿；(8) 相簿在本機不是備份，硬碟壞一起沒，外接備份照舊。
壞掉：(9) 相簿壞了那段退不了，健檢查、重拍一本（「保護壞了修不好」那種要服務人員）；(10) AI 動相簿或下危險 git 指令，守門擋。
多人：(11) 拉進來的同事改動要跟使用者自己動的分開；(12) 外掛在一句話中間拉，「動檔前→答完」那段混進同事的改動，會被算成 AI 做的，要扣掉拉進來的；(13) 改回會推給全隊，要講一句；(14) 新電腦、新同事的相簿從空的開始，之前的退不了（團隊 git 還有歷史，服務人員找得回來）。
其他：(15) 刪掉的敏感檔在相簿留 30 天，要能單獨清；(16) Mac 不一定有 git；(17) 改動大，甲丙大改、要 jacky 同意。

## 九、要 spike 的

1. 3000 份、1.1 GB（B-527 那份假資料）：第一次照、沒變、改幾份、搬 250 MB 各要幾秒；Windows 與 Mac。
2. git 資料放在知識庫外、知識庫在 OneDrive 夾裡：照、還原、改名、中文檔名都正常。
3. 多人：保護 git 與知識庫的 `.git` 疊在同一批檔上互不干擾；外掛自動 commit、推、拉時保護紀錄照常；兩邊共用 git 物件省空間（git alternates）做不做得到。
4. 清 30 天前的：要多久、清完還原最近的正常。
5. Mac 沒裝 git 時怎麼辦（Windows 的 Claude Code 本來就要 Git for Windows，要確認）。

## 十、階段二（相簿）上線時一起換的（單人多人都用相簿）

使用者 11-01：「單人也要用 git」——相簿每台都有，單人多人一樣（第二節）。寫階段二 spec 時一起看：

| 現在的做法 | 相簿上線後 |
|---|---|
| 回合備份（`versions/<回合>/files/`、manifest）：刪、蓋、改 willy 自己的檔前留一份 | 相簿照得到的都改由相簿留；回合備份只剩大檔與相簿不照的 |
| 丙的搬動偵測：清冊快速比對、`detected.jsonl` | 改用相簿兩張之間的差（git 認得搬動與改名）；清冊照差更新位置 |
| 丙的改回：讀回合備份把舊版寫回 | 從相簿拿那一份；日誌照舊記意思 |
| 清冊內容指紋（sha256，Office 另算內文指紋 `text_sha256`） | **留著**：卡、認領、同名比內容靠它；Office 檔另存一次位元組就變、內容沒變，git 只看位元組，分不出來。相簿照的檔可以順便拿 git 算好的雜湊省一次讀檔（只是加速，不換指紋） |
| B-528 回合備份在雲端夾裡跟著上傳 | 相簿在知識庫外，照得到的就不在雲端夾；剩大檔備份要另處理 |
