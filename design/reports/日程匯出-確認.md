## 落差（只記看到的，spec 錯或實作錯由設計 session 判）

1. **恢復後 `last_error` 不清掉。** 成功匯出後 `agenda_export.json` 仍保留上一次的 `last_error`；`--status` 人看的版本也照印「上次沒放成」。要靠比 `last_error_at` 與 `last_ok_at` 才知道已經恢復。spec 只定了欄位，沒說成功時要不要清。
2. **未曾失敗時狀態檔沒有 `last_error_at`／`last_error` 鍵**（不是 null）；`--status --json` 輸出有沒有補 null 這次沒看到（第一次看 `--status` 時已經失敗過）。spec 寫的形狀是四個鍵都在。
3. **`--status` 在有錯誤時 exit 0。** spec 沒規定，記下供參考。
4. **資料夾回來後不會自己補，要等下一次寫日程或實體。** 符合 spec（「下一次寫入補上」），但服務人員排錯時要知道：雲端硬碟重新登入後若她一直沒記新事，手機頁面停在斷線前；可手動跑 `kb agenda export`。
5. **情境 3 多一輪問答。** 演練知識庫裡王大明原本就有 10/29 一條會議，willy 照 note skill 問是哪一條，客戶答了才改。跟匯出無關，是素材造成的。
