# 對話結束後跑的指令不掛回那句對話的回合
日期：2026-10-26
狀態：定稿
版本：發行時填

## 目的

客戶的對話結束後，從終端機、排程、外部程式跑會寫入的 `kb` 指令（例如 `kb agenda done`），寫入的備份會算進**上一句對話**的回合：`kb versions list` 把它列在那句話底下，客戶退回那句話時會連這些對話外的寫入一起退掉。工作日誌那邊 D-085 補已經不掛回去了，備份這邊沒有，兩邊對不上。

使用者時刻：她問完一句「今天有什麼事」關掉對話；排程的程式在背景把一條日程記成完成；隔天她說「退回上一步」想退掉別的東西，手機那邊打的勾不會跟著被退掉。

## 決策（D-502）

- `scripts/kb/_lib/turn.py` 的 `current(vault, session_id=None)`：沒有 OVERRIDE、沒有 session_id（或 session 檔不存在）時讀 `current.json`。讀到的回合 `session_id` 非空**而且** `done` 為 true（對話已答完）→ 不回它，改呼叫 `start(vault, None, "")` 開終端機回合（代號尾 0000）回傳。
- `current.json` 的 session_id 是空的（終端機回合）→ 照舊沿用，不變。
- 對話還在回答中（session_id 非空、`done` 為 false）→ 照舊沿用（D-085：模型在對話裡叫的算在那句話裡）。
- 判斷「已答完」用跟 `mark()`、`touch()` 一樣的條件；舊回合檔沒有 `done` 鍵時 `_read_turn` 已補成 true，照這個值。

## 要做的事

1. 改 `current()` 照上面。
2. 補測試：新測試檔 `tests/test_turn_ended.py`（或併進 `tests/test_lib_turn.py`）。

## 來源程式對照

- `scripts/kb/_lib/turn.py`：`current()` L159 起；`mark()`、`touch()` 已有 `data.get("done")` 判斷可對照。
- `scripts/kb/_lib/journal.py` 程式段（D-085）：L325 起，代號用現在時間、尾 0000。

## 資料與介面格式

不變。回合檔、`current.json`、`versions/<回合>/` 格式都不動；指令參數與輸出不動。

## 可以動 / 不可以動

- 可以動：`scripts/kb/_lib/turn.py` 的 `current()`；`tests/test_lib_turn.py`、新測試檔。
- 不可以動：hooks、其他 `scripts/`、skills、其他既有測試（既有測試若因這個改動變紅，先停下回報，不改測試）。

## 驗收準則

1. 對話已答完（`current.json` 有 session_id、`done` true），無 session_id 呼叫 `current()` → 回新回合，代號尾 `0000`、session_id 空；`current.json` 換成這個新回合；原對話的 `turns/<sid>.json` 不被改。
2. 接著同一個終端機再呼叫一次 → 沿用同一個 0000 回合（不是每次開新的）。
3. 對話回答中（`done` false）→ 回那句對話的回合，不開新的。
4. 有 session_id 呼叫 → 讀 `turns/<sid>.json`，行為不變。
5. OVERRIDE（`--turn`）→ 行為不變。
6. 整條路走一次：模擬對話一句（UserPromptSubmit → 寫入 → Stop），之後在終端機跑 `kb agenda done <id>` → `kb versions list` 那筆是自己一個回合，不在那句對話底下；對那句對話 `versions revert` 不會把 `agenda done` 那筆退掉。
7. 全套測試 exit 0。

## 確認情境

服務人員視角，在演練知識庫的複本裡（不用桌面版也可以，用 CLI 加真的 hook 跑一句對話）：

1. 開 Claude 對知識庫說一句會改東西的話（例如「明天下午三點跟陳志強開會」），等它答完，關掉對話。
2. 在終端機跑 `kb agenda done <另一條的 id>`。
3. `kb versions list`：第 2 步是獨立的一筆，不在第 1 步那句話底下；工作日誌兩段分開。
4. 再開對話說「退回上一步」或退回第 1 步那句：第 2 步那條仍是完成。

## 不做

- 外部程式的 `--source` 旗標、一輪同步合成一段日誌、同步衝突的待處理（issue #3、#4 原本提的，改由外部程式自己處理）。
- 對話回答中另開回合。
- `kb turn current --json` 回「還在回答中」。
