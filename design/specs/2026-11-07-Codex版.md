## 資料與介面格式

**認 Codex**：PreToolUse／PostToolUse／UserPromptSubmit／Stop 的 payload 有 `turn_id`（Codex schema 必填；Claude Code 沒有這鍵）。

**normalize**（PreToolUse、PostToolUse）：

| Codex `tool_name` | 轉成 |
|---|---|
| `Bash` 而且指令裡有 `*** Begin Patch`（從殼叫 apply_patch） | 整條照殼指令判一份，**另外** patch 裡每個檔照 Write／Edit 各判一份（只會多擋、不會少判；review 7、三輪 1～3） |
| `apply_patch`（patch 文字取 `command`，沒有就 `patch`、`input`；陣列取含 `*** Begin Patch` 的那段） | 每個（行首可有空白）`*** Add File:`→`Write`、`*** Update File:`／`*** Delete File:`→`Edit`、`*** Move to:`→`Write`，`tool_input={"file_path": 絕對路徑}`（相對路徑接 `cwd`）。一個都拆不出回 None |
| `Bash` | Windows 上改 `PowerShell`，其他照 `Bash`；`command` 是陣列時：第一個是殼（powershell、pwsh、cmd、bash、sh、zsh）就找第一個指令旗標（-Command、-c、/c、-lc、-ic；前面的旗標可帶值），PowerShell、cmd 取後面幾段用空白接、bash 類只取下一段，否則照 Windows 規則加引號接成一行 |
| `view_image` | `Read`，`file_path` 取 `path` |
| 其他 | 原樣 |

**combine**：任一份 deny → deny（第一個 deny 的理由）；否則任一份 ask → 那份 ask（走同意流程）；只有一份照它；全部 allow → allow（不帶 updatedInput）；其他不表態。

**同意（Q2-A）**：
- 守門判到 ask（現有 `secret_action`）而且是 Codex：session 檔（`.system/turns/<sid>.json`）這一句有 `codex_consent` 等於這個指令的指紋（`sha256(指令去頭尾空白)[:16]`，指令用轉接後的那份）→ 清掉 `codex_consent` 與 `codex_consent_pending`、allow（照舊帶 `--session` 的 updatedInput）；否則記 `codex_consent_pending`＝指紋、ledger 記一筆 `consent_needed`、deny，理由是 `CONSENT_REASON` 接原本的 ask 理由。Codex 下不會輸出 ask。
- turn.py（Codex 的 UserPromptSubmit，不是客戶訊息的那幾種開頭照舊不開回合、不看同意）：上一句的回合有 `codex_consent_pending`，而且這一句 `is_agreement` → 新回合記 `codex_consent`＝那個指紋。所以同意只對**緊接的下一句**有效、只對那一個指令、用一次。
- `is_agreement(prompt)`：去掉空白與 `，。！!、,.~～…」「` 後（大小寫不分），整句只由同意字（沒問題、同意、可以、確定、允許、去做、做吧、okay、ok、yes、好、是、對、行、嗯）與語助詞（的、啊、呀、喔、哦、囉、了、吧、唷、耶、嘛、請、就）組成，而且至少一個同意字。所以「不要」「等一下」「可以嗎」「這是什麼」「是誰」「好，但先等等」都不算（review 3 後收緊）。
- AI 自己寫的字不能算：同意只從 UserPromptSubmit 的 `prompt` 來；AI 改 `.system/turns/` 會被守門擋（Z7）。

1. 實作時發現（spec 以外，main 也有）：密碼動作的指令後面接 ` #…`（`… unlock get --name X #x`），`kb.guard.decide` 回 allow 不回 ask（Bash、PowerShell 都是）；殼把 `#` 後面當註解，kb 照樣跑 `unlock get`，等於繞過 D-212。不在這題範圍、沒改，回報主管。

2. review（claude -p、Sonnet、0.40 美元）7 條：1 patch 標頭縮排、2 陣列指令任意位置找 -c、3 同意太鬆、5 多檔一份出錯後面不登記、6 `_codex` 載不進來就沒守門、7 從殼叫 apply_patch，都修了（6：載不進來照守門出錯處理，知識庫裡 deny）。4（AI 一被擋就記待同意，客戶回「好」可能是回 AI 問的別的事）**接受、不修**：hook 看不到 AI 問了什麼（`last_assistant_message` 是 AI 寫的，也不能當證據），只能靠擋下的理由叫 AI 先問清楚；代價是客戶隨口一句「好」可能被當成同意那個密碼動作，範圍限緊接的下一句、那一個指令、一次。列進實機要測。

3. review 第二輪（只審修正的 diff，Sonnet、0.21 美元）4 條，都修了：(1) 殼指令只要含 `*** Begin Patch` 就整條當 patch，前面的指令沒被判——改成整條指令就是 `[cd <夾> &&] apply_patch` 接「結束字加引號的 heredoc」或「整段單引號」才當 patch（`SHELL_PATCH_RE`），其他照一般殼指令判；(2) 殼旗標帶值（`-ExecutionPolicy Bypass`）時找不到 `-Command`——改成找第一個指令旗標，bash `-c` 只取下一段；(3) 「我同意」「同意，請繼續」「yes please」不算——同意字加「我同意」「繼續」、語助詞加 please；(4) output_log、turn 頂層 import `_codex` 沒接——載不進來時 Claude 的 payload 照舊、Codex 的當不認得（guard 那邊照守門出錯 deny）。
4. review 第三輪（只審二輪修正，Sonnet、0.15 美元）6 條：二輪 1 的 `SHELL_PATCH_RE`（整條是 apply_patch 才當 patch）還是繞得過（heredoc 結束字之後接指令、`cd "$(…)"`、cmd 不認單引號），而且 `cd` 的路徑推不準。**改成不認這條捷徑**：殼指令一律照殼指令判，含 patch 字樣時另外把 patch 的檔逐一判，只會多擋（1、2、3、5）。`_command_text` 改回遇到第一個非旗標就停（`bash evil.sh -c …` 的 `-c` 是腳本參數），只有 PowerShell 帶值的選項（`-ExecutionPolicy Bypass` 等）跳過值（4）。6（不認得的殼旗標整串交給殼指令判）不修：守門本來就會判包著殼的指令。另修 combine：多份裡有 ask 時回 ask，不合併成不表態。
5. review 第四輪（只審三輪修正，Sonnet、0.20 美元）3 條：(1) 殼指令裡 `cd <夾> && apply_patch`，相對路徑只照 cwd 判會判錯檔——改成 cwd 與指令裡每個 `cd`／`Set-Location`／`pushd` 的夾各判一次（只會多擋）；守門只在 cwd 是知識庫裡時動作，這點同 Claude 版、不改；(2) PowerShell 帶值選項的縮寫與別名（`-ep`、`-Exec`、`-w`）、bash 的 `-o`／`-O`／`--rcfile` 沒跳值——補上；(3)「同意後放行還帶 updatedInput」不改：官方文件寫 Bash 的 allow 可以帶 `updatedInput`，`--session` 就是靠它插進去，有沒有生效列在實機要測第 6 條。
6. spec 以外的發現（裁定 1，密碼指令後接 ` #x` 繞過 D-212）：主管 2026-11-07 說另開題、Claude 版一起修，codex 分支不自己修。
7. 實機測（2026-11-08，`文件\實機測紀錄.md`）修了兩件：UserPromptSubmit timeout 5→30（msys python 冷啟動 7.5 秒，逾時 Codex 靜默放過、回合與同意都沒記）；ingest 開頭講明不派工（AI 照別處跑 dispatch 後空等）。
8. **改掉 Q1-A，jacky 2026-11-09 裁定「甲乙都要」**。Codex 自審（`文件\Codex自審.md`）發現 Q1-A 漏了：`cards dispatch` 依序派做卡 → 日程 → 綜合卡三種批次，主對話只寫卡就沒人做日程與綜合卡；而且 Claude 版靠 SubagentStop 把批次記成做完，kb 沒有別的收尾路。Codex 其實有子代理（`spawn_agent`），但不能指定類型，SubagentStart／Stop 認不認得出製卡助手沒驗證。做法（9c：一個收尾指令甲乙共用，不靠沒驗證的 hook，hooks.json 不動、不用重新信任）：
   - kb 加 `cards batch <批次> --done [--failed "<編號>：<原因>" …]`（`batches.batch_done`；多行回報塞指令列在 PowerShell 容易壞，只收沒做成的）：那批還在認領中（跟 `cards batch` 看的同一個 `live` 判斷）就記成 done（`--failed` 記進 failed，只收這批的編號、別的編號印出來不記，同 `agent_stop`）、做完的卡收認領標籤；停了、做完了、放掉了、**過期了**都印「這批已經停了或做完了」、不改（過期的放回去重派；11-09 review 改：原本過期也收，沒做的會被記成沒做成、不再派）。`--failed` 沒帶 `--done` 報錯。不驗產物：記成做完但還在待做清單的，下次 dispatch 記成沒做成（預設原因、不再派，同 Claude 版）。
   - dispatch 給的 `prompt` 自己說清楚：先讀外掛的 `agents/card-maker.md`（絕對路徑，執行時從 `plugin_root()` 算、不存），照它做，做完跑 `--done`（沒做成的帶 `--failed`）、最後一則照回報格式（字典外、沒照做的偏好照舊由主對話從回報讀）。
   - 甲：有子代理工具就每批派一個（prompt 原樣），等通知再 dispatch。乙：沒有就主對話照每批 prompt 依序自己做，做完再 dispatch。兩條都做到 `done`。停：`cards stop` 照舊放掉批次，子代理用 Codex 自己的中斷工具停。
   - 已知限制：沒有 SubagentStart 記子代理，批次 30 分鐘（`card_batch_expire_minutes`）後就算過期，不會因為子代理還在跑而延長；過期的項目下次 dispatch 會再派（重做，不會漏）。兩個對話同時整理時，別的對話的批次沒有 `last_seen` 更新，10 分鐘（`card_batch_idle_minutes`）就當沒人在做，可能兩邊重做同一份（11-09 review）。
   - 動到：`scripts/kb/_lib/batches.py`（`PROMPT`、`batch_done`）、`scripts/kb/cards.py`（`--done`、`--report`）、`skills/ingest/SKILL.md`、`skills/build/SKILL.md`、`tests/test_scripts_cards_dispatch.py`、`tests/test_skill_ingest.py`、`tests/test_codex_adapter.py`。
