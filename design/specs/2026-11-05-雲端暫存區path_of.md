## 要做的事
根因：多人把暫存區登記成團隊雲端的夾（別名「暫存區」，D-324）後，收進來的檔清冊 uri 是 `file://暫存區/…`；`inventory.path_of` 遇到這個別名直接回知識庫裡的 `暫存區/`，在查登記的來源之前就回了，所以 `lookup --id` 的 open 是 null、`convert` 找不到原檔。
1. `scripts/kb/_lib/inventory.py` `path_of`：別名是暫存區時先找登記的來源，有就用它的位置，沒有照舊。
2. `scripts/kb/versions.py` `_move_root`（review 找到同一個寫死）：登記的來源先比，暫存區的預設放最後。
3. `tests/test_people_hold.py`：登記在雲端時 `path_of`、`_move_root` 解到這台的雲端夾、`kb convert <編號>` 讀得到；沒登記時照舊是知識庫裡的暫存區。
4. `ops/map-lib-knowledge.md` inventory 列、`ops/map-cli.md` versions 列。

## 可以動 / 不可以動
- 可以動：上列檔、本 spec。
- 不可以動：`uri_of`（反查本來就對）、`hold_root`、intake／output（已用 `hold_root`）、守門。
- 相關測試：`grep -l path_of`、`_move_root` 找到的 test_people_hold、test_hooks_detected、test_lib_inventory_scan、test_versions_moves、test_items_undo；加 test_repo_hygiene。
