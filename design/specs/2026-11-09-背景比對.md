# 檔案比對搬出對話：電腦排程定時比、對話只讀清單

日期：2026-11-09
狀態：定稿（jacky 2026-11-09 定，五題照建議，willy主管 轉達）
版本：（發行後填；跟 #62、#63 一起發，willy主管 發行）
來自：issue #60、#61；併入 無
區域：核心規則與開場、hooks
決策：D-536
分支：`spec/背景比對`，**從 `spec/pyc快取` 開**（#62 已改每支 hook 與 kb.py 開頭那幾行，這題也要動 kb.py 開頭，從它開才不會衝突）；worktree `willy-測試\開發\#60-61-背景比對\worktree`

## 目的

檔多的知識庫（1 萬份以上）每句開頭比對比不完、新放的檔一直報不出來（#60）；答完的 stop.py 超過 hook 上限 10 秒（#61）。客戶的時刻：她在檔案總管丟了幾份檔進來，過一陣子跟 AI 說話，AI 知道有新檔；她說「我剛放了一份報價」，AI 當場找得到。每句話不能讓她等。

## 決策

D-536（方向 jacky 2026-11-09 定）：
1. 每句開頭（turn.py）、答完（stop.py）**都不再比對原檔**。
2. 電腦的排程每 N 分鐘跑 `kb changes --background`，結果寫成清單 `.system/local/changes.json`；每句開頭只讀這份。
3. AI 也可以當場跑 `kb changes`（她說剛放了檔、找不到某份時），跑完順便更新清單。拖進對話、說存起來照舊。
4. 每天第一句那批查一次排程在不在、對不對，不在或不對就重設；設不起來記待處理，開場照常。第一次設或重設時 AI 在回答末尾說一句。
5. 單人、檔少的庫也一樣。

### 實測（2026-11-09，jacky 這台，3 萬份、每份都有卡的壓力測試庫，各 3 次）

| | 現在 | 拿掉比對 |
|---|---|---|
| stop.py | 6.9～7.2 s | 1.2～2.7 s |
| turn.py（不是今天第一句） | 3.0～3.7 s | 3.0～4.4 s：剩下的大多是 `cards_mtime` 走完 3 萬張卡 3.0 s、`turn.start` 0.7 s |
| 每天第一句那批的「製作中」`cards.wip` | 12.5 s（不設上限量） | 要搬進清單 |
| `schtasks /query` 一個工作 | 137～161 ms | |
| `schtasks /create`（目前使用者，不用系統管理員） | 163 ms | |

Mac `launchctl` 沒量：這台沒有 Mac，willy 程式目前也只支援 Windows（只有 `unlock.py` 分平台），Mac 列在「不做」。

## 要做的事

1. **`kb changes --background`**（`scripts/kb/changes.py`）：
   - 跟 `kb changes`（不帶 `--quick`）同一個 `inventory.scan`，不設時間上限、只讀不套用。另外算兩樣：`cards.wip` 的份數與前 3 個檔名（每天第一句的「製作中」用）、卡的最新修改時間（現在 `_checks.cards_mtime` 的算法，搬到 `kb/_lib` 共用）。
   - 寫 `.system/local/changes.json`（格式見下一節），先寫暫存檔再換名。不印東西，任何例外寫 `.system/hook-errors.log`（source `scan`），exit 0。
   - 同一個知識庫已經有一個在跑（鎖檔 `.system/local/changes.lock`，30 分鐘內）就直接結束。
   - `--background` 時 stdout、stderr 可能是 None（pythonw 跑的）：`scripts/kb.py` 開頭的 `reconfigure` 要包 try（照 hooks 的寫法）。
2. **清單跟著更新**：`kb changes`（不帶 `--background`，AI 當場跑的；含 `--quick`、`--moved`）比完也寫一次清單；`kb inventory scan`（全部來源，不帶 `--source`）套用完寫一次清單（套用之後的變動是空的，`at` 是現在）。帶 `--source` 的只掃一部分，不寫。
3. **每句開頭只讀清單**（`hooks/_checks.py`）：
   - `file_compare` 改成讀清單，回一樣的 `(sources, report)`；沒有清單或讀不懂回 None（不記 log，排程還沒跑過是正常的）。下游的 `record_detected`、`line_missing_sources`、`line_moved_files`、`change_lines`、`line_drift` 不改。
   - `CHANGES_INCOMPLETE` 那句拿掉（清單是比完才寫的）。
   - 卡的手改：`turn_lines` 第 2 段用清單裡的 `cards_mtime` 跟 `stamps["cards"]` 比，不再呼叫 `cards_mtime(vault)` 走整個知識庫。
   - 每天第一句的 `line_wip` 用清單的 `wip`，不再呼叫 `cards.wip`。
4. **答完不再比**：`hooks/stop.py` 拿掉 `_after_answer`；`_checks.after_answer` 刪掉。
5. **排程**（新檔 `scripts/kb/_lib/schedule.py`，Windows）：
   - 工作名稱 `wiki-with-willy\變動比對-<vault.json 的 id 前 8 碼>`（一台電腦好幾個知識庫各一個）。
   - 跑什麼：`<sys.executable 同夾的 pythonw.exe> "<plugin 根>\scripts\kb.py" changes --background --vault "<知識庫>"`，工作目錄是知識庫。用 `schtasks /create /xml <暫存檔> /tn … /f` 建（`/tr` 有 261 字的上限，中文路徑容易超過）；設定只用基本的：登入後每 N 分鐘一次、只在使用者登入時跑、同一個工作還在跑就不開新的（排程器預設）。不勾錯過補跑、失敗重試。
   - `ensure(vault)`：`schtasks /query /tn … /xml` 讀現有的；沒有、或指令裡的 plugin 根、pythonw、間隔跟現在不同 → 重建，回 `"created"`／`"updated"`；一樣回 `"ok"`；`background_scan_minutes` 是 0 → 有就刪、回 `"off"`；不是 Windows 回 `"unsupported"`；失敗回 `"failed"` 並記待處理（`pending`，一句：背景比對的排程設不起來，原因），不丟例外。
   - `_checks.daily_lines` 加 `line_schedule`：呼叫 `ensure`；`created`、`updated` 回一行給 AI：「設好背景比對（每 N 分鐘看一次資料夾有沒有新檔或改過的檔）：回答末尾跟她說一句，不講怎麼設的、不教她操作。」其他情況回 None。測試環境變數 `WIKI_WITH_WILLY_NO_BACKGROUND` 有值時不碰排程。
   - 第一次跑：建置（`kb init` 那天）的第一句就會經過 `daily_lines`，不另外在建置設。
6. **設定**（`config/defaults.json`）：加 `background_scan_minutes`（預設 10，`_why` 一句）；拿掉 `stop_scan_seconds`、`turn_scan_hash_budget_bytes`（客戶 config 裡留著的舊鍵照現在 `config.get` 的規則處理，實作時確認不會報錯）。`turn_scan_seconds` 留著（其他檢查還用）。
7. **說明**：`skills/answer/SKILL.md`、`skills/ingest/SKILL.md` 各加一句：她說剛放了檔、問的那份清冊裡沒有 → 先跑 `kb changes` 再答。`skills/*/references/commands.md` 的 `kb changes` 一節加 `--background`（排程用，AI 不用跑）。
8. **ops 地圖**：`ops/map-hooks.md`、`ops/map-cli.md`、`ops/map-lib-*.md` 改到的列一起改，新檔加一列。

## 資料與介面格式

`.system/local/changes.json`（這台電腦自己的，`.system/local/` 已在知識庫 `.gitignore`，不備份、不進回合帳）：

```json
{"schema_version": 1, "at": "2026-11-09T21:30:00", "seconds": 28.4, "via": "background",
 "report": { …inventory.public(report) 同形… },
 "wip": {"n": 12, "names": ["報價v2.xlsx", "合約.docx", "進度.xlsx"]},
 "cards_mtime": 1762694400.0}
```

- `via`：`background`｜`changes`｜`inventory scan`。
- `report` 要能還原成 `file_compare` 下游要的形狀（`added`、`modified`、`missing`、`still_missing`、`moved`、`missing_sources`、`incomplete`）；實作時照 `inventory.scan` 的回傳決定存哪些欄，存不下的（例如 sources 物件）讀的時候重新 `sources.load`。
- 讀不懂、`schema_version` 不是 1 → 當沒有清單。

`kb changes --background --vault <夾>`：不印、exit 0。`kb changes --json` 輸出不變。

## 確認情境

在測試 vault（`<測試環境>\總資料夾`），plugin 用 worktree 的快照市集裝在知識庫（local），權限模式預設。

1. **人眼**：今天第一句隨便問一句（「今天有什麼事」）→ 回答末尾有一句說設好了背景會定時看資料夾，沒有教她怎麼設；`schtasks /query /tn … /v` 看得到工作，指令是 pythonw、間隔 10 分鐘。（驗收 8 的真機部分）
2. **自動**：在來源夾放一份新的 docx，跑 `schtasks /run` 等它跑完 → 開新對話問「最近有什麼新的檔嗎」→ 回答提到那一份（製作中、沒整理）。
3. **自動**：再放一份新檔，**不跑排程** → 說「我剛放了一份 X 報價在資料夾裡，幫我看一下」→ AI 跑 `kb changes` 找到那份、讀原檔回答。
4. **人眼**：排程每 10 分鐘跑時桌面不會跳出視窗（等 10 分鐘以上看）。
5. **自動**：`schtasks /delete` 刪掉工作、把 env 的 `daily_done` 改成昨天 → 開新對話說一句 → 工作又在，回答末尾有那一句。
6. **自動**：`kb config set background_scan_minutes 0`、`daily_done` 改成昨天 → 開新對話說一句 → 工作不見；改回 10、再改 `daily_done` → 工作又在。（驗收 11 的真機部分，裁定 8）

## 裁定（測試、確認之後才有）

### 實作疑義

1. （2026-11-10，willy實作 問）`kb changes`（不帶 `--background`）、`kb inventory scan` 寫清單時，`wip` 與 `cards_mtime` **不重算**：沿用舊清單的值；沒有舊清單就寫 null，不另外算（`cards.wip` 3 萬份要 12.5 s，AI 當場跑時她在等）。讀的那邊 null 當不知道：`line_wip` 不印、卡的手改這句不比。下一次背景（≤10 分鐘）補上。代價：`kb inventory scan` 剛記進清冊的檔，「製作中 N 份」最多晚 10 分鐘算進去。
2. （同上，實作自定、設計同意）`kb changes --quick` 比到一半（incomplete）不寫清單，維持「清單是比完才寫的」。
3. （同上，實作自定、設計同意）清單的 `report` 多存 `ids`（變動那幾份的 uri→清冊編號），給 `record_detected` 的 `detected_rows` 用，不存整份 entries。

4. （2026-11-10，實作回報）`background_scan_minutes` 加進 `config.USER_KEYS`，`kb config set` 改得到、她說一句就能關（D-536 定案 5）；`scripts/kb/_lib/config.py` 只准動這一處。
5. （同上，追認）排程 XML：用電池也跑（`DisallowStartIfOnBatteries`、`StopIfGoingOnBatteries` false）、TimeTrigger（建好起每 N 分鐘）加 LogonTrigger（登入後每 N 分鐘）、`ExecutionTimeLimit` 2 小時；工作名稱取 vault_id 去掉 `kb-` 的 8 碼；找不到 `pythonw.exe` 算 failed，不退回 python.exe。
