- **這份 spec 新定（要使用者看過說可以）**：
  1. **git 只由 kb 程式跑**：新 `_lib/git.py` 一支包起來（逾時、不跳帳密視窗、`index.lock` 重試）；AI 不經 Bash 跑 git（守門現在就把 `git checkout|reset|…` 當寫入擋，不放寬）。
  2. **pull 之後的「修改」只認指紋真的變了**：git pull 會把動到的檔的修改時間都更新，快速掃描來不及算指紋的會被當「修改」（現在 quick 模式超過預算就這樣算）。對帳時先問 git 這次 pull 動了哪些檔（`git diff --name-only <上次版本> HEAD`），只有這些去算指紋，其他的只更新本機修改時間；**認領與整理只看指紋確定變了的**，「來不及比」的只報數字、不派工。
  3. **衝突時留哪版**：卡留**對方**的版本（`git checkout --theirs`，剛 pull 進來的那版），自己這邊的放進 D-270 的「她改過」比對（`card_base` 的 `pending`），之後照手改流程變成知識；這樣自己這台的改動不會不見，對方那台也不用再處理一次。原檔與產出：原位留**自己的**、對方的另存「<名稱>（<對方名字>的版本）.<副檔名>」。
  4. **Obsidian git 外掛用 rebase 而不是 merge 時**：willy 不收拾 rebase 到一半的狀態（風險大），開場與每句話開頭說「同步卡住了（rebase 到一半），請聯絡服務人員」並寫 `hook-errors.log`；建置的建議設定裡把外掛設成 merge（spike B-524 第 2 項確認外掛有這個設定）。
  5. **標籤的名字**：`willy/claim/<清冊編號>-<指紋前 12 碼>-<YYYYMMDD>`（整理）、`willy/lint/<年>-W<週>`（健檢）、`willy/upgrade/<版本>/<路徑雜湊前 12 碼>`（共用檔改寫）；用 annotated tag，訊息是這台的人名（第 2 份），開場要講「X 那台在整理」從這裡讀。

## 驗收準則

1. [ ] `git.py`：不是 repo、沒有 git 時各函式回不適用；`push_tag` 同名第二次回 `taken`；遠端不存在回 `offline`；`index.lock` 存在時重試後成功（測試裡建一個再刪）。
2. [ ] `kb refresh`：兩份 clone，A 加日程、改一份原檔 push；B pull 後跑 refresh → 日程頁有新的那筆、`changed.modified` 是 1、沒改的檔即使修改時間變了也不算（新定 2）；B 的 `系統/客戶設定檔.md` 被她手改過時 refresh 不蓋掉。
3. [ ] 每句話開頭：HEAD 沒變不叫 refresh（計次）；變了叫一次；同時叫兩次只跑一次。
4. [ ] 認領：A、B 同時 `cards dispatch` 同一份變了的檔 → 只有一邊派到、另一邊 `claimed_elsewhere` 有 A 的名字；做完標籤被刪；遠端連不上 → `offline: true`、沒派；有 1 天前的同名前綴標籤 → 可以重新認領（推今天的）。加密檔這台沒密碼 → 不認領。單人或不是 git → 照現在派。
5. [ ] 衝突（真的 git）：A、B 改同一張綜合卡的同一段、先後 push → B pull 衝突 → B refresh：卡是 A 的版本、`kb cards edits` 列出 B 那段、卡標要重做、合併 commit 完成、`git status` 乾淨、可以 push；同一份 `.docx` 兩邊改 → 原位是 B 的、多一份「（A的版本）」、兩份都在清冊。
6. [ ] rebase 到一半：不動任何檔、回 `rebase: true`、開場與每句話開頭有那句。
7. [ ] 退回時別人改過：A 寫綜合卡 → B 改同一張並 push → A pull → A 退回：卡不換回、標要重做、句子說後來被別人改過；產出同樣情況 → 另存「（退回前的版本）」、原位不動。同一台另一個對話改過照 D-508 擋。
8. [ ] 大檔：原檔區放一個 100 MB 的檔 → refresh 回 `big`、`.git/info/exclude` 有它、`git status` 看不到；有雲端來源時 `kb source-edit move` 搬過去後 exclude 那行拿掉、清冊與卡跟著走；已經追蹤的大檔不動。
9. [ ] 健檢：兩台同一週跑 → 只有一台跑 shared、另一台只跑 local（看 `lint.json` 與待處理沒有重複）；偏好月檢兩台都跑；7 天前的 claim 標籤被清；`sizes` 報 repo 大小。
10. [ ] 沒照格式的字：日程頁最底下打「下週三跟廠商確認規格」→ 下一句話的 additionalContext 有這句與 id、只出現一次（再下一句沒有）；`kb renders drop` 後那段沒了；首頁不再有「要加成一筆日程嗎」。
