D-324、D-326 講的是多人時暫存區放雲端、`_個人` 留本機；但出貨的 `.gitignore` 是一份（第 7 點），單人沒用 git 時寫了也沒作用，有作用的只有「一人兩台用 git 同步」（B-418）。

### 問 2 沒有共用雲端硬碟的團隊，暫存區放哪——**定了：(b) 進 git 同步**（使用者 11-02 先選 (a)，問「放知識庫但是同步會怎樣」後改 (b)）：這種團隊照 D-323 原檔本來就在 git，暫存區也進 git 才一致；只放本機的話暫存區的檔做了卡、卡進 git，同事點卡打不開原檔，那台壞了檔就沒了（跟當初收件匣不能只放本機同一個理由）。做法：`.gitignore` 照問 1 一律寫 `暫存區/`，**只有沒有共用雲端硬碟的團隊**建置時拿掉那一行（`kb build` 照訪談的答案做，設計自定），兩人同時改同一份草稿照 D-295 兩版都留問，大檔照第 3 份第 7 點的安全網，外掛照 D-329 停止改動才 commit；建置講明「私人的放 `_個人`」。

- (a) 留知識庫、不同步（原推薦）：照問 1 的 `.gitignore` 不進 git，暫存區只在放的那台；建置時講明「暫存區的東西只在這台，要給同事的請歸到案子的夾」。缺點：同事看不到彼此暫存區的檔（卡進 git 但點不開）。

## 目的

人說的資料（口述、日程、裁示、推算、實體、設定檔、待處理、先放著、卡的手改基準、清冊、來源登記）現在是一種一份整份 JSON，每改一筆整份重寫。放進 git 給幾台電腦同步時，兩台各改一筆就衝突，Obsidian git 外掛遇衝突停同步（D-288）。這份把它們換成**每台只寫自己的流水檔**：一行記一筆改了哪幾欄，讀的時候把所有台的檔合起來。單人知識庫也換（程式一套、一人兩台 B-418 直接能用），已建好的經 `kb upgrade` 遷移一次。退回改成「改回」（D-296 補，對齊丙的 `kb versions items`／`undo`，D-321）。出貨 `.gitignore`（D-292）與 `.gitattributes`（不轉換行）。git 只放 willy 產的文字，原檔與暫存區留團隊雲端硬碟（D-323、D-324），這份不管原檔。

這份做完，單人客戶用起來跟原本一樣；兩台電腦開同一個 git repo，各記各的、push／pull 之後兩邊都看得到、沒有衝突。「是誰」與「誰的」（第 2 份）、git 同步與收拾（第 3 份）不在這份。

使用者時刻：家裡那台記「11/25 有個會」、公司那台記「提醒我寄發票」，各自 push、pull 之後兩台的日程都有兩筆，git 沒有停下來問人。

**三份 spec 的分工**（各自一次實作做得完，照順序做；使用者 11-01 定）：1 共用流水檔（這份）→ 2「是誰」與「誰的」（身分、幾個人用、日程偏好可以讀的誰的、成員名單、分人畫、來源每台位置、新同事第一次開、舊版停寫）→ 3 git 同步與收拾（對帳、標籤認領、衝突、退回時別人改過、大檔、沒照格式的字、健檢、建置）。實作與測試照份跑；**確認三份做完後一起做一次、發行一次**（這份改所有客戶的資料格式，是大升級）。

## 決策

- D-285：多人共用走方向 B，一個知識庫、git 同步；人說的進 git、機器算的不進。
- D-288：進 git 的狀態檔每台只寫自己的 `<種類>/<這台代號>.jsonl`；一行只記改了的欄位、帶是誰、從第幾版改；先後看版號不看時鐘；兩人從同一版改同一欄才算撞到、AI 兩邊講；包成一支共用程式，各模組照舊整份讀進整份交回；單人也改、經 `kb upgrade` 遷移。
- D-292：進 git 分四類（甲流水檔、乙原樣、丙本機、丁未定）；清冊的編號、位置、指紋共用，修改時間留本機；來源的別名與預設位置共用、每台實際位置本機；`.gitignore` 寫丙類加憑證檔名樣式。（乙類的「原檔區」「AI 產出」照 D-323、D-324 拿掉。）

- D-298 第 (1) 點：每行帶格式版本，新版讀得懂所有舊版的行，`kb upgrade` 只轉這台自己的檔。
- D-291：工作日誌留本機（這份不動日誌）。

- **這份 spec 新定（要使用者看過說可以）**：
  1. **檔放哪**：`.system/streams/<種類>/<這台代號>.jsonl`；這台代號 `m-` 加 8 碼 hex，第一次要寫時產生、存 `env.json` 這台那一筆的 `machine_id`。機器的、不進 git 的本機狀態集中放 `.system/local/`（`.gitignore` 一行擋整個夾）。
  2. **設定檔怎麼拆成「筆」**：設定檔是一整份，不是一筆一筆。偏好（第六節）一條一筆（第 2 份要掛「誰的」）；其他每一節整節算一欄（一筆 `profile`，欄是 `types`、`card_types`…）。兩人同時改同一節就是撞到同一欄、照 D-288 問。
  3. **清冊拆兩半**：共用的是人或程式**明確做的事**（編號、來源、位置、指紋、排除、刪、取代、要重做、跳過種類、拒讀、日程指紋、衍生自、收件資料 `intake.from`／`intake.name`（D-325 定期抓的記位置靠它）、連結、卡式 `card_mode`、記不記過程 `track`（D-331）、封存 `archived`（D-332））；**掃描看到的**（大小、修改時間、讀得到嗎、占位、不見、不見起日、錯誤）存本機 `.system/local/inventory.json`。所以 A 那台找不到某個雲端夾，只是 A 這台不見，不會讓全隊的清冊都變「不見」。待處理的「原檔不見」「讀不到」同理只開在本機（`.system/local/pending.json`），其他種類的待處理共用。
  4. **封存不再搬檔**：口述、推算的封存（`statements-archive.json`、`findings-archive.json`）改成同一筆多一欄 `archived`（日期），讀的時候照舊分兩邊；兩個封存檔遷移後不再寫。
  5. **退回的「之後被動過」改成看「同一筆」**：流水檔一台一個檔，同一台兩個對話都會寫它，照「同一個檔」比會互相擋退回。丙（D-321）已把 D-508 改成逐項檢查；流水檔的一項是一筆，比同一筆同一欄；卡、產出、原檔照丙比檔。
  6. **purge（「不想讓 AI 看到」的清理）在多台時**：每台只能改自己的檔，所以 purge 在自己的檔寫一行「這幾筆遮掉」的標記；每台下次讀到標記時把**自己寫過**的那幾筆的字改寫成遮掉的（自己的檔可以重寫）。**git 的歷史裡還留著原文**，要清歷史得改寫 git 歷史（force push），這版不做；purge 的成功句多一句「已經同步出去的舊版本還留在 git 的歷史裡」（只在知識庫是 git repo 時說）。
  7. **遷移後舊的 JSON 不刪**：搬到 `.system/legacy/<版本>/`（本機、不進 git），留一個版本，下一次大升級清掉。

## 要做的事

1. **共用程式 `scripts/kb/_lib/streams.py`**（新，只用標準函式庫）：
   - 行的格式見「資料與介面格式」。`KINDS`：`statements`、`agenda`、`rulings`、`findings`、`entities`、`profile`、`preferences`、`pending`、`set_aside`、`card_base`、`inventory`、`sources`（共用）；`inventory_local`、`pending_local` 不走流水檔（本機普通 JSON，見第 4、6 點）。
   - `machine_id(vault)`：讀 `env.json` 這台的 `machine_id`，沒有就產生（`m-`＋`secrets.token_hex(4)`）寫回，`env` 加 `machine_id`／`set_machine_id`。
   - `load(vault, kind) -> State`：讀 `.system/streams/<kind>/*.jsonl` 全部的檔，逐行 `json.loads`；**最後一行不完整**（git pull 寫到一半、斷電）略過並記 `hook-errors.log`，不當壞檔；行的 `v` 比程式新 → 丟 `NewerFormat`（第 2 份接成「舊版停寫」，這份只要丟得出來、讀的指令照常回錯誤句）。合併規則：同一筆照 `seq` 排，同 `seq` 照 `by` 排（全隊每台算出同一個順序）；每一欄取「最後一個設這一欄的行」；`op: "create"` 是一筆的開始，沒有 create 的行（孤兒）照收、欄位照算（另一台先寫了改、create 還沒 pull 到時）。回 `State`：`records {id: {欄: 值}}`、`meta {id: {"seq", "by", "who", "at"}}`、`conflicts [{"id", "field", "lines": [行, 行]}]`。
   - **撞到**：兩行 A、B 設同一筆同一欄、值不同，而且彼此都沒看過對方（`A.seq > B.base` 而且 `B.seq > A.base`）→ 進 `conflicts`；值一樣不算（D-304 用得到）。暫時照上面的順序取一個值，`conflicts` 交給呼叫的指令（`kb asks` 第 3 份接，這份先在 `kb <種類> show --json` 帶出來）。
   - `write(vault, kind, before, after, turn_id, by="ai"|"program")`：`before`／`after` 是模組照舊整份讀進、整份交回的 `{id: {欄: 值}}`；比出新增、刪掉、改了哪幾欄，每筆一行寫進這台的檔：新增 `op: "create"`＋全部欄位、改了 `op: "set"`＋改的欄、刪掉 `op: "set"`＋那個種類的收回欄（`RETRACT`：statements／findings `status=withdrawn`、agenda `status=cancelled`、rulings `status=revoked`、entities `status=removed`、pending `status=done`、set_aside 與 card_base 與 sources `deleted=true`、inventory `status=deleted`、profile 不會刪）。`seq` = 這筆目前最大的 `seq`＋1，`base` = 寫的人讀到的 `seq`（呼叫端讀進來時記住的，`State.meta`）。整段在這台的檔的 `FileLock` 裡（只鎖自己的檔；別台的檔只有 git 會改，不鎖）。寫入走 append（`open(..., "a")`、一行一次 `write`、`flush`＋`os.fsync`），不整份重寫。
   - 回合：每寫一行在這個回合的 `versions/<turn>/streams.jsonl` 記 `{kind, id, seq}`（給退回用，第 5 點）；不再整份備份狀態檔。
   - 快取：合併結果存 `.system/local/cache/<kind>.json`，帶每個流水檔的大小與修改時間，都沒變直接用；實作量測 10 台 × 每台 5,000 行的 `entities` 合併時間記進測試報告，超過 0.5 秒回報（hook 有 3～10 秒時限）。
   - `compact(vault, kind)`：只重寫**這台自己的**檔，把被同一台後面的行完全蓋過的舊行併掉（別台的行不動）；這份只做函式與測試，誰叫它是之後的事。

## 資料與介面格式

一行（`.system/streams/agenda/m-1a2b3c4d.jsonl`，一行一個 JSON，UTF-8、LF）：
```json
{"v": 1, "op": "create", "id": "a-9f8e7d6c", "seq": 1, "base": 0, "by": "m-1a2b3c4d", "who": null, "at": "2026-11-01T10:00:00", "turn": "t-…", "set": {"kind": "meeting", "date": "2026-11-25", "text": "跟廠商開會", "status": "open"}}
{"v": 1, "op": "set", "id": "a-9f8e7d6c", "seq": 2, "base": 1, "by": "m-5e6f7a8b", "who": null, "at": "2026-11-02T09:00:00", "turn": "t-…", "set": {"date": "2026-11-26"}}
{"v": 1, "op": "set", "id": "a-9f8e7d6c", "seq": 3, "base": 2, "by": "m-1a2b3c4d", "who": null, "at": "2026-11-02T11:00:00", "turn": "t-…", "set": {"status": "cancelled"}, "reverts": [{"kind": "agenda", "id": "a-9f8e7d6c", "seq": 1}]}
{"v": 1, "op": "mask", "ids": ["s-…"], "fields": ["text"], "seq": 0, "by": "m-…", "at": "…", "turn": "…"}
```
`v` 是格式版本（D-298）；每行另帶 `app`（寫這行的 willy 版本，例 `"0.33.0"`，上面範例省略；第 2 份「舊版停寫」講版本用）；`who` 第 2 份填名字，這份一律 `null`；`at` 只給人看、不拿來排先後。

設定檔：一筆 `{"id": "profile", "set": {"types": [...], "card_types": [...], "exclusions": [...], "synthesis_sections": [...], "about": [...], "templates": [...], "tags": [...], "applied": ..., "md_sha256": ...}}`；偏好 `preferences` 種類 `{"id": "pf-…", "set": {"text", "use", "source", "date"}}`。

`env.json` 這台那一筆多 `machine_id`、`agenda_export_dir`、`source_paths`（第 2 份才寫）。

`.system/local/inventory.json`：`{"schema_version": 1, "items": {"f-…": {"size", "mtime", "read", "placeholder", "status_seen", "missing_since", "error"}}}`。

回合夾多 `streams.jsonl`：一行 `{"kind", "id", "seq"}`。

`kb <種類> show --json`（有 show 的那幾個）多 `"conflicts": [{"id", "field", "values": [{"value", "by", "seq"}]}]`，沒有就空清單。

清冊 `inventory` 一筆的共用欄另有丙第三輪的 `card_mode`、`track`、`archived`（`{"date", "reason", "turn"}`），實體 `entities` 一筆另有 `archived`，都是一般的欄，照上面的行格式寫（`op: "set"`、`set` 只帶改的欄）；`.system/local/textcache/<id>.txt` 本機、不進流水檔。

`kb versions items --json` 的流水檔項目（照丙「資料與介面格式」的項目格式）：`{"item": "<回合>#3", "turn", "said", "op": "create"|"set", "kind": "agenda", "id": "a-…", "seq": 1, "what": "11/25 跟廠商開會", "set": {"date": "2026-11-25"}, "copy": false, "undoable": true}`；`undo` 的 `conflict` 一項多 `"fields": ["date"]`，`later` 每一項的 `side` 是 `self`（同一台另一個對話）或 `other`（別台；第 2 份補 `"who"`），`now` 是那幾欄現在的值。

`skeleton/.gitattributes`：一行 `* -text`。

## 裁定（測試、確認之後才有）

以下是實作 session 的裁定（實作疑義，不是設計 session 定的），照最簡單且不違反已定決策的做法：

1. **轉接層取代逐模組改寫**：不逐一改各模組的 `_mutate`／`_save`，而是在 `io.read_json`／`io.write_json_atomic` 認得搬走的檔名（`streams.LEGACY`），轉成 `streams.read_doc`／`streams.write_doc`（整份文件與筆互轉；`write_doc` 比出新增、刪掉、改了哪幾欄再 `streams.write`）。呼叫端形狀不變，`purge`／`migrate`／`cards` 這些直接寫的地方不用另改。`turn.backup` 對已是流水檔的路徑只在 manifest 記 `stream: true`，改動記在回合的 `streams.jsonl`。
2. **刪掉一筆寫 `{"_del": true}`**，不寫各種類的收回欄（讀回來不列）；收回欄（`RETRACT`）只給「改回新增」用（`kb versions undo` 把新增的那筆改成取消或收回，原本那行還在）。沒有收回欄的種類（profile 等）改回新增時寫 `_del`。另加行欄位 `unset`（欄位被拿掉）。
3. **舊路徑的 JSON 留成衍生副本**（`.system/agenda.json` 等，進 `.gitignore`）：每次合併後寫回，讓還直接開舊路徑讀、查有沒有檔的程式（守門、init、restore、測試）照舊能用；副本被外部整份改過（sha 跟上次寫的不同）會被當成一次整份交回吸收進流水檔（退回換回舊版檔、手改都靠這個）；副本壞了從流水檔重寫。這是 spec 沒寫的，目的是不逐一改十幾個直接開檔的地方。
4. **舊檔懶遷移**：第一次寫某種類時，若還是舊的整份 JSON，就先轉成這台的流水檔（每筆一行 create）並把舊檔搬到 `.system/legacy/`；`migrate.apply` 最後一步 `migrate_streams` 一次轉全部並帶版本資料夾、搬 `config.json` 的 `agenda_export_dir` 到 `env.json`（沒有加進 `STATE_FILES`，免得所有舊庫都顯示「有狀態檔要遷」）。轉換前的 `turn.backup` 對還沒轉的舊檔照舊整份備份，所以 migrate 本身可退。
5. **設定檔與偏好同一個種類目錄** `profile`（`id: "profile"` 一筆放各節，`pf-` 加文字雜湊的各筆是偏好），沒有分成兩個目錄。
6. **退回看同一筆同一欄**：`items._expand_stream` 把回合 `streams.jsonl` 拆成項目；整個回合的「退回」在沒有同欄被動過時走原流程（寫反向行），有同欄之後的行（同台後來的回合，或別台）才逐項列 `conflict`（別台的 `side: other`）。同一台兩個對話記不同筆日程不再互相擋（舊測試 `test_4*` 改成新行為）。流水檔的「版本、其他頂層欄」那一筆（`__meta__`）不列成項目，隨該回合同種類第一個項目一起改回。
7. **purge**：`purge()` 期間 `streams.hard_delete=True`：動到的筆，這台檔裡的舊行拿掉、現在的樣子整筆寫成一行；其他字詞照 `words` 遮；`sources` 的流水檔跟舊的 `sources.json` 一樣不遮（排除的夾名記在那裡）。快取刪掉、副本重算。`write_mask` 標記行（新定 6 的跨台遮掉）有函式與單元測試，但 `purge.py` 實際走的是拿掉舊行（只處理這台的檔）；別台的檔與同步歷史不動，成功句「已同步的舊版本還在歷史裡」沒加。
8. **`系統/` 底下有正本**：`系統/客戶設定檔.md` 是使用者手改後 `kb profile apply` 的來源（D-067），照 `.gitignore` 擋掉的話手改不會跟著同步（套用後的結果 profile 流水檔會同步）。這份照 spec 把 `系統/` 整個擋，回報給設計 session 決定要不要把設定檔 md 放行。
9. **快取量測**：10 台 × 5,000 行 `entities` 合併時間見 `tests/test_lib_streams.py::test_merge_speed_report` 的輸出。
10. **`test_agenda_export::test_folder_gone_still_writes_agenda_opening_silent`** 在 main 上本來就失敗（開場「新作品」那行只講一次），不是這份造成的。

## 補完（第二輪實作）

- inventory、pending 轉流水檔並拆兩半：清冊本機半（`read`、`error`、`missing_since`、`status_seen`、位置的 `size`／`mtime`）、待處理的 `missing_file`／`unreadable` 兩種放 `.system/local/<種類>.json`，其他共用。本機半是 `{id: {…, locs: {uri: {size, mtime}}}}`（位置層級，不是整筆一個 size，裁定）。本機半寫之前整份備進回合（manifest 的一般檔），整個回合退回時一起換回；逐項改回不處理本機半。清冊的流水檔項目標成 derived（不單獨列、不單獨改回，跟舊的清冊一樣）。
- 封存：`statements-archive.json`、`findings-archive.json` 是同一份流水檔的「封存那一邊」（筆的 `archived` 欄有值），主文件不列、封存文件只列它們；兩個檔都只是衍生副本。`lint/checks/archive.py` 不用改（走 `load_archive`）。
- `kb statement／agenda／ruling／finding／entity list --json` 與 `kb profile show --json` 多 `conflicts`。
- purge 成功句在知識庫有 `.git` 時多一句歷史還在；purge 另外把這台自己的檔收成每筆一行現在的樣子、拿掉已刪筆的舊行，回合夾的 `streams.jsonl` 拿掉那些卡的編號行。
- `compact` 由 `streams.write` 在自己的檔超過 `COMPACT_BYTES`（1 MB）時叫。
- 驗收 8 專屬測試 `tests/test_streams_migrate.py`。
- 裁定 8 作廢：設計 session 決定 `系統/客戶設定檔.md` 放行，`.gitignore` 改成 `系統/*` 加 `!系統/客戶設定檔.md`。
