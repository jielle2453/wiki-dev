# 日程匯出到指定資料夾
日期：2026-10-26
狀態：approved
版本：（發行後填）

## 目的

客戶不在電腦前也要看到日程、收到提醒。現在靠一支客製程式每 5 分鐘叫 `kb agenda list` 再寫成 JSON 放到雲端硬碟資料夾，手機頁面與通知程式讀那份檔。問題：

- 她跟 willy 說「下週二下午拜訪王先生」，最慢 5 分鐘後手機才看得到；電腦排程沒設好就永遠看不到。
- 匯出格式（欄位、指紋算法）寫在客製程式裡，willy 改日程欄位時沒人知道要跟著改。
- 想縮短時間只能另掛 Stop hook，跟 willy 自己的 hook 並存沒驗證過。

使用者時刻：她剛說完一件事，拿起手機打開頁面，那件事已經在上面。

## 決策

D-229（2026-10-26 核可；同日縮範圍：willy 只負責輸出 JSON，拿去做什麼是客製；設定由服務人員下指令，不進任何 skill，開場不講）。實作疑義裁定：狀態檔帶 `schema_version`、未設定時 exit 1；回退不還原匯出檔記 B-459。第一輪測試後（2026-10-26）：匯出移到放鎖之後、匯出自己一把鎖並在鎖裡重讀、實體存檔也匯出（T-1～T-3）。第二輪實作疑義裁定（2026-10-26）：`kb agenda export` 不再握 agenda.json 的鎖、直接走 export（同意）；改名／合併／改進度時匯出發生在實體鎖還握著時（接受，B-462）；改名中途失敗 Undo 前已匯出（接受，併 B-459）；匯出鎖搶不到只記 log 不匯出、`kb agenda render`／`kb init`／migrate 不匯出（接受，下一次寫入補上）。

| 抉擇 | 選了 | 為什麼 | 放棄了 |
|---|---|---|---|
| 什麼時候匯出 | 每次寫日程或實體，**放開鎖之後**匯出（第二輪改，原本在 render 結尾、鎖裡面） | 寫日程的路徑（`_mutate`、實體改名合併 `entities._agenda_md`、`refresh_md`）都會走到 render，實體存檔另加一處，涵蓋背景製卡與非對話的 kb 呼叫；匯出在鎖外，匯出夾再慢也不卡住日程的鎖（測試 T-1） | Stop hook：漏掉沒有對話的寫入（客製程式套用手機改動、背景製卡結束後）；排程輪詢：慢、要另外設 |
| 匯出到哪 | 知識庫設定一個資料夾路徑，空的就不匯出 | willy 不知道也不必知道那是雲端硬碟；任何本機資料夾都行 | 直接呼叫雲端 API：要帳號授權，超出 willy 範圍 |
| 匯出什麼 | 只有日程（加實體名單），格式定成 willy 的契約 `willy-agenda/1` | 日程是 willy 的資料，格式該由 willy 管；跟現行客製程式輸出相容，消費端不用改 | 一起匯出客戶綜合卡摘要：那是客製頁面要的形狀，留在客製程式 |
| 失敗怎麼辦 | 匯出失敗不擋日程寫入；寫 hook-errors.log，並記在匯出狀態檔 | 日程是正本，匯出只是一份視圖（同 D-067 的日程.md） | 失敗就整筆退回：會讓她記不進事情 |

## 要做的事

1. `config/defaults.json` 加 `agenda_export_dir`（預設 `""`）與 `_why_agenda_export_dir`。客戶端 `.system/config.json` 覆寫（config.get 現行機制）。
2. `scripts/kb/_lib/agenda.py`：
   - 新增 `export(vault)`：讀 `agenda_export_dir`，空就回 `None`；拿**匯出自己的鎖**（`.system/agenda_export.json` 的 FileLock，不是 agenda.json 的鎖），**在鎖裡重新讀 agenda.json 與實體**組 `willy-agenda/1`（見下節）——不用呼叫端傳進來的資料，最後一個匯出一定是最新內容（測試 T-3）；內容（`exported_at` 以外）跟資料夾裡現有那份相同就不寫，否則原子寫 `<dir>/willy-agenda.json`。任何例外吞掉、寫 hook-errors.log（source `agenda_export`），回 `{"ok": false, "reason": ...}`。
   - 呼叫點一律在**放開 agenda.json 的鎖之後**、外面包 try，保證原本的行為與回傳不變：`_mutate` 的 with 區塊之後（有改才叫）；`entities` 改名合併與 `refresh_md` 走到 render 的路徑，在它們的鎖放開之後叫；`render()` 本身不再呼叫匯出。
   - `scripts/kb/_lib/entities.py` 實體存檔（寫 entities.json）之後也叫一次 `agenda.export(vault)`，名單立刻跟上（測試 T-2）。
   - 每次結果寫 `.system/agenda_export.json`：`{schema_version, last_ok_at, last_error_at, last_error}`（`schema_version` 照 conventions）。
3. `scripts/kb/agenda_cli.py` 新增子命令 `kb agenda export`（服務人員在終端機用；客戶不用知道，不進任何 skill）：
   - 不帶參數：立刻匯出一次（第一次設定後、或資料夾換了時用），印結果。
   - `--set <資料夾>`：檢查資料夾存在且寫得進去（寫一個暫存檔再刪），寫進 `.system/config.json` 的 `agenda_export_dir`，接著匯出一次。不存在或寫不進去就拒絕、不改設定。
   - `--off`：清掉設定（不刪已經匯出的檔）。
   - `--status`：印設定的資料夾與 `.system/agenda_export.json`。
   - 還沒設定資料夾就叫 `kb agenda export`（不帶 `--set`）：exit 1，一句話說怎麼設。
   - `scripts/kb/cli.py` 裡 agenda 那行說明補上 `export`。
   - 都支援 `--json`。
4. 測試：`tests/` 補下節驗收準則對應的測試。

## 來源程式對照

全新（舊 plugin 沒有）。格式對照客製程式 `sync.py` 的 `export()` 與 `fp_of()`（不在本 repo；下節已完整寫出，不需要看原檔）。

## 資料與介面格式

`<agenda_export_dir>/willy-agenda.json`：

```json
{
  "schema": "willy-agenda/1",
  "exported_at": "2026-10-26T08:58:52+08:00",
  "willy_version": "<plugin 版號>",
  "fp": "7d1243ce6a18",
  "items": [
    {"id": "a-ce50311c", "kind": "promise", "start": null, "date": "2026-11-01", "time": null,
     "text": "給李美華旅平險報價", "entities": ["李美華"], "status": "open",
     "source": "inferred", "lead_days": null, "fp": "234f52bb780f"}
  ],
  "entities": [{"id": "e-…", "name": "李美華", "type": "客戶"}]
}
```

- `items`：agenda.json 全部條目（含 done／cancelled），只取上面 11 個欄位；不帶 history、origin、proposal、created_turn。
- 條目 `fp`：`sha256(json.dumps({k: item.get(k) for k in ("kind","date","start","time","text","entities","status","lead_days")}, ensure_ascii=False, sort_keys=True))` 的 hex 前 12 碼。**手機寫回用它判斷衝突，算法改了就要升 schema。**
- 整檔 `fp`：所有條目 fp 依 items 順序串起來再 sha256 前 12 碼。
- `entities`：狀態 active、不是她自己（self）的實體，帶 type；消費端自己挑型別。
- `exported_at` 帶時區；「內容相同不寫」比對的是 `exported_at` 以外的全部。

`kb agenda export --json` 輸出：`{"dir": "...", "written": true|false, "items": 3, "ok": true}`；失敗 `{"ok": false, "reason": "資料夾不存在"}`，exit 1。`--status --json`：`{"dir": "...", "last_ok_at": ..., "last_error_at": ..., "last_error": ...}`。

## 可以動 / 不可以動

可以動：`config/defaults.json`、`scripts/kb/_lib/agenda.py`、`scripts/kb/agenda_cli.py`、`scripts/kb/cli.py`（只改 agenda 那行說明）、`scripts/kb/_lib/entities.py`（只在存檔後與改名合併放鎖後加匯出呼叫）、`tests/` 新增檔、`CHANGELOG.md`（發行時）。

不可以動：`agenda.json` 的 schema 與既有欄位、`render_text()` 的輸出、`_mutate` 與 entities 的鎖與備份順序（只准在放鎖之後加匯出呼叫）、守門（guard）規則、所有 hook、所有 skill 與 references、既有測試。

## 驗收準則

- [ ] 未設定 `agenda_export_dir`：`kb agenda add …` 後資料夾沒有任何檔，`.system/agenda_export.json` 不存在。
- [ ] `kb agenda export --set <暫存夾>`：設定寫進 `.system/config.json`，暫存夾出現 `willy-agenda.json`，`schema` 為 `willy-agenda/1`。
- [ ] `--set` 一個不存在的資料夾：exit 1、白話原因、設定不變。
- [ ] 設定後 `kb agenda add`、`done`、`edit`（改日期）、`cancel` 各一次：每次之後匯出檔的對應條目立刻反映（同一個指令結束時就已寫好）。
- [ ] 實體改名（`kb entity rename`）後，匯出檔條目的 `entities` 已換成新名。
- [ ] 條目 `fp` 與上節算法逐條相符（測試裡獨立重算比對）。
- [ ] 日程沒變再呼叫 `render()`：匯出檔的修改時間不變。
- [ ] 匯出資料夾被刪掉後 `kb agenda add`：日程照常寫入、exit 0；hook-errors.log 多一行 source `agenda_export`；`agenda_export.json` 有 `last_error`；開場不多任何一行。
- [ ] `--off` 後再寫日程：匯出檔不再更新、原檔還在。
- [ ] 匯出夾是連不上的網路路徑時寫日程：匯出期間 agenda.json 的鎖已經放開（另一個行程在這段時間拿得到鎖、寫得進日程，不用等匯出）；日程不掉條目。（測試 T-1）
- [ ] 兩個寫入幾乎同時（第一個的匯出被人為拖慢）：兩個都結束後，匯出檔內容等於最新的 agenda.json。（測試 T-3）
- [ ] `kb entity add`／停用一個實體後，不寫日程，匯出檔的 entities 名單立刻跟上。（測試 T-2）
- [ ] 全部既有測試仍綠（commit 後以 exit code 為準）。

## 確認情境

服務人員視角（客戶不參與設定）：

1. 在知識庫的終端機跑 `kb agenda export --set "G:\我的雲端硬碟"` → 雲端硬碟根目錄出現 `willy-agenda.json`。
2. 她跟 willy 說「下週二下午兩點拜訪王先生」→ willy 記好 → 那份檔立刻有這條（雲端硬碟同步到別台需要幾十秒）。
3. 她說「王先生那個改到週三」→ 檔裡那條日期變週三、條目 fp 變了。
4. 把雲端硬碟登出（資料夾不見）再記一件事 → 照常記好、willy 什麼都不講；`kb agenda export --status` 看得到錯誤。

## 不做

- 匯出檔拿去做什麼（手機頁面、Google 日曆、通知）：一律是客製。
- 讓客戶用說的設定匯出、建置時詢問、開場提示：設定與排錯都是服務人員的事。
- 讀手機寫回的改動檔（另一題；現在由客製程式排程套用）。
- 匯出客戶綜合卡摘要、`willy-clients.json`、通知狀態檔（留在客製程式）。
- 直接呼叫 Google Drive 或其他雲端 API、iCal 匯出。
- 多個匯出資料夾。
- 實體改名回退時同步還原匯出檔（B-459）。
