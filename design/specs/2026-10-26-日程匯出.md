# 日程匯出到指定資料夾
日期：2026-10-26
狀態：approved
版本：（發行後填）

## 目的

客戶不在電腦前也要看到日程、收到提醒。現在靠一支客製程式每 5 分鐘叫 `kb agenda list` 再寫成 JSON 放到雲端硬碟資料夾，手機頁面與通知程式讀那份檔。問題：

- 她跟 willy 說「下週二下午拜訪王先生」，最慢 5 分鐘後手機才看得到；電腦排程沒設好就永遠看不到。
- 匯出格式（欄位、指紋算法）寫在客製程式裡，willy 改日程欄位時沒人知道要跟著改。
- 想縮短時間只能另掛 Stop hook，跟 willy 自己的 hook 並存沒驗證過。

使用者時刻：她剛說完一件事，拿起手機打開頁面，那件事已經在上面。

## 決策

D-229（2026-10-26 核可）。

| 抉擇 | 選了 | 為什麼 | 放棄了 |
|---|---|---|---|
| 什麼時候匯出 | `agenda.render()` 的最後，每次寫日程都匯出 | `_mutate`、實體改名合併（`entities._agenda_md`）、`refresh_md` 都會走到 render，一個點就涵蓋所有寫法，包括背景製卡與非對話的 kb 呼叫 | Stop hook：漏掉沒有對話的寫入（客製程式套用手機改動、背景製卡結束後）；排程輪詢：慢、要另外設 |
| 匯出到哪 | 知識庫設定一個資料夾路徑，空的就不匯出 | willy 不知道也不必知道那是雲端硬碟；任何本機資料夾都行 | 直接呼叫雲端 API：要帳號授權，超出 willy 範圍 |
| 匯出什麼 | 只有日程（加實體名單），格式定成 willy 的契約 `willy-agenda/1` | 日程是 willy 的資料，格式該由 willy 管；跟現行客製程式輸出相容，消費端不用改 | 一起匯出客戶綜合卡摘要：那是客製頁面要的形狀，留在客製程式 |
| 失敗怎麼辦 | 匯出失敗不擋日程寫入；寫 hook-errors.log，並記在匯出狀態檔 | 日程是正本，匯出只是一份視圖（同 D-067 的日程.md） | 失敗就整筆退回：會讓她記不進事情 |

## 要做的事

1. `config/defaults.json` 加 `agenda_export_dir`（預設 `""`）與 `_why_agenda_export_dir`。客戶端 `.system/config.json` 覆寫（config.get 現行機制）。
2. `scripts/kb/_lib/agenda.py`：
   - 新增 `export(vault, data=None)`：讀 `agenda_export_dir`，空就回 `None`；組 `willy-agenda/1`（見下節），內容（`exported_at` 以外）跟資料夾裡現有那份相同就不寫；否則原子寫 `<dir>/willy-agenda.json`。任何例外吞掉、寫 hook-errors.log（source `agenda_export`），回 `{"ok": false, "reason": ...}`。
   - `render()` 結尾（不論 md 有沒有寫）呼叫 `export(vault, data)`，外面再包一層 try，保證 render 的行為與回傳不變。
   - 每次結果寫 `.system/agenda_export.json`：`{last_ok_at, last_error_at, last_error}`。
3. `scripts/kb/agenda_cli.py` 新增子命令 `kb agenda export`：
   - 不帶參數：立刻匯出一次（第一次設定後、或資料夾換了時用），印結果。
   - `--set <資料夾>`：檢查資料夾存在且寫得進去（寫一個暫存檔再刪），寫進 `.system/config.json` 的 `agenda_export_dir`，接著匯出一次。不存在或寫不進去就拒絕、不改設定。
   - `--off`：清掉設定（不刪已經匯出的檔）。
   - `--status`：印設定的資料夾與 `.system/agenda_export.json`。
   - 都支援 `--json`。
4. `skills/manage/SKILL.md`：加問法「日程放到 G 槽雲端硬碟」「手機要看得到日程」「不要再匯出日程」→ 對應 `kb agenda export --set／--off`；設定前先講「之後每次日程有變，會把一份日程表放到 <資料夾>，看得到那個資料夾的人都看得到」，她說好才做。
5. 開場（`hooks/session.py`）：`agenda_export.json` 的 `last_error_at` 比 `last_ok_at` 新，開場多一行「日程放不到 <資料夾>：<白話原因>」，同一個錯誤只講一次（照「這台電腦找不到的來源只報一次」的做法）。
6. 測試：`tests/` 補下節驗收準則對應的測試。

## 資料與介面格式

`<agenda_export_dir>/willy-agenda.json`：

```json
{
  "schema": "willy-agenda/1",
  "exported_at": "2026-10-26T08:58:52+08:00",
  "willy_version": "<plugin 版號>",
  "fp": "7d1243ce6a18",
  "items": [
    {"id": "a-ce50311c", "kind": "promise", "start": null, "date": "2026-11-01", "time": null,
     "text": "給李美華旅平險報價", "entities": ["李美華"], "status": "open",
     "source": "inferred", "lead_days": null, "fp": "234f52bb780f"}
  ],
  "entities": [{"id": "e-…", "name": "李美華", "type": "客戶"}]
}
```

- `items`：agenda.json 全部條目（含 done／cancelled），只取上面 11 個欄位；不帶 history、origin、proposal、created_turn。
- 條目 `fp`：`sha256(json.dumps({k: item.get(k) for k in ("kind","date","start","time","text","entities","status","lead_days")}, ensure_ascii=False, sort_keys=True))` 的 hex 前 12 碼。**手機寫回用它判斷衝突，算法改了就要升 schema。**
- 整檔 `fp`：所有條目 fp 依 items 順序串起來再 sha256 前 12 碼。
- `entities`：狀態 active、不是她自己（self）的實體，帶 type；消費端自己挑型別。
- `exported_at` 帶時區；「內容相同不寫」比對的是 `exported_at` 以外的全部。

`kb agenda export --json` 輸出：`{"dir": "...", "written": true|false, "items": 3, "ok": true}`；失敗 `{"ok": false, "reason": "資料夾不存在"}`，exit 1。`--status --json`：`{"dir": "...", "last_ok_at": ..., "last_error_at": ..., "last_error": ...}`。

## 可以動 / 不可以動

可以動：`config/defaults.json`、`scripts/kb/_lib/agenda.py`、`scripts/kb/agenda_cli.py`、`skills/manage/SKILL.md`、`hooks/session.py`（只加開場那行）、`tests/` 新增檔、`CHANGELOG.md`（發行時）。

不可以動：`agenda.json` 的 schema 與既有欄位、`render_text()` 的輸出、`_mutate` 的鎖與備份順序、守門（guard）規則、其他 hook。

## 驗收準則

- [ ] 未設定 `agenda_export_dir`：`kb agenda add …` 後資料夾沒有任何檔，`.system/agenda_export.json` 不存在。
- [ ] `kb agenda export --set <暫存夾>`：設定寫進 `.system/config.json`，暫存夾出現 `willy-agenda.json`，`schema` 為 `willy-agenda/1`。
- [ ] `--set` 一個不存在的資料夾：exit 1、白話原因、設定不變。
- [ ] 設定後 `kb agenda add`、`done`、`edit`（改日期）、`cancel` 各一次：每次之後匯出檔的對應條目立刻反映（同一個指令結束時就已寫好）。
- [ ] 實體改名（`kb entity rename`）後，匯出檔條目的 `entities` 已換成新名。
- [ ] 條目 `fp` 與上節算法逐條相符（測試裡獨立重算比對）。
- [ ] 日程沒變再呼叫 `render()`：匯出檔的修改時間不變。
- [ ] 匯出資料夾被刪掉後 `kb agenda add`：日程照常寫入、exit 0；hook-errors.log 多一行 source `agenda_export`；`agenda_export.json` 有 `last_error`；下次開場有一行「日程放不到…」，再開一次不重複。
- [ ] `--off` 後再寫日程：匯出檔不再更新、原檔還在。
- [ ] 全部既有測試仍綠（commit 後以 exit code 為準）。

## 確認情境

1. 她說「日程放到 G 槽的雲端硬碟」→ willy 說明會放一份日程表、問好不好 → 好 → 雲端硬碟根目錄出現 `willy-agenda.json`。
2. 她說「下週二下午兩點拜訪王先生」→ willy 記好 → 手機打開日程頁面（讀那份檔），按重新讀取就看到這條（雲端硬碟同步需要幾十秒）。
3. 她說「王先生那個改到週三」→ 頁面重讀後日期變週三。
4. 把雲端硬碟登出（資料夾不見）再記一件事 → 照常記好；下次開場 willy 說一次日程放不到雲端硬碟。

- 直接呼叫 Google Drive 或其他雲端 API、iCal 匯出。
- 多個匯出資料夾。
