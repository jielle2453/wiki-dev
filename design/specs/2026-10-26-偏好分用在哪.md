# 偏好分「用在哪」，加入前先比對
日期：2026-10-26
狀態：開發中
版本：發行時填
來自：issue #12（第二階段）；併入 無
區域：設定與知識、整理成卡、skill 文字

## 目的

第六節偏好不分場合：只講卡片的、只講做文件的、只講某個客製 skill 的，全部擠在開場段同一份清單、同一個 10 條 400 字上限，AI 也分不出哪條在什麼時候用。偏好越記越多還會重複、互相矛盾，現在只擋一字不差的重複。

使用者時刻：
- 她說「以後報價單金額加千分位」→ willy 回「記下了，只在做文件時用」；之後回答問題不會把金額改成千分位。
- 她說「每日議題也找工商時報」→ 記成每日議題的偏好，下次排程照做（客製 skill 不必改設定檔，C001 每日議題 v3 卡住的那件）。
- 她說「講重點就好，不要囉嗦」→ willy 回「這跟第 1 條『回答先講結論』很像，要合併成『回答先講結論、簡短不囉嗦』嗎？」

## 決策（D-504，修訂 D-137、補 D-503）

1. **第六節多一欄「用在哪」**：`全部`、`整理成卡`、`做文件`，或知識庫 `.claude/skills/<名稱>/SKILL.md` 實際存在的客製 skill 名稱。空白＝全部。
2. **送到哪由程式決定，不靠 skill 文字叫 AI 去讀**：
   - 開場段（主對話：回答、記事、做文件、客製 skill 都看得到；compact 後 SessionStart 重跑照樣帶）：`整理成卡` 以外的全部。`全部` 照現在一條一行；其他依「用在哪」分組加小標（`做文件時：`、`<skill 名>：`），AI 只在那件事時套用。
   - 製卡助手材料（`cards batch` 的 `profile.preferences`，D-503）：`全部`＋`整理成卡`。
   - answer、note、produce 不另外送（Jie 2026-10-26 第 1 點：它們沒有固定先跑的指令；都在主對話，開場段就是送達）。
3. **上限分兩組**（設定）：開場段那組（`整理成卡` 以外）最多 `preference_max` 20 條、`preference_max_chars` 1000 字；`整理成卡` 另算 `preference_card_max` 5 條、`preference_card_max_chars` 200 字。依據：2026-10-26 量常駐合計 3198 字（描述 856、core 1013、CLAUDE.md 539、開場狀態 316、偏好最壞 474），上限 5000；偏好放到 1000 字最壞約 3750。
4. **加入前先比對**：`kb profile add 偏好 … --check` 不寫，回同一組與 `全部` 的每一條（序號、句子、用在哪、字面相似度），標出相似度過門檻的、加了會不會超過上限。note 記偏好一律先 `--check`；意思一樣、可合併、互相矛盾由 AI 判斷，提議合併或拿掉，她說好才改。程式保證每次都拿出來比，意思由 AI 判。
5. **可以改既有的一條**：`kb profile add 偏好 序號=N 偏好=<新句> [用在哪=<值>]` 改第 N 條（合併、改用在哪），不另加一條。
6. **歸錯類的補救**（Jie 第 2 點）：分不清用在哪就記 `全部`；成功句講明用在哪（「記下了，只在做文件時用：…」「記下了，每次都照做：…」），她聽了不對可以當場改。
7. **兩個時機檢查**：每次加偏好都先比對（決策 4）；另外**每月**一次掃第六節（jacky 2026-10-26：不用每週），在背景健檢裡多一項「偏好」、自己記上次跑的日子，滿 `preference_lint_days`（30）天才跑：同組（含 `全部`）字面相似過門檻的兩條、用在哪的 skill 已不在、某組超過上限八成，列進待處理。手改 Obsidian 的不經 `--check`，靠這項補。
8. **格式**：profile.json schema 6，每條多 `use`（字串）；schema 5 由 load 在記憶體補 `全部`。md 第六節表頭 `序號｜偏好｜用在哪｜來源｜日期`；讀到舊表頭（沒有用在哪欄）照全部讀。改格式＝大升級，版號 0.24.0。
9. 第六節提示句與 note 文字「偏好只管怎麼回答」改成「怎麼回答、怎麼做東西、寫卡時照做的習慣；用在哪不填就是每次都照做」。

```json

                {"text": "報價單金額加千分位", "use": "做文件", "source": "corrected", "date": "2026-10-30"}]

```
客戶偏好（…照現在的開頭…）：

## 驗收準則

1. schema 5 的知識庫：load 後每條 `use` 是 `全部`；`kb profile show` 第六節多用在哪欄；寫回後 schema 6；舊表頭的 md `apply` 照全部讀。
2. 用在哪只收 全部／整理成卡／做文件／已裝的客製 skill 名：填別的 `apply` 與 `add` 都擋，訊息列出能填的值；skill 被移除後 load 不擋。
3. 開場段：`全部` 一條一行；`做文件`、客製 skill 各自分組加小標；`整理成卡` 不出現；沒有偏好不印。
4. `cards batch` 的 `profile.preferences` 只有 `全部`＋`整理成卡`，順序照表。
5. 上限分組：開場那組第 21 條或超過 1000 字擋；`整理成卡` 第 6 條或超過 200 字擋；兩組互不佔用。
6. `--check` 不寫檔；回同組＋全部的每一條與相似度；`講重點就好，不要囉嗦` 對 `回答先講結論、簡短` 這類例句標出相似（門檻實作時定，例句寫進測試）。
7. `序號=N` 改既有一條：句子與用在哪改了、來源 corrected、日期今天；N 不存在擋。
8. 健檢偏好項：相似的兩條、skill 不在、某組超過八成，各列一題；都沒有不列。距上次不到 30 天不跑（其他項照跑）。
9. `test_budget` 常駐合計 ≤ 5000（偏好照新上限最壞量）。
10. 相關測試全過（jacky 2026-10-26 裁示：開發中與發行前跑相關測試檔，不跑全套）。

## 不做

- 依意思自動合併（只提議，她說好才改）；程式判斷矛盾（AI 判）。
- answer、note、produce 各自的偏好組（都在主對話，用 全部 就好）。
- 偏好分到第二節（卡上段落）以外的其他節。

## 裁定（測試、確認之後才有）

1. （2026-10-26，實作疑義）md 第六節**不加序號欄**，表頭 `偏好｜用在哪｜來源｜日期`；序號只在 `kb profile show` 與 `序號=` 用（照表的順序）。新舊表頭用表頭的字判斷，不數欄數。決策 8 的表頭照這條改。
2. （同上）每月一次的健檢：准改 `scripts/kb/lint/runner.py`（模組 `due(ctx)` 回 False 就這次不跑、不算進 ran、它的待處理件不關）與 `scripts/kb/lint/state.py`（lint.json 多 `last_preference`，KEYS、TYPES 各一行）。
3. （同上）skeleton 與 build steps.md 沒有第六節的表或問偏好那段（設定檔由程式產生）：要做的事第 7 點不用改檔，程式產生的表頭對就好。D-504、D-137 修訂由設計 session 寫（已寫，e77a1ca）。另：同一句跨組也算重複；第六節提示句寫死的上限改成照設定的兩組上限。
4. （同上，相似度門檻）`preference_similar_ratio` 0.35（字元二元組 Jaccard，先去空白標點）。試算：近乎重複 0.43～0.67、字面相反「日期帶星期／日期不用帶星期了」0.38 都標得出；不相干的 ≤ 0.12。意思像字不像的（「講重點就好，不要囉嗦」對「回答先講結論」0.00）門檻抓不到，照決策 4 由 AI 看 `--check` 回的全表判斷。驗收 6 改用「回答先講結論／回答要先講結論」「日期帶星期／日期不用帶星期了」兩對（標出），spec 原例句改成「不標、但 compare 有列出」。每月健檢只看字面，意思像的手改重複抓不到（接受）。
