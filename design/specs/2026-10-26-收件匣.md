# 收件匣：對話裡給的、程式交來的東西經 kb intake 存進知識庫
日期：2026-10-26
狀態：開發中
版本：發行時填
來自：issue #10；併入無
區域：清冊與來源、整理成卡、skill 文字

## 目的

收件匣現在只有客戶自己用檔案總管丟檔進去才進得來；AI 與程式都寫不進去（守門 Z4，`kb intake` 沒做）。這題做 `kb intake`：拖進對話的檔、貼的圖、貼的一段文件、程式或 skill 從外面拿到的內容，都經這一個入口存進 `收件匣/`，記出處，照常整理成卡，整理完問要放哪；收件匣放太久開場提醒。

使用者時刻：
- 沒有資料夾的客戶（C001）把一份 PDF 拖進對話說「這是王先生的合約」→ 收進來、整理成卡掛王先生、回答最後問「要放到王先生的夾嗎」。
- 貼一張名片截圖說「存起來」→ 存成圖檔、整理成卡。
- 公司系統擷取程式每天交一批客戶資料 → 同一位客戶的資料只留最新一份，內容變了卡跟著重做。

## 決策

D-240（拖檔一律複製、說一聲）、D-241（會更新的外部內容住 `收件匣/<來源>/`、同名覆蓋）、D-242（出處同一類「對話收件」，多記從哪裡）、D-243（貼圖從對話紀錄取出、照原格式存）、D-244（整理完當場問一句要放哪）、D-245（檔名：有意義的原檔名照用，其他 AI 取、說一聲）。照做的舊決策：D-045（放太久開場提醒、推薦去處）、D-046（收件匣只有 kb intake 能寫）、D-048（原文一字不改、收件日期）、D-049（貼的文字預設口述、像文件問一句、明說存起來才收）、D-178（推薦去處程式數、AI 判斷）、D-502（對話外跑的寫入有自己的回合）。

這份 spec 另外落實的兩點（從上面推出來，不另開 D）：
1. 貼的文字也從對話紀錄取（同 D-243 的做法）：AI 重打一遍保證不了 D-048 的「一字不改」。桌面版貼的長文字在紀錄裡包在 `<pasted_content>` 裡，取那一段；沒有這個標記（VS Code、終端機）就取客戶那則訊息的全文。
2. 退回收件那一句：收進來的檔拿掉（AI 產出的成品退回時留著，收件不留，issue 情境 10）。

## 要做的事

### 1. `kb intake`（新：`scripts/kb/intake_cli.py`，本體 `scripts/kb/_lib/intake.py`）

不收 `--vault`，總資料夾從 cwd 找（同 convert、output）。三種用法：

**(a) 收檔**：`kb intake <路徑>… [--title <檔名>] [--from <來源名> [--name <項目名>]] [--json]`
- 照順序判斷每份（`output.source_mode` 的寫法，守門同一套 `guard.classify`、`credential_hit`）：
  1. 不存在、不是檔 → 拒絕 `找不到這個檔：<路徑>`。
  2. 在知識庫裡：在收件匣 → `這份已經在收件匣：<相對路徑>`（exit 0，不動）；其他區 → 拒絕 `這份已經在知識庫裡：<相對路徑>`。
  3. 排除的（Z10、Z10b）→ 拒絕 `這個位置你說過不讀`。
  4. 檔名像密碼或金鑰 → 拒絕 `這個檔名像密碼或金鑰，不收`。
  5. 登記的來源裡（Z9）→ 不複製，`這份我已經在讀了：<別名/相對路徑>`（exit 0）。
  6. 指紋（sha256）等於清冊某個 active 條目的現行指紋 → 不複製，`這份收過了：<別名/相對路徑>`（exit 0）。帶 `--name` 的不走這條（見 (c)）。
  7. 其餘 → 複製（`shutil.copy2`）到 `收件匣/<檔名>`，原檔不動。
- 檔名：預設原檔名；有 `--title` 用它加原副檔名（D-245，AI 判斷原檔名看不出內容時給）。檔名檢查照 `output` 的 `_UNSAFE`、冒號、Windows 裝置名，加 `$`、反引號；同名照 `output.free_rel` 加 (2)。
- 多份路徑：每份各自判斷、各自一行結果；有一份被拒，其他照收，exit 3。

**(b) 收這一句貼的圖與文字**：`kb intake --pasted list [--json]`、`kb intake --pasted <種類>:<第幾個> --title <檔名> [--json]`
- 從這一句的對話紀錄取（D-243）：回合檔記的 `transcript` 路徑（見第 3 點），從檔尾往前找第一則客戶訊息（`type` user、`message.role` user，內容不是 tool_result，不是 `isMeta`）。
- `list`：列這則訊息裡的 `image:<n>`（媒體類型、位元組數）與 `text:<n>`（`<pasted_content>` 每段一個；沒有標記時整則訊息算 `text:1`），附字數。
- 存圖：base64 解出來照 `media_type` 存 `.png`／`.jpg`／`.webp`，不轉檔。同一則訊息若有 `attachment` 的 `inlined_image_paths`（`~/.claude/uploads/…` 原圖），照順序對上就複製那份原圖。
- 存文字：那一段原文（去掉 `<pasted_content …>` 與 `</pasted_content>` 標記本身，內文一字不動）寫 UTF-8、LF 的 `.txt`。
- `--title` 必填（沒有原檔名，D-245）；副檔名程式加。
- 取不到（回合檔沒有 transcript、檔不在、這則訊息沒有那一項、JSON 認不得）→ exit 3，一句 `這張圖我拿不到檔；請把它存到電腦，再拖進對話`（圖）或 `這段我拿不到原文；請把它存成檔，再拖進對話`（文字）。
- 標記：清冊 `intake.pasted` 記 `image`／`text`；圖是從 base64 取的（不是 uploads 原圖）另記 `intake.copy: true`（卡上「對話裡的版本」）。

**(c) 程式、skill 交來**：`--from <來源名>`（D-242）、`--name <項目名>`（D-241，要配 `--from`）
- `--from` 沒 `--name`：一次性的，照 (a) 放收件匣最上層，清冊記來源名。
- 有 `--name`：存 `收件匣/<來源名>/<項目名><原副檔名>`。來源名、項目名照檔名檢查（不含 `/`，不准 `.`、`..`、`.` 開頭）。
  - 那裡已有、清冊條目 `intake.from`、`intake.name` 對得上：指紋一樣 → `沒有變：<相對路徑>`、不動；不一樣 → 備進回合（modify）、覆蓋、清冊追加指紋（同 `register_output` active 那段）、`更新了：<相對路徑>`。
  - 那裡已有但不是 intake 交的（客戶自己放的同名檔）→ 拒絕 `收件匣/<來源名>/ 裡已經有同名的檔，不是 <來源名> 交的；請先改名或搬走`。
  - 沒有 → 新收。
- 不帶 `--from` 的就是對話裡收的，清冊不記來源名。

**共同**
- 寫入前 `turn.backup`（新收 create、覆蓋 modify），同 `output.save`。回合照 `turn.current()`（對話外跑的照 D-502 自己一個回合）。
- 清冊：新函式 `inventory.register_intake(vault, rel, turn_id, meta)`，條目 `origin: intake`，選填欄 `intake`（見資料格式），`created_turn`。掃描（`scan`／`apply`）保留 `intake` 欄（同 `skip_kind`、`agenda_fp` 的做法）。
- 對話裡跑的：`turn.touch` 記這份（`kb asks` 當成跟這一句有關）。
- 終端機跑的記程式段（同 output）；對話裡的併進回合。
- 輸出：人讀一份一行（成功句見下），最後一行 `接著整理：kb cards dispatch --json`（有新收或更新才印；對話外跑的不印）。`--json`：`{"items":[{"path","id","result","said"}],"next"}`，`result` 是 `new`｜`updated`｜`same`｜`already_inbox`｜`reading`｜`have`｜`refused`。
- 成功句（一字不差）：`收進收件匣了：<相對路徑>（原檔沒動）`（a）；`收進收件匣了：<相對路徑>（原本叫 <原檔名>）`（a 有 `--title`）；`收進收件匣了：<相對路徑>`（b、c）；`更新了：…`、`沒有變：…`（c）。

## 資料與介面格式

清冊條目選填欄 `intake`（只有 kb intake 收的有；客戶自己丟進收件匣的沒有）：

```json
"intake": {
  "received": "2026-10-26T14:32:05",
  "from": "公司系統",
  "name": "客戶王先生",
  "original_name": "IMG_2034.jpg",
  "pasted": "image",
  "copy": true
}
```

`received` 必有（最近一次寫進來的時間）；其他沒有就不寫鍵。`from` 只有 `--from`；`name` 只有 `--name`；`original_name` 只有改了檔名的；`pasted` 只有 (b)；`copy` 只有從紀錄 base64 取的圖。

回合檔多選填欄 `transcript`（字串，hook 給的路徑）。`env.json` 每台電腦多選填欄 `inbox_reminded`（`YYYY-MM-DD`）。

卡檔頭多選填鍵 `收件`（字串），例：`收件: 2026-10-26`、`收件: 2026-10-26，從公司系統`、`收件: 2026-10-26，對話裡的版本`。

`kb asks --json` 的 `inbox_place` 題：`{"key":"inbox:<條目編號>","kind":"inbox_place","about":[實體…],"question":"…","results":[{"label":"放到 <夾>","do":["kb source-edit move …"]},…,{"label":"先放著","do":[]}]}`（其他欄照現有題）。

拒絕句（一字不差、exit 3）：`找不到這個檔：<路徑>`、`這份已經在知識庫裡：<相對路徑>`、`這個位置你說過不讀`、`這個檔名像密碼或金鑰，不收`、`檔名不能有 \ / : * ? " < > | $ \` 這些字元`、`這張圖我拿不到檔；請把它存到電腦，再拖進對話`、`這段我拿不到原文；請把它存成檔，再拖進對話`、`收件匣/<來源名>/ 裡已經有同名的檔，不是 <來源名> 交的；請先改名或搬走`、`--name 要配 --from`、`--pasted 要給 --title`。

3. 登記的夾裡的檔 → `這份我已經在讀了：<別名/相對路徑>`、不複製。排除夾裡的、`帳密.xlsx` → 照拒絕句、exit 3、什麼都沒寫。

5. `--from 公司系統 --name 客戶王先生` 交 `a.md` → `收件匣/公司系統/客戶王先生.md`；同內容再交 → `沒有變`；改內容再交 → `更新了`、回合備份有舊內容、清冊同一筆多一個指紋、`cards todo` 把那張卡列 stale。客戶自己放的同名檔 → 拒絕。
6. `--pasted`：用 fixture 的桌面版紀錄（回合檔 `transcript` 指到它）→ `list` 列出 image:1、text:1；存 `text:1` 的 `.txt` 內容跟 `<pasted_content>` 內文一字不差；存 `image:1` 的 `.png` 位元組等於 base64 解出來的；有 `inlined_image_paths` 時存的是那份原圖、清冊沒有 `copy`。VS Code 版沒有標記 → `text:1` 是整則訊息。回合檔沒有 `transcript` → 拿不到的那句、exit 3。

8. 退回：收件那句 `versions revert` → 收件匣那份不見、清冊那筆 `turn_reverted`；再退回「退回」本身 → 檔回來、active。覆蓋那次退回 → 舊內容回來。
9. `kb asks --json`：這一句收的、已有卡掛實體的收件匣最上層條目出現 `inbox_place` 題，結果是該實體的夾（份數最多的前三）與「先放著」，`do` 可以直接跑；沒資料夾的知識庫給實體夾；來源子夾的不出現；前幾句收的不在題目裡、算進 `others_line`。
10. 開場：收件匣最上層 10 份 → 印 `收件匣：` 那行並記 `env.json`；同一天再開不印；7 天後再印；只有子夾裡有檔不印；最舊一份 8 天前、只有 1 份 → 印。
11. `kb source-edit move` 從 `收件匣/公司系統/` 搬出 `--check` 多那一行。
12. 守門：AI 用 Write 直接寫 `收件匣/x.txt` 照舊 deny（`test_guard_corpus` 照過）。
13. 對話外（`current.json` 是已答完的對話回合）跑 `kb intake` → 備份在自己的 0000 回合（D-502），不掛進那句對話。

### 實作疑義（2026-10-26）
1. 實體夾還沒建時歸位走不通（`entities.add` 不建夾，綜合卡寫出來才有；沒資料夾的客戶第一份檔整理完 `<型別>/<名稱>/` 多半不在，`source_edit.check_to` 回找不到）。定甲：`kb source-edit move` 的 `--to` 是實體清單裡 active 實體的 `<型別>/<名稱>`（型別在設定檔型別表、名稱是登記的名稱）而夾不在時，先建那個夾再搬；建夾記 `folders.jsonl` 的 make（退回時先搬回檔、再拿掉空夾，照現有資料夾帳），`--check` 多一行 `<型別>/<名稱> 還沒有夾，會先建一個`。只建這一層，型別夾不在（設定檔有、磁碟沒有）照現有拒絕；別的不存在的夾照舊拒絕。`plan` 的 `inbox_place` 照 spec 給 `<型別>/<名稱>`。「可以動」加 `scripts/kb/_lib/source_edit.py` 的 `check_to` 與 move 建目標夾那段、`scripts/kb/source_edit.py` 的 `--check` 輸出。驗收加：沒資料夾的知識庫，實體登記了、夾不在，`kb source-edit move "收件匣/合約.pdf" --to "案子/王先生"` → 夾建好、檔搬進去、卡跟著搬；`versions revert` → 檔回收件匣、夾拿掉。之後綜合卡寫進同一個夾不受影響（`test_lib_cards`／`synthesis` 相關照過）。
2. 開場預算（實作回報：收件匣那行最壞 64 字，疊上「有新版」或「撤回」那行加摺疊會超過 8 行 550 字）。定丙加縮短：(a) `line_version` 印了（有新版、撤回、換了版任一句）時不印收件匣那行，也不記 `inbox_reminded`（下次開場再提醒；收件匣不急，讓版本那行先講）；(b) 句子縮成 `收件匣：<N> 份沒歸位、最久 <D> 天；回答末尾問她要不要一起看，說好再跑 kb asks --all`，取代第 6 點原句。上限不放寬（D-070）。`test_budget` 照這兩條量最壞情況，要過。
