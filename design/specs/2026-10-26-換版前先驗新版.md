# 換版前先驗新版
日期：2026-10-26
狀態：定稿
版本：（發行後填）
來自：issue #7；併入 無
區域：升級與發行、hooks

## 目的

林小姐早上開對話，背景查到有小修就直接換上，現在只驗「版本號對不對」。如果那一版的守門 hook 在她電腦上起不來（語法錯、她的 Python 比我們的舊、缺檔、太慢逾時），hooks.json 的 `onFailure: block` 會讓她**所有資料夾**的 Claude 工具都被擋，連退回都叫不動。這題讓換版之前先在她的電腦上，用她的 Python 跑一次要裝的那份新版，不過就不換。

## 決策

- D-230：抓清單那一版的 zip、核對 sha256、解到系統暫存夾；現在這一版編譯新版每個 .py；跑新版自帶的 `kb selftest`；不過就不換。背景與 `kb upgrade` 都驗；發行程式打包時也跑同一套加 Python 3.10 語法檢查。不做自動退回。
- 相關：D-215（大升級）、D-217（小修自動換、不拍快照、撤回靠發小修）、D-218（清單在 GitHub raw）、D-171（清單的 archive 來源帶網址與 sha256）。
- 這題跟 issue #6（關掉自動記憶，`design/specs/2026-10-26-關掉自動記憶.md`）一起發一版（大升級）。兩題動的檔不重疊。

## 要做的事

### 一、新版自帶的自我檢查：`kb selftest`

1. 新檔 `scripts/kb/selftest_cli.py`（子命令 `selftest [--json]`，註冊進 `scripts/kb/cli.py` 的 `COMMANDS`）與本體 `scripts/kb/_lib/selftest.py`。
2. `kb selftest` 檢查**它自己所在的這份 plugin**（照 `paths.plugin_root()`），不收 `--vault`、不碰 cwd 的知識庫。步驟照順序，第一個不過就停：
   1. `import`：`scripts/kb/` 底下每個模組都 import 得到（照檔案走訪，`kb.lint.checks` 這類子套件也算）。
   2. `version`：`.claude-plugin/plugin.json` 讀得到、版本照 `_lib/upgrade.parse_version` 合法。
   3. `vault`：在系統暫存夾（`tempfile.mkdtemp`）用這份的 `kb init` 建一個小知識庫，並寫 `.system/config.json` 把 `update_manifest_url`、`update_rollout_url` 設成空字串（背景升級那段不連網）。
   4. `hooks`：讀這份的 `hooks/hooks.json`，每個註冊的 command 都跑一次子行程：`[sys.executable, <plugin_root>/hooks/<檔>.py, <參數…>]`（從 command 字串取出 `hooks/` 後面的檔名與參數，不經 shell），stdin 給下表的 payload，環境變數帶 `CLAUDE_PLUGIN_ROOT=<plugin_root>`、`WIKI_WITH_WILLY_NO_BACKGROUND=1`。每個要 exit 0、在 `selftest_hook_seconds` 內結束，守門與開場還要看輸出：

      | hook | payload（cwd 一律是暫存小知識庫，`session_id` 是 `selftest`） | 要看的 |
      |---|---|---|
      | SessionStart `session.py` | `{"hook_event_name":"SessionStart","source":"startup"}` | stdout 是 JSON，`hookSpecificOutput.additionalContext` 含「【wiki-with-willy】」 |
      | UserPromptSubmit `turn.py` | `{"hook_event_name":"UserPromptSubmit","prompt":"自我檢查"}` | exit 0 |
      | PreToolUse `guard.py`（該擋） | `Write`，`file_path` 是 `<小知識庫>/.system/sources.json` | stdout JSON 的決定是 deny |
      | PreToolUse `guard.py`（該放） | `Read`，`file_path` 是暫存夾裡小知識庫外的一個檔，cwd 也在知識庫外 | 沒有輸出，或決定不是 deny |
      | PostToolUse `output_log.py` | `Write`，`file_path` 是小知識庫外的一個檔 | exit 0 |
      | Stop `stop.py` | `{"hook_event_name":"Stop","last_assistant_message":"好"}` | exit 0 |
      | SessionEnd `session_end.py` | `{"hook_event_name":"SessionEnd","reason":"other"}` | exit 0 |
      | SubagentStart／Stop `subagent.py` | `agent_type` 是 `selftest`（不是 card-maker） | exit 0 |

      hooks.json 有、上表沒有的 hook：給 `{"hook_event_name":<事件>}`，只看 exit 0 與時間。
   5. `upgrade`：在小知識庫跑 `kb.py upgrade --background`（子行程），要 exit 0、在 `selftest_hook_seconds` 內結束（清單網址是空的，會直接回來）。這一步保證之後修好的小修送得到。
   6. 收尾一律刪掉暫存小知識庫（`finally`）。
3. 輸出：人讀第一行 `自我檢查過了（X.Y.Z）` 或 `自我檢查沒過：<步驟>：<原因>`，exit 0／3。`--json`：`{"ok": true|false, "version": "X.Y.Z"|null, "step": null|"import"|"version"|"vault"|"hooks"|"upgrade", "file": null|"<plugin 根底下的相對路徑>", "line": null|整數, "why": null|"一句話"}`。`file`、`line` 從例外或子行程 stderr 最後一段 traceback 取（取得到才填）；`why` 不含絕對路徑、照 `credentials.mask_secrets` 遮過。
4. 自我檢查本身出錯（例外）也回 `ok: false`，`step` 照當時那步、`why` 是例外名稱，不丟 traceback。

### 二、換版之前驗：`scripts/kb/_lib/upgrade.py`

1. `fetch` 多回清單那一筆的 `source`：`{"url": …, "sha256": …}`（照 `tools/release.py` 寫進 `marketplace.json` 的 `entry["source"]`；不是 archive、缺網址或缺 sha256 時是 `None`）。
2. 新函式 `verify(vault, latest, source)`：
   1. `source` 是 `None` → 不過（`why`：「清單沒有這一版的下載網址」）。
   2. 抓 zip 到系統暫存夾（`tempfile.mkdtemp`，`finally` 刪），經可換替身的 `_download`；算 sha256，跟 `source["sha256"]` 不同 → 不過。
   3. 解壓前每一項檢查：不准絕對路徑、`..`、磁碟代號（跟 `_lib/backup.verify` 的 zip slip 同一套判法，能共用就共用）。
   4. 編譯：用目前這個 Python（`sys.executable`，就是她的）對解出來的每個 `.py` 做 `compile(原始碼, 相對路徑, "exec")`，只在記憶體、不寫 .pyc。第一個 `SyntaxError` → 不過，記檔與行號。
   5. 跑新版的自我檢查：`[sys.executable, <解出來的>/scripts/kb.py, "selftest", "--json"]`，子行程、cwd 是暫存夾、逾時 `update_verify_seconds`（含下載的總時間，經 `_call`，逾時殺整棵行程樹）；沒有這個子命令、非 0、逾時、輸出讀不懂、`ok` 不是 true、`version` 跟 `latest` 不同 → 不過。
   6. 回 `{"ok": bool, "version": latest, "python": "<主>.<次>", "step", "file", "line", "why"}`，`step` 多兩種：`download`、`compile`。
3. **背景小修**（`_auto_patch`）：拿鎖之後、`run_update` 之前先 `verify`。不過就不換，回 `{"verify_failed": <verify 的結果>, "error": <句子>}`，句子：`新版 {version} 在這台電腦跑不起來（{where}），沒有換`，`where` 是「`<file>` 第 `<line>` 行」或「`<step>` 那步」加原因。`update_check` 已經記著同一版、同一個 `python` 的 `verify_failed` 時，背景不再抓、不再驗，直接沿用（不每天重抓）。
4. **對話裡的 `kb upgrade`**（`upgrade`，大升級與小修都走這裡）：`_guard_ready` 之後、拍快照之前先 `verify`（不管 `update_check` 記過什麼，每次都驗）。不過就丟 `backup.Refused`，句子：`新版 {version} 在這台電腦跑不起來（{where}），先不換；什麼都沒動`，exit 3；沒拍快照、沒記 `pending`。
5. `--downgrade` 不驗（要回去的是她之前跑過的版本）。
6. `env.json` 的 `update_check` 多一個選填欄 `verify_failed`（`verify` 的回傳，`ok` 是 false 的那份）；`BLANK_CHECK` 補 `"verify_failed": None`。換成功或清單換了新版本時清掉。
7. `kb upgrade --check`（`check`／`check_lines`）：`update_check.verify_failed` 的版本等於清單現在的版本時，人讀多一行 `新版 {version} 在這台電腦跑不起來（{where}），先沒換`，`--json` 多 `verify_failed`。開場（`opening`、`hooks/session.py` 的 `line_version`）**不改**，照舊安靜（issue #7）。

### 三、發行時也跑：`tools/release.py`

1. `build` 打完 zip、最後檢查那段多兩項（不過照現有做法丟 `ReleaseError`，問題一次全列）：
   1. 每個 `.py` 用 `ast.parse(原始碼, feature_version=(3, 10))` 檢查，抓到的寫「`<檔>` 第 N 行：Python 3.10 不認得這種寫法」。
   2. 把這份 zip 解到暫存夾，跑它的 `kb selftest --json`（開發機的 Python），不過就列出那句。經可換替身的 `_selftest` 呼叫，測試換掉。
2. `publish` 照舊先 `build`，所以兩項都會跑到。

### 四、設定與文件

1. `config/defaults.json` 加兩個鍵，各帶 `_why_`：
   - `update_verify_seconds`：`90`。為什麼：下載一份 zip、編譯、跑自我檢查（開一個小知識庫、每個 hook 跑一次）的總時間上限；背景不拖慢開場，對話裡的升級會多等這麼久。
   - `selftest_hook_seconds`：`5`。為什麼：自我檢查裡每個 hook 最多幾秒；hooks.json 給守門 10 秒，正常不到 1 秒，超過 5 秒在她電腦上就有逾時的風險，當作不過。
2. `CLAUDE.md`（repo 的）原始碼地圖：新增 `scripts/kb/selftest_cli.py`、`scripts/kb/_lib/selftest.py` 兩列；`scripts/kb/_lib/upgrade.py`、`scripts/kb/upgrade_cli.py`、`tools/release.py`、`config/defaults.json`、`scripts/kb/_lib/env.py` 各列補一句。
3. `skills/manage/references/ops.md` 升級那段補一句：`kb upgrade` 回「新版 X 在這台電腦跑不起來…」時照句子講，說我們修好會再發，不要叫她重試或自己換。

## 驗收準則

1. `kb selftest --json` 在 repo 裡跑：`ok: true`、`version` 是 `plugin.json` 的版本；跑完系統暫存夾沒有留下它建的小知識庫；cwd 的知識庫（如果有）沒有任何檔被改（比對前後的檔案清單與修改時間）。
2. 把 repo 複製到暫存夾、各做一種壞法，`kb selftest --json` 都是 `ok: false` 且 `step` 對：
   - `scripts/kb/_lib/` 某模組加一行 import 不存在的模組 → `import`，`file` 是那個檔；
   - `hooks/guard.py` 改成永遠不輸出 → `hooks`，`why` 說守門該擋沒擋；
   - `hooks/session.py` 最上面加 `import time; time.sleep(10)`（`selftest_hook_seconds` 設成 1 的暫存 config 也可）→ `hooks`，`why` 說逾時；
   - `hooks/turn.py` 改成 `sys.exit(1)` → `hooks`；
   - `scripts/kb/upgrade_cli.py` 讓 `--background` 丟例外結束碼非 0 → `upgrade`。
3. `upgrade.verify` 用替身下載（`_download` 回一份測試裡現打的 zip）：
   - 正常的 zip、sha256 對 → `ok: true`；
   - sha256 不對 → `ok: false`、`step: download`；
   - zip 裡有 `../x` 或絕對路徑的項目 → `ok: false`，暫存夾外沒有多檔；
   - `hooks/guard.py` 有語法錯 → `ok: false`、`step: compile`、`file: hooks/guard.py`、`line` 是那一行；
   - 沒有 `selftest` 子命令的舊版 zip → `ok: false`、`step: selftest`；
   - 自我檢查超過 `update_verify_seconds` → `ok: false`，子行程被殺掉；
   - `source` 是 `None` → `ok: false`。
4. 背景小修：替身清單給一個小修、名單允許、`verify` 不過 → `run_update` 沒被叫、`update_check.verify_failed` 有值、`error` 是那句；隔天（替身改日期）再跑、清單同一版 → `_download` 沒被叫；清單換成更新的一版 → 重新驗。`verify` 過 → 照現有行為換版、`auto_patched` 有值、`verify_failed` 清掉。
5. 對話裡的 `kb upgrade`（大升級與小修各一）：`verify` 不過 → exit 3、那句一字不差、沒拍快照（`.system/snapshots/` 沒有新檔）、`upgrade-history.json` 沒有 `pending`、`run_update` 沒被叫；`verify` 過 → 照現有行為。
6. `kb upgrade --downgrade` 不叫 `verify`。
7. `kb upgrade --check`：`update_check.verify_failed` 是清單現在那一版時人讀多那一行、`--json` 有 `verify_failed`；是更舊的版本時不印。開場段（`hooks/session.py` 的輸出）跟改之前一樣（`test_budget` 照舊過）。
8. `tools/release.py build`：tag 裡有一個 `.py` 用了 3.10 不認得的寫法（例如 3.12 的型別參數 `def f[T](x): …`）→ 拒絕、列出檔與行；替身 `_selftest` 回不過 → 拒絕；都過 → 照現有行為打包。
9. 全部測試 `python -m unittest discover tests` exit 0（commit 之後跑）；`kb selftest` 在全部測試裡至少真的跑一次（不換替身）。

## 確認情境

在桌面版跑，跟 issue #6 那份一起確認（同一個測試知識庫、同一次 local 安裝）；這份的步驟另外記。設計 session 先備好：拋棄式公開 repo 與本機市集照 `design/reports/備份還原與升級打包-確認.md` 的做法，打三版：
- **X**：這題實作的最後 commit（裝在測試知識庫，local 範圍）；
- **X+0.0.1 壞的**：同一份，只把 `hooks/guard.py` 加一行語法錯；
- **X+0.0.2 好的**：同一份，只改版本號與 CHANGELOG（版本號比壞的大一號，清單才換得過去）。

先停用舊 llm-wiki plugin；記下 `~\.claude\settings.json` 的 sha256，做完比對沒變。

1. 清單指到「壞的」小修、名單放測試知識庫，清掉 `.system\env.json` 的 `update_check`，開新對話。預期：開場照常、沒有提到更新；過一兩分鐘（背景跑完），`claude plugin list` 的版本還是 X。再開新對話，守門照常：問「我有哪些資料夾」照常回答、讀檔不被擋。
2. 跟 AI 說「有新版嗎」。預期：AI 跑 `kb upgrade --check`，白話說新版在這台電腦跑不起來、先沒換、我們修好會再發，不叫她自己換；`--json` 的 `verify_failed` 寫 `hooks/guard.py` 和行號。
3. 清單換成「好的」X+0.0.2，開新對話（不用清 `update_check`：清單換了版本就會重新驗）。預期：背景驗過、換上；再開新對話開場說「已自動套用小修正 X+0.0.2：…」。
4. 手動做一個大升級版本（版本第二位加一，壞的），開場提有新版後說「好，升級」。預期：AI 說新版在這台電腦跑不起來、先不換、什麼都沒動；`.system\snapshots\` 沒有新的「升級前」快照。
5. 時間：步驟 1 的開場跟沒有新版時一樣快（背景跑，不等它）。

收尾：local plugin 與市集照 process 第六節清掉；拋棄式公開 repo 請使用者自己刪。
