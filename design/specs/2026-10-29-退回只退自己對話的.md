# 多個對話同開時，退回只退自己那個對話的
日期：2026-10-29
狀態：做完（0.27.1）
版本：0.27.1
來自：issue #20；併入 B-019（部分：模型在對話裡叫的 kb 拿得到 session）
區域：回合與日誌、hooks、守門與密碼

## 目的

同一位客戶、同一台電腦，對同一個知識庫開兩個以上的對話。現在說「退回」，會退掉**整個知識庫最近的那一回合**，可能是另一個對話寫的；更早一步，另一個對話開口之後，這個對話叫 kb 寫的東西會記進**另一個對話的回合**。要改成：每個對話的寫入記在自己的回合，退回只退自己對話的，而且不蓋掉別的對話後來的改動。只開一個對話時行為不變。

使用者時刻：她在 A 視窗記「11/25 有個會」，B 視窗接著記「提醒我寄發票」；回到 A 說「退回」。她要的是會議不見、提醒還在。

### 查證（2026-10-29 實跑，0.26.3，main 7c4d0da 之後）

假知識庫用 `kb init` 建，回合用真的 `hooks/turn.py`、`hooks/stop.py` 開與收，寫入用 `kb agenda add`。腳本在設計 session 的 scratchpad（`two_sessions.py`），不進 repo。

| # | 操作 | 實際 | 結論 |
|---|---|---|---|
| a | A 記會議 → 答完；B 記提醒 → 答完；A 說「退回」→ `kb versions revert` | 退掉 `B：提醒我寄發票`，A 的會議留著 | **證實**：挑回合不分對話（`versions.py` `_revert_locked` 的 `cands` 取 `.system/versions/` 全部回合，`[0]` 就退） |
| a2 | 同上，看 `versions/<回合>/turn.json` | 每個回合夾都記了完整 `session_id`（`turn.turn_dir` 寫的） | 挑回合**有依據可用**，不用猜代號尾 4 碼 |
| 1b | A 開口；B 開口（還沒答完）；A 這時才 `kb agenda add` | A 的會議記進 **B 的回合**「B：你好」 | **新發現**：kb 指令拿不到自己的 session，`turn.current()` 讀共用的 `current.json`（誰最後開口就是誰）。光改退回挑回合不夠，寫入就記錯了（B-019 同根） |
| c | 量常見寫入碰哪些檔 | `agenda add` → `.system/agenda.json`＋`系統/日程.md`；`profile add 偏好` → `.system/profile.json`＋`系統/客戶設定檔.md` | 每種 kb 寫入只碰「自己那份整份狀態檔＋渲染的 md」。兩個對話做**不同種類**的事不重疊；做**同一種**事（都記日程、都整理檔案動清冊）就重疊 |

檔案工具（Write／Edit）寫綜合卡、檔案索引、AI 產出時，守門與 PostToolUse **已經**用 payload 的 session_id 記回合（`hooks/guard.py:104`、`hooks/output_log.py:73`），這段沒問題；漏的是 kb 指令：`scripts/kb` 底下 63 處 `turn.current(vault)` 不帶 session。

### 情境 2「兩個對話改同一張綜合卡」現在怎麼擋（I-038）

**現在沒有任何「這份之後被別的回合改過」的檢查**（`CHANGED_SINCE` 只用在 `delete-outputs`，`versions.py:964`）。I-038 是靠 D-074「只從最近一次退、不跳」在結構上避開：要退的永遠是最新那回合，後面沒有別人的改動可蓋。情境 2 現在的實際結果（由 a 推得，同一段程式）：A 說退回，退掉的是 B 對那張卡的改動——退錯對象，但不會蓋掉更新的內容。

一旦改成「跳過別的對話的回合」，就是 I-038 那種退舊回合，**必須**補上重疊檢查，否則還原整份 `agenda.json` 或綜合卡會把 B 後來的改動蓋掉（上表 c：兩邊都記日程就會碰到）。

## 決策

2026-10-29 使用者定：三題都照推薦（D-506～D-508）。D-507 修訂 D-074，照 process 第八節第 3 條要 jielle2453 同意；2026-10-29 使用者裁示先開工不等（已在 #20 留言），對方有異議時回設計改 spec。下面保留候選與放棄的理由。

### 決 1 kb 指令的寫入記在哪個對話（D-506：選 (a)）

- 推薦 (a)：守門替主對話的**每個單一 kb 呼叫**插 `--session <payload 的 session_id>`（現在只插 `cards dispatch|status|stop`、`build`、`intake`，`hooks/guard.py:49-50`、`:202`）；`turn.current()` 與其他讀 `current.json` 的函式有 `turn.SESSION` 時只認那個對話的回合檔，不退回去讀 `current.json`。
- (b) 只替 `versions` 插：退回挑得對，但上表 1b 的寫入照樣記錯，退回仍會退到別人的東西。
- (c) 不插，靠 `current.json` 的時間與 done 猜：兩個對話同時在回答時猜不出來。
- 為什麼推薦 (a)：機制已經有（`--session` 全域旗標、守門插旗標、模型自己帶 `--session` 會被 `SELF_FLAGS` 擋），只是範圍擴大；一處改、63 個呼叫點一起對。
- 碰到守門（`hooks/guard.py`），照 process 第三節不走輕流程，要另開測試 session。這不是放寬守門（只多插旗標，判斷不變）。

### 決 2 對話裡說「退回」時挑哪些回合（D-507：選 (a)）

候選回合＝「沒退過、有改動」的回合中，排除**別的對話**的（`turn.json` 的 `session_id` 非空且不等於這個對話）。剩下的照時間取最新一個，自己對話的照舊不跳。

- 推薦 (a)：留下「這個對話的」＋「沒有對話的」（終端機 `0000`、背景健檢 `-lint`、`turn.json` 沒 session_id 的舊回合）。只開一個對話時候選跟現在完全一樣，情境 3 成立。
- (b) 只留這個對話的：順便解 B-613（背景健檢排在最上面），但只開一個對話時行為也變了，終端機跑的改動從對話裡退不到（要另給路）。
- card-maker 的 job 回合：`turn.json` 的 session_id 是派工那個對話（實作時驗；不是的話照 `batches.json` 的 job `session` 認），算「這個對話的」。
- 終端機跑 `kb versions revert`（沒有 `--session`）：照現在，全部回合取最新一個。

### 決 3 要退的回合碰過的檔，後來被別的回合改過（D-508：選 (a)）

「後來被改過」＝比要退的回合晚、**任何**回合（別的對話、對話外、已退回的、退回動作本身都算）的 `manifest.jsonl`、`folders.jsonl`、`moves.jsonl` 碰到同一個路徑（大小寫不分）。保守判斷：寧可多擋。

- 推薦 (a)：**整個不退**，什麼都不動，拒絕句講是哪幾份、被哪一句（`_describe`：「MM-DD HH:MM 那句「…」」）改過，給兩條路：到那個對話先退、或直接說要改成什麼（用改的，不用退的）。exit 3。
- (b) 只退沒重疊的那幾份、重疊的留著：退成一半，客戶分不清哪些退了。
- (c) 整份狀態檔按條目合併（只拿掉這回合加的那筆日程）：最準，但 agenda、statements、entities、inventory、pending…每種一套合併，另起一題。
- (d) 照退、蓋掉：違反 I-038，不考慮。
- 代價：兩個對話碰到同一份整份檔就會被擋——同種事（都記日程），以及共用的衍生檔：清冊 `.system/inventory.json`、`檔案索引/總目錄.md`、`.system/pending.json`＋`系統/待處理.md`、`.system/batches.json`（兩邊都整理、收件、存成品就會撞，裁定 7）。要解只能走 (c)，列進 backlog 等真的常發生再做。

### 決 4 修訂 D-074（D-507；待 jielle2453 同意）

D-074「退回只能從最近一次開始，不跳」改成「只能從**這個對話**最近一次開始，不跳；別的對話的回合跳過，但碰到它們改過的檔就整個不退」。D-502 的重談條件「B-019 解了、CLI 拿得到 session_id」也因決 1 成立，要一起看（決 1 只解模型在對話裡叫的，終端機與外部程式照 D-502）。

**process 第八節第 3 條：修訂已定的決策要對方（jielle2453）在 issue #20 留言同意才做。** spec 定稿前要拿到。

### 預設照做（小決定，不另問）

- `versions list` 在對話裡只列決 2 的候選範圍；有別的對話的回合時多一行「另一個對話還有 N 次改動，不在這裡退」。`--json` 每筆多 `session`（`self`｜`other`｜`none`），照留全部。
- `delete-outputs` 沒給代號時挑「最近一個有可刪成品的已退回回合」也照決 2 的範圍。
- 退回動作本身的回合（`_acting_turn`）用這個對話的回合，不讀 `current.json`。

## 驗收準則

假知識庫照「查證」的做法：`kb init`，回合用 `hooks/turn.py`／`hooks/stop.py` 帶不同 session_id 開，kb 呼叫帶 `--session <sid>`（模擬守門插的）。

1. [ ] 情境 1：A 記日程（agenda）→ 答完；B 記口述（statement，先 `entity add`）→ 答完；A 開口「退回」、`kb --session A versions revert` → exit 0，成功句是 A 那句；`agenda list` 沒有 A 的、`statement list` 有 B 的。
2. [ ] 寫入歸屬（上表 1b）：A 開口；B 開口未答完；`kb --session A agenda add …` → `versions list --json` 那筆在 A 的回合（從 A 看 `session` 為 `self`）、不在 B 的。
3. [ ] 情境 2：A 改綜合卡 X（`turn.before_write` 帶 A 的 sid）→ 答完；B 改 X → 答完；A「退回」→ exit 3，印決 3 的拒絕句、列出 X 與 B 那句；X 內容、`reverted.json`、回合夾都沒變（比對前後 sha256 與檔案清單）。`--json` 回 `refused: overlap`。
4. [ ] 同種狀態檔重疊：A、B 先後各記一筆日程，A「退回」→ exit 3（列出 `系統/日程.md`、`.system/agenda.json`），兩筆日程都在。
5. [ ] 情境 3（只有一個對話）：現有 `tests/test_scripts_versions_cli.py` 全綠；另加：A 改完 → 終端機跑 `kb agenda add`（`0000` 回合）→ A「退回」→ 退的是 `0000` 那回合（決 2 推薦 (a)，跟現在一樣）。
6. [ ] 自己對話不跳：A 連續兩句各改不同檔，B 其間改別的檔；A「退回」→ 退 A 的第二句；再「退回」→ 取消剛才那次退回（`AGAIN` 那行的現行行為），不是退 A 的第一句。
7. [ ] 終端機跑 `kb versions revert`（沒 `--session`）：照現在，退全部回合最新的一個。
8. [ ] `versions list`：從 A 看，B 的回合不列，多一行「另一個對話還有 1 次改動，不在這裡退」；`--json` 列全部且 `session` 欄對。
9. [ ] 守門：主對話 Bash 跑單一 `python …/kb.py agenda add …`、payload 帶 session_id → `updatedInput` 插了 `--session <sid>`；card-maker（帶 agent_id）照舊插 `--turn` 不插 `--session`；模型自己帶 `--session` 照舊被擋（`SELF_FLAGS`）；主對話已帶 `--turn` 的呼叫不插 `--session`（裁定 1）。
10. [ ] `kb turn note`／`redact` 帶 `--session A` 改的是 A 那句，B 開口之後也一樣。
11. [ ] card-maker job 回合算派工的對話：A 派整理、job 回合寫了卡；B 改別的；A「退回」→ 候選包含 A 的 job 回合（照現有 `test_cardmaker_revert.py` 的做法造）。
12. [ ] 拒絕句與列表不出現回合代號（B-074）。

## 不做

- 一人多對話的協作本身（分層、角色、主管、開會、檢查點）：不放進 willy，在 pixel-office 做；那邊要在知識庫寫紀錄時，照樣經守門與 kb 寫，等那邊設計定了另開題（issue #20 第四節）。
- 多位使用者、多台電腦（issue #5）。
- 重疊時按條目合併退回（決 3 的 (c)）：另起題。
- 終端機、排程、外部程式拿 session（B-019 其餘部分、B-612）：照 D-502。
- 背景健檢排在退回最前面（B-613）：決 2 選 (a) 時不解，照舊在 backlog。
- 客戶在 Obsidian 手改的檔不在 manifest，重疊檢查看不到（跟現在一樣）。
- 兩個對話同開時，帶密碼值的呼叫（`unlock save --value`、`convert --password`）的備份與 convert 自己標的 `secret_shown` 可能記到別的對話的回合（裁定 12、16、17；B-628）。

## 裁定（測試、確認之後才有）

### 實作疑義

1. （2026-10-29，實作回報：插 `--session` 會讓三處「主對話沒有 updatedInput」的既有斷言變紅）主對話的單一 kb 呼叫一律插 `--session`，**但呼叫已經帶 `--turn` 的不插**（以 `--turn` 為準，`turn.OVERRIDE` 管這次呼叫；同時有兩個會讓 `_set` 等改到對話的回合而不是 job 回合）。所以：`tests/test_hooks_guard.py:451-453`（`kb version`）與 `tests/test_cardmaker_round1.py:183`（`cards todo --json`）改成斷言插了 `--session <SID>`；`tests/test_cardmaker_round1.py:174`（`turn note --turn <job>`）**維持**沒有 updatedInput。`test_cardmaker_round1.py` 加進「可以動」，只准改這兩處斷言。驗收準則 9 多一項：主對話帶 `--turn` 的呼叫不插 `--session`。
