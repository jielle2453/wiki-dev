## 要做的事
根因：`系統/客戶設定檔.md` 是 profile 流水檔的渲染頁，卻用 `!系統/客戶設定檔.md` 放進 git；兩台各自渲染出不同的 md → git 衝突；pull 進來的 md 跟這台記的 `md_sha256` 對不上 → 被當手改、舊值回寫。
1. `skeleton/.gitignore`：拿掉 `!系統/客戶設定檔.md`（跟其他渲染頁一樣擋掉）。
2. `scripts/kb/_lib/git.py`：`untrack(vault, paths)`（`git rm --cached --quiet --ignore-unmatch`）。
3. `scripts/kb/_lib/skeleton.py` `reconcile`：這次新建或換新版 `.gitignore` 的那台（多人時就是拿到認領的那台）對 `UNTRACKED`（設定檔 md）`untrack`，檔留在這台；不是 git、出錯不擋升級。她改過 `.gitignore`（交 AI 問的那種）不動。
4. `scripts/kb/_lib/refresh.py` `_render_pages`：設定檔 md 沒有也重畫（別台不再追蹤時，pull 會把這台的刪掉）。
5. 多人共用 1 spec 決定紀錄加一條「裁定 8 改回」（jacky 2026-11-05 定）。
6. `tests/test_refresh.py` `test_profile_md_untracked_and_rerendered`、`tests/test_streams_skeleton.py` 的清單；ops 四列。

## 可以動 / 不可以動
- 可以動：上列檔、本 spec。
- 不可以動：設定檔的手改流程（`kb profile apply`、她改過先問）、其他渲染頁、`claim_rewrite`。
- 相關測試：test_refresh、test_git_two_clones、test_streams_skeleton、test_lib_skeleton、test_lib_git、test_scripts_init_cli、test_scripts_upgrade_cli、test_version_sync、test_repo_hygiene。

## 驗收準則
