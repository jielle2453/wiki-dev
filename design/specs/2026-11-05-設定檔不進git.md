## 要做的事
根因：`系統/客戶設定檔.md` 是 profile 流水檔的渲染頁，卻用 `!系統/客戶設定檔.md` 放進 git；兩台各自渲染出不同的 md → git 衝突；pull 進來的 md 跟這台記的 `md_sha256` 對不上 → 被當手改、舊值回寫。
1. `skeleton/.gitignore`：拿掉 `!系統/客戶設定檔.md`（跟其他渲染頁一樣擋掉）。
2. `scripts/kb/_lib/git.py`：`untrack(vault, paths)`（`git rm --cached --quiet --ignore-unmatch`）。
3. `scripts/kb/_lib/skeleton.py` `reconcile`：每次對帳後，`.gitignore` 沒有放行 `UNTRACKED`（設定檔 md）的就 `untrack`（她改過 `.gitignore` 但沒自己放行的也算；重跑無害），檔留在這台；不是 git、出錯不擋升級、記 log。
4. `scripts/kb/_lib/refresh.py` `_render_pages`：設定檔 md 沒有也重畫（別台不再追蹤時，pull 會把這台的刪掉）；`resolve_conflicts`：設定檔 md 的衝突（還沒升級的那台改了、這邊不再追蹤）一律不追蹤、留這台的、之後重畫。
4b. `scripts/kb/_lib/streams.py`（review 找到）：`md_sha256`（這台渲染出的 md 指紋）照「本機那一半」（`SPLIT`、`.system/local/profile.json`）每台自己記；共用那份照舊帶著（還沒升級的別台讀它），讀的時候換成這台的，這台沒記過先用共用的。不然 A 改設定、B 的 md 還是舊的，對同步來的指紋就被當成手改、`profile apply` 把舊值寫回——就是本題要解的。
4c. `scripts/kb/_lib/migrate.py` 兩處：md 不見（`md_sha256` 回 None）不算有沒套用的手改。
5. 多人共用 1 spec 決定紀錄加一條「裁定 8 改回」（jacky 2026-11-05 定）。
6. `tests/test_refresh.py` `test_profile_md_untracked_and_rerendered`（含 A 改設定、B 的 md 舊但不當手改、refresh 畫成新的）、`test_profile_md_modify_delete_conflict`、`tests/test_streams_skeleton.py` 的清單；ops 四列。

## 可以動 / 不可以動
- 可以動：上列檔、本 spec。
- 不可以動：設定檔的手改流程（比的基準換成這台的指紋，流程本身不變）（`kb profile apply`、她改過先問）、其他渲染頁、`claim_rewrite`。
- 相關測試：test_refresh、test_lib_streams、test_streams_migrate、test_lib_migrate、test_lib_profile、test_scripts_profile_cli、test_git_two_clones、test_streams_skeleton、test_lib_skeleton、test_lib_git、test_scripts_init_cli、test_scripts_upgrade_cli、test_version_sync、test_repo_hygiene。
