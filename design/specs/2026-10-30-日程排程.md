# 日程第二題：開始與工期、接、屬、原定、要徑、順延、假日表，加首頁拖曳改期

日期：2026-10-30（10-31 補完句子、驗收與首頁的部分；11-09 對齊 0.35.1：多人共用、記帳、D-335 之後的格式）
狀態：設計中（「待決」四題使用者定完、看過說可以才改定稿）
版本：0.36.0（功能版，D-217 標 minor；沒有遷移列，不是大升級）
來自：issue #23；D-107、D-125、D-253、D-252、D-266、D-268、D-273、D-288、D-289、D-290、D-335、D-337；Obsidian 首頁 0.29.0（#22）留下的「拖曳改日期等 #23」
區域：日程、延伸、Obsidian

## 目的

做工程的客戶要排工期：「泥作做 5 天，完了隔一天木作進場」「水電完成前 2 天木工就可以進來」。一件事延了，後面接著的要跟著推，她想先看到會推到哪天再決定。日程條目多四個選填欄（工期、接、屬、原定），程式照工作天與假日表算日子、算要徑、提順延建議；Obsidian 首頁的時間軸畫出子項、連線、原定的淡框與要徑，bar 可以拖。不填這些欄的客戶看到的跟現在一樣（D-107）。

時間軸的資料格式（`kb home --json` 的 `timeline`，含這題要填的 `children`、`links`、`baseline`、`critical`、`slack`、`derived`、`hard`）定在 Obsidian 首頁 spec「資料與介面格式」第 1 節，這裡只寫這題怎麼填。0.29.0 已經先做好的：`kb home` 每個記號帶這幾欄的預設值、每列 `links: []`（`home.py`）；外掛已會畫子項縮排、同列連線（要徑加粗）、原定框、要徑 class 與滑過提示「要徑」，有 node 測試（`tests/obsidian/timeline.test.js`）。這題要填值，外掛補還沒有的：`.wwh-baseline` 與要徑記號的樣式、母項收合子項、提示裡的工期／接／原定、拖曳。

## 決策

- D-107：四欄、全部選填、順延先問、工作天。
- D-125：分兩題，這是第二題。
- D-253：「接」只留「前項完成才開始」，間隔可負；首頁改日期也問要不要跟著推。
- D-252：時間軸由 kb 算，外掛只畫。
- D-266、D-268：首頁動作少、要你確認的只放點完就做完的題（順延題的「照建議推」是一個指令就做完，放得上首頁）。
- D-269：`系統/日程.md` 不畫圖。
- D-273 (3)：改日程日期時程式列出同實體同一天的帳（`related_money`），AI 問要不要一起改、不自動連動。
- D-288：日程正本是流水檔 `.system/streams/agenda/<這台>.jsonl`，`agenda.json` 是讀出來的副本；兩台改同一欄、值不同、彼此沒看過才算撞到。
- D-289：日程有 `whose`，畫面只列全隊的加自己的。
- D-290：影響共用資料的設定檔節全隊一份。
- D-335：狀態檔自己的 `schema_version` 凍結、新欄一律選填、遷移看內容；遷移表有新列才是大升級。
- D-337：只往後加的歷程合起來不算撞到（`streams.APPEND_ONLY` 的 agenda `history`）。
- 這份 spec 新定（10-31，設計 session 判斷，使用者看 spec 時可改）：
  1. 順延建議兩個方向都給：前項延後就往後推、提前就問要不要跟著提前；句子講清楚是哪個方向。
  2. 拖曳只在時間軸（月曆照現在點日期小框改）；母項、重複的事、到期與會議以外的都能拖。到期與會議可以拖（它自己改期），但永遠不被別人推（D-107 的 late）。
  3. 前項晚了才完成（打勾那天比原定 `date` 晚）或改了日期時，當場問要不要跟著推，照實際完成那天算；逾期還沒處理時只在待辦「已經過了」顯示，不另出題、不靠健檢（使用者 10-31）。
- 11-09 對齊時照上面的決策推出來的（不另開 D）：
  4. 不升版號、沒有遷移（D-335）：四欄與假日節都選填，沒有就當空的；`agenda`、`profile` 的 `schema_version` 不動，`migrate.STATE_FILES` 不加列，`streams.FORMAT_VERSION` 停在 2。同事那台還是舊版時照常能寫，只是不記 `moved_from`、不出順延題（D-335 已接受這類，不個案判斷）。
  5. 母項的 `start`／`date` 讀的時候由子項算、不寫回流水檔：寫回的話兩台各改一個子項會撞母項同一欄（D-288）。
  6. 工期推出來的日子寫的時候算好、存進原本的 `start`／`date`（很多地方直接讀 `date`：件數、逾期、匯出），另記哪一欄是推出來的（給 `derived`）。
  7. 一起推做成一個指令（`agenda edit … --shift`），一個回合：外掛每叫一次 kb 就是一個回合，`edit` 再 `shift` 會變兩個回合，復原會再跳順延問句。
  8. 要徑、連線、母項範圍用全部條目算，畫的時候才照 D-289 篩人。

## 欄位

日程條目多四個選填欄，存法照流水檔（D-288），`schema_version` 不動（決策 4）。

| 欄 | 中文 | 意思 |
|---|---|---|
| `duration` | 工期 | 工作天數（正整數）；有 `date` 沒 `start` 時程式往前推 `start`；有 `start` 沒 `date` 時往後推 `date`；推出來的那欄記進 `derived`（`["start"]` 或 `["date"]`），之後她直接改那欄就拿掉 |
| `after` | 接 | `[{"id": "a-…", "gap": n}]`：前項完成才開始，`gap` 是工作天、可負（重疊）；前項不能是自己、自己的母項或子項、不能成環；最多 5 個前項 |
| `parent` | 屬 | 上一層條目的 id；母項不能有 `parent`（只一層）；母項的 `start`／`date` 讀的時候由子項算（最早的 start、最晚的 date），不存、不能直接改（決策 5） |
| `moved_from` | 原定 | 第一次改期前的 `{start, date}`，程式自動留、之後不覆寫；`kb agenda edit --clear-moved` 清掉（她說「以這個為準了」）；等於現在的日期時當沒有 |

- 重複的條目不收這四欄。
- 到期、會議可以有 `after`（等前項做完才到期），但順延時不推它們，列進 `late`。
- 兩台同時改：改期的歷程照 `_log` 寫進 `history`（只往後加，D-337，不算撞到）；`moved_from` 是一般欄，兩台都從同一版第一次改期時寫的值一樣，不算撞到；兩人同時拖同一件、拿舊資料推，照 D-288、D-295 撞到就問，不另出題。
- 完成時所有種類都記 `ended`（現在只有期間記，`agenda.py` 設 status 那段）：`date` 不動；晚完成時 `moved_from` 記原本的 `{start, date}`；首頁記號的結束改用 `ended`（`home._mark`、日程頁過去區照現在期間的做法）。
- 設定檔第十一節「假日」（第九節數字欄、第十節記帳已用）：欄 日期／種類（放假｜補班）／說明，主鍵日期；`profile.SECTION_SPECS`、`SECTION_NAMES` 加一列、`NUMERALS` 加「十一」。跟九、十節一樣是選填節（`REQUIRED_SECTIONS = 8` 不動），舊 md 少這節不算錯；`profile.json` 版號停在 7。全隊一份（D-290）。預設工作天是週一到週五，扣放假、加補班。只影響工期與 gap 的換算，不影響「到期」那天本身。
- 假日表增減時，同一回合重算還沒做完、`derived` 有標的那幾筆；後項照順延題問（確認情境 5）。

## 要做的事

1. **`kb agenda add|edit`** 收 `--duration N`、`--after <a-…>[:<gap>]`（可重複）、`--no-after`、`--parent <a-…>`、`--no-parent`、`--clear-moved`。`add` 有 `--start --duration` 時 `--date` 可以不給（現在 `--date` 必填，`agenda_cli.py`）；`--whose` 照舊。
   - `edit` 改了日期（start 或 date）時，第一次記 `moved_from`；算 `proposals`（照 `after` 與 gap、工作天，受影響的後項與子項帶出的母項）。
   - 只回 `proposals`、不推；`--check` 連這一條都不寫，只回會怎樣（給拖曳預覽用）。`--check` 的本體照 D-256 放 `_lib/check.py`（現在只有 `cancel --check`）。
   - `--shift`：改這一條、照建議一起推後項，一個回合（決策 7）；`--no-shift`：只改這一條、不開順延題（外掛「只改這一件」用）。
   - 母項直接改日期拒絕；改子項時母項的範圍跟著重算（這不算順延，不問）。
   - 改了日期照現在一樣回 `related_money`（D-273 (3)）。
2. **`kb agenda shift <a-…> [--check]`**：從這一條往下照現在的日期重算後項，照建議一起改（一個回合）。到期與會議不動、列 `late`。`moved` 每一筆也帶 `related_money`（D-273 (3)）。跑完關掉那個前項的 `reschedule`（照 `pending.resolve_money_dupe` 的做法）。
   - `kb agenda done <a-…>` 完成那天比原定 `date` 晚、後面有接著的：記 `ended`、`moved_from`，回 `proposals`（照實際完成那天算），跟改期同一套。
3. **要徑**：每個事類實體裡有 `after` 的條目才算；照工作天、以那實體 open 條目最晚的 `date` 為終點算寬裕；寬裕 0 的 `critical: true`，`slack` 填工作天數。用全部條目算（含別人的，決策 8）。
4. **工作天**：`_lib/workdays.py`（新）讀設定檔第十一節；用現有的 `kb profile add 假日 日期=… 種類=放假|補班 說明=…`、`kb profile remove 假日 日期=…`（`profile_cli.py` 通用，不另加子命令）。
5. **順延題**：待處理 kind `reschedule`。登記在 `pending.KINDS`、`SECTIONS`、`plan.PENDING_ONLY`、`plan._pending_results`；照 `pending.add_money` 用 `data` 記前項（`{"after": "a-…"}`），不用 `file_ids`。
   - 誰開：`edit`／`done` 有 proposals、沒帶 `--shift`／`--no-shift` 時程式自己開，不靠 AI。外掛先跑 `--check`，Esc 什麼都沒寫，也就不開題；外掛跳的小框她直接關掉（沒選）時才叫一次不帶旗標的 `edit` 讓題留著。
   - 同一個前項只開一件，**新的蓋舊的**（跟 `add_money` 的「已有就不重開」相反）。不靠健檢。
   - 她直接改 `系統/日程.md` 的日期（D-263 的手改吸收）走同一條：改了日期就開題；改母項的日期做不了，放進「認不出的」（carried）。
   - 題目與答案（`kb asks`，首頁照 D-268 放得上）：「泥作改到 11/20，後面 2 項要跟著往後推 3 天嗎？」→「照建議推」（`agenda shift <id>`）、「只改這一件」（`pending resolve`，記「她說不推」）；不急的有「先放著」。晚完成的：「泥作晚了 2 天完成，後面 2 項要跟著往後推嗎？」。
   - 多人時問誰：見「待決」第 2 題。
6. **`kb home`**：時間軸填 `children`（子項照母項分組、畫在母項那一列，不照子項自己掛的實體分列；母項 bar 是子項範圍）、`links`（`{"from","to","gap","critical"}`，只給同一列的，外掛跨列不畫）、`baseline`（有 `moved_from` 的給 `{start, date}`，等於現在日期時 `null`）、`critical`、`slack`、`derived`。先用全部條目算，再照 D-289 篩人（現在 `home._build` 一開始就篩，要改順序）。要你確認的照 D-268 加 `reschedule`。`willy-home/1` 不升版（加欄不升版，同首頁裁定 33、40）。
7. **外掛**：
   - 時間軸：子項在母項下面縮一格（母項前的小箭頭收合子項，跟案子收合分開）；連線是淡灰細線從前項尾巴到後項開頭，要徑的條與線加粗、用那案子的顏色深一階；原定淡框（虛線、跟現在的推測虛線要分得出來：原定用淡灰底、推測用虛線框）；滑過 bar 提示「工期 5 天｜接在泥作後面，隔 1 天｜原定 11/10～11/14」。補 `styles.css` 的 `.wwh-baseline` 與要徑記號樣式。
   - **拖曳**：按住記號拖，移動少於幾像素算點擊（開卡，首頁裁定 32），超過算拖；按住背景照現在是捲動。拖 bar 中間整條平移（工期不變）、拖右邊緣改結束日、拖點改那天；每格對齊一天，拖的時候旁邊小字顯示新日期；放手叫 `edit --check`，沒有 proposals 就直接 `edit`、跳「改好了」加「復原」；有 proposals 就在那條旁邊跳小框「後面 2 項要跟著往後 3 天嗎？木作 11/21→11/24、系統櫃 11/25→11/28」，按「一起推」→ `edit --shift`，按「只改這一件」→ `edit --no-shift`；Esc 或點框外 → 都不改，bar 回原位。
   - 「復原」照首頁裁定 36（隨手記）的做法叫 `versions revert` 退那個回合，不送相反的 `edit`（會再跳順延問句、`moved_from` 也留著）。
   - 母項、重複的事不能拖（游標顯示不能放，放手跳一句為什麼）；推測的拖了算確認。
   - 待辦點日期改期（D-266）、月曆小框改日期、待辦打勾完成時比原定晚，同一套問法（D-253）。
   - 同一天有帳時小框怎麼說：見「待決」第 3 題。
   - 月曆：子項當一般的事畫（同案同色），不畫連線與要徑。
8. **note**：`skills/note/references/agenda.md` 加「拆成幾項」「接在…後面」「隔兩天」「前兩天就可以進場」「工期 5 天」「放假、補班」「以這個為準」的聽法與指令；成功句與拒絕句照下一節；聽不出前項是哪件就問，不猜。多人的 `--whose` 規則照現在那段。
9. `系統/日程.md`：清單裡有工期、接的那件多一小段字「（5 天，接泥作後）」；母項的日期照算出來的寫；不畫圖（D-269）。手機頁匯出 `willy-agenda/1` 不加欄（D-252），母項的 `start`／`date` 放算出來的值。

- 「重複的事不能接在別的後面、拆子項或設工期。」
- 「這樣會繞一圈（木作接泥作、泥作又接木作），改不了。」
- 「施工的日期是照底下幾項算的，改其中一項就好。」
- 「子項不能再拆一層。」
- 「找不到要接的那件（a-…）。」
- 「工期要是 1 以上的整數。」

## 資料與介面格式

`kb agenda edit <id> --date 2026-11-20 --json`（`--check` 同格式、`"changed": false`）：沿用現在的 `{"item", "changed", "related_money"}`，加 `proposals`、`late`、`direction`：
```json
{"changed": true, "item": {"id": "a-…", "text": "泥作", "start": "2026-11-14", "date": "2026-11-20", "moved_from": {"start": "2026-11-10", "date": "2026-11-17"}},
 "related_money": [],
 "proposals": [{"id": "a-…", "text": "木作", "from": {"start": "2026-11-18", "date": "2026-11-24"}, "to": {"start": "2026-11-21", "date": "2026-11-27"}, "days": 3}],
 "late": [{"id": "a-…", "text": "燈具到期", "date": "2026-12-01", "why": "到期"}],
 "direction": "later"}
```
- `days` 是工作天差；`direction` 是 `later`｜`earlier`｜`none`（沒有 proposals）。
- `kb agenda shift <id> --json` 與 `edit --shift --json`：`{"moved": [同 proposals 一筆，加 related_money], "late": [...]}`（`edit --shift` 另帶 `item`、`changed`）。
