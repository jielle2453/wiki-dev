# 關掉自動記憶
日期：2026-10-26
狀態：設計中
版本：（發行後填）
來自：issue #6；併入 B-077（已轉成 issue #6）
區域：核心規則與開場、建置、升級與發行

## 目的

林小姐在知識庫裡說「以後跟我講日期都要帶星期」，AI 有時走 note 寫進設定檔第六節，有時寫進 Claude Code 自己的自動記憶（`~/.claude/projects/<專案>/memory/`）。後者她看不到、退不回、備份不帶（I-114、note 改規則確認 G-1）。這題把平台那條路在知識庫裡關掉，要記的事只剩 willy 的路。

## 決策

- D-229：骨架的 `.claude/settings.json` 加 `"autoMemoryEnabled": false`；建置的環境檢查多一項；桌面版實測，不吃才加守門；舊記憶檔不搬不刪；改骨架所以是大升級。
- 相關：D-137（偏好在設定檔第六節）、D-146（口述清單）、D-217（改骨架不准標小修）、例句 9 與 `_lib/skeleton.py`（骨架對帳）。
- 這題跟 issue #7（自動套小修前先驗 hook）一起發一版（大升級）。

## 要做的事

1. **`skeleton/.claude/settings.json`**：多一個鍵 `"autoMemoryEnabled": false`，`permissions.deny` 照舊是空清單。JSON 兩格縮排、LF、結尾換行，跟現在的檔同一個寫法。
2. **`scripts/kb/_lib/build.py` 環境檢查多一項 `memory`**：
   - `ENV_KEYS` 在 `trust` 後面插 `memory`（變九項）；`env_items` 照 `ENV_KEYS` 的順序回，`safe()` 包起來（出錯那項回 warn「看不出來（例外名）」，現有做法）。
   - 新函式 `_env_memory(p)`：讀 `<p>/.claude/settings.json` 與 `<p>/.claude/settings.local.json`（後者優先序比較高，有這個鍵就以它為準）。結果與句子見「資料與介面格式」。只讀，不改任何檔。
   - `env_items`、`ENV_KEYS` 的 docstring 與註解「八項」改成「九項」。
3. **其他地方不用改程式、但要有測試守著**：
   - `kb init` 新建知識庫會帶新的 `settings.json`（骨架照抄，現有行為）。
   - 既有知識庫大升級時，`kb upgrade --finish` 的骨架對帳把沒改過的 `settings.json` 換成新版並備進回合；改過的列進要問的（現有行為，`_lib/skeleton.reconcile`）。
   - `kb moved` 換電腦時，環境檢查不是 ok 的項目照現在的做法一起列出（`_lib/moved.py` 用 `build.env_items`），`memory` 自動進去。
4. **`CLAUDE.md`**（repo 的）：原始碼地圖 `skeleton/` 那列補「`.claude/settings.json` 關掉自動記憶（D-229）」，`scripts/kb/_lib/build.py` 那列的 `env_items` 八項改九項、補 `memory`。
5. **測試**：照下面「驗收準則」寫，改到的既有測試（`tests/test_scripts_init_cli.py` 的 `test_settings_json_is_bare_deny_list`、`test_scripts_build_cli.py` 數項數的地方、`test_lib_skeleton.py`）跟著改。
6. 不動 `config/skeleton_history.json`：那是發行時 `tools/release.py build --prepare` 追加的。

## 來源程式對照

全新。兩個舊 plugin（`design/reference/` 的兩個 zip）都沒處理過自動記憶。

## 資料與介面格式

**`skeleton/.claude/settings.json`**（完整內容）：

```json
{
  "permissions": {
    "deny": []
  },
  "autoMemoryEnabled": false
}
```

**`_env_memory(p)` 的判法與回的項目**（`{"key": "memory", "level": …, "text": …}`，沒有 `fix`）：

| 情況 | level | text |
|---|---|---|
| `settings.local.json` 有 `autoMemoryEnabled` 而且是 `false`；或沒有這個鍵、`settings.json` 的是 `false` | ok | `自動記憶關了：要記的事都記進知識庫` |
| `settings.local.json` 的 `autoMemoryEnabled` 是 `true` | warn | `自動記憶被 .claude\settings.local.json 打開了：要記的事可能記到知識庫外面；請服務人員把那一行拿掉` |
| `settings.json` 在，但沒有這個鍵或不是 `false`（local 也沒設） | warn | `這個知識庫沒關自動記憶：要記的事可能記到知識庫外面；升級到新版時會補上` |
| `settings.json` 不在（還不是知識庫，例如 `kb build env` 在空資料夾跑） | ok | `還沒建知識庫；建好就會關自動記憶` |
| 任一個檔讀不了或 JSON 壞了 | warn | `看不出自動記憶有沒有關（.claude 裡的設定檔讀不了）` |

`kb build env`（人讀與 `--json`）照現有格式多這一行；`kb build status --json` 的 `env.items` 多這一項。

## 驗收準則

1. `kb init <空夾>` 建出來的 `.claude/settings.json` 用 `json.loads` 讀得到 `autoMemoryEnabled is False`，`permissions.deny == []`；位元組跟 `skeleton/.claude/settings.json` 一樣。
2. 既有知識庫：`settings.json` 是舊版內容（`{"permissions": {"deny": []}}` 那份，位元組照舊骨架），`.system/skeleton.json` 記著舊版指紋 → 跑 `_lib/skeleton.reconcile`（或 `kb upgrade --finish` 用替身換版）之後，檔案換成新版，回合夾有舊版的備份，退回（`kb versions revert`）換得回舊版。
3. 同上，但 `.system/skeleton.json` 不在：舊內容對得上 `config/skeleton_history.json` 裡任何一版 → 算沒改過、照樣換新（現有規則）。測試用暫存的歷史檔造一筆舊版指紋。
4. `settings.json` 被改過（內容跟所有記錄過的版本都不同）→ 不換、列進要問的（現有行為不退步）。
5. `env_items` 回九項，順序 `python, kb, trust, memory, sac, pdf, office, disk, old_wiki`；`memory` 照上表五種情況各一個測試，句子一字不差；`_env_memory` 丟例外時那項是 warn「看不出來（…）」、其他八項照常。
6. `kb build env --json` 在剛 `kb build start` 的知識庫裡，`memory` 是 ok。
7. `kb moved --check --json` 在 new_machine 狀態、`settings.json` 沒有這個鍵時，列出的環境項目含 `memory` 那句（用替身造 new_machine，照 `test_lib_moved` 的做法）。
8. `tools/release.py` 的小修規則：骨架檔改了的版本不准標小修（現有測試在就好；沒有就補一個用這個檔當例子的）。
9. 全部測試 `python -m unittest discover tests` exit 0（commit 之後跑，process 第三節步驟 3）。

## 確認情境

在桌面版跑，不能用子代理代替（子代理沒有自動記憶，測不到，I-114）。跟 issue #7 那份一起確認時照這份的步驟另外記。

準備（設計 session 先備好）：
- 先停用舊 llm-wiki plugin（process 第六節確認段的做法）。
- 測試知識庫照 conventions 第六節的假來源建好；plugin 用 worktree 的快照市集，只裝在測試知識庫那個夾（local 範圍，process 第六節）；權限模式用預設。
- 記下這個知識庫的記憶夾路徑（`~/.claude/projects/<知識庫路徑換成的夾名>/memory/`）：裡面現有哪些檔、`MEMORY.md` 的修改時間；再放一份假記憶 `MEMORY.md`，內容一行「回答一律用英文」。
- 記下 `~\.claude\settings.json` 的 sha256，做完比對沒變。

步驟：
1. 開新對話，問「今天有什麼要做的」。預期：回答是繁體中文，表示假記憶「回答一律用英文」沒有被讀進來。人眼：`/memory` 畫面的自動記憶顯示關。
2. 說「以後跟我講日期都要帶星期」，再說「回答先講結論」。預期：AI 走 note，`系統/客戶設定檔.md` 第六節多兩條；記憶夾沒有新檔、`MEMORY.md` 修改時間不變；畫面沒有「Saved N memories」。
3. 開新對話，問一個會講到日期的問題（例：「信義王下次開會是哪天」）。預期：日期帶星期。
4. 說「日期不用帶星期了」（第六節那條拿掉），再開新對話問同一題。預期：不帶星期。這證明偏好只來自知識庫。
5. 說「幫我備份」，再到一個空資料夾從那份備份還原（manage 的還原流程，或確認 session 在終端機跑 `kb restore apply`）。預期：新資料夾的 `系統/客戶設定檔.md` 第六節有步驟 2 的「回答先講結論」，`.claude/settings.json` 有 `autoMemoryEnabled: false`。
6. 終端機在知識庫跑 `kb build env`。預期：有「自動記憶關了：要記的事都記進知識庫」那行。

判讀：步驟 1 或 2 不過（假記憶被讀到，或記憶夾多了檔），表示桌面版不吃專案設定。這時停下來回報設計 session，照 D-229 改加守門，不要繼續往下。

收尾：移除假記憶，plugin 用 `claude plugin uninstall … --scope local`、`marketplace remove … --scope local` 清掉，比對使用者範圍的 `settings.json` 沒變。

## 不做

- 守門擋寫記憶夾：等確認情境證明桌面版不吃專案設定才做（D-229）。
- 舊記憶檔搬進知識庫：還沒有真客戶有記憶檔（D-229）。
- 還原 0.23 之前的備份會把 `settings.json` 一起還原成沒有這個鍵的版本：沒有客戶有那麼舊的備份，不處理；環境檢查會看出來。
- 使用者層的 `~/.claude/CLAUDE.md`、環境變數 `CLAUDE_CODE_DISABLE_AUTO_MEMORY`（整台電腦）都不碰。
- 總資料夾的 `skeleton/CLAUDE.md` 不加句子。
