日期：2026-11-01
狀態：設計中（三份草稿 11-01 寫好；11-02 對齊 D-323～D-334；「這份 spec 新定」要使用者看；D-287 修訂 D-191 等 jacky 在 #5 同意；三份定稿前先跑 B-524 的 spike）
版本：（發行後填）

區域：設定與知識、日程、守門與密碼、建置

## 目的

第 1 份把資料換成每台寫自己的流水檔，但每一行的 `who` 都是空的，也不知道這個知識庫是不是多人在用。這份讓 willy 知道「這台是誰」「這個知識庫幾個人用」，多人時：口述等出處寫人名、日程與偏好與「可以讀」分「全隊」和「某人的」、每台的畫面只列全隊的加自己的、同事列進團隊成員不被當外人；每台的雲端同步夾位置（含放在團隊雲端的暫存區）問一次記本機；新同事 clone 下來第一次開能直接用；舊版讀到新格式停寫並問要不要升。單人知識庫看起來跟現在一樣（照舊寫「你」、不問名字）。

使用者時刻：小王在新電腦第一次開對話 → Claude 問「這台電腦是誰在用？我先記成 wang-laptop，要換別的叫法嗎？」→ 他說「小王」；之後他說「提醒我週五寄樣品」只出現在他自己的日程頁與首頁，老闆說「週五全員開會」大家都看得到；口述出處寫「小王 11/01 說的」。

## 決策

- D-286：多人時每台第一次開對話問一次這台是誰，預設 git 的 user.name，存本機不進 git；出處、日程、回合、帳記這個名字；單人照舊寫「你」不問。
- D-287（修訂 D-191，等 jacky 同意）：看建置訪談的「幾個人用」，記進客戶設定檔一行，2 人以上算多人；對話裡可改；沒有這行的舊庫當單人。
- D-289：日程每筆「誰的」：全隊或一到幾個人；AI 判斷、拿不準當全隊；檔案抽的全隊；每台畫面只列全隊的＋我的。
- D-290：設定檔影響卡的全隊一份；「關於你」改公司＋團隊成員名單（問名字時自動加，算客戶自己）；偏好帶「誰的」、拿不準歸說的人、開場帶全隊的＋我的、上限兩邊合算。
- D-292：來源的每台實際位置存本機，這台第一次找不到 AI 問一次記這台。
- D-297：開檔密碼只存各台；多人時解鎖那刻說「解開後內容會整理成卡，團隊都看得到」；「可以讀」的裁示記是誰同意的、只對那人有效。
- D-298 第 (2) 點：舊版讀到比自己新的行停止寫入、查與答照常；要記時問要不要升、說好照 D-215 升、提醒開新對話。
- D-300：新 clone 第一次開照各條自動走；這台的原檔指紋在背景算、算完才報變動；新 clone 不誤問搬家。
- D-296：別人之後改過同一欄先說一句再退。
- **11-02 對齊放寬限制（#28 #29）的決策**（這份用到的）：
  - D-321：退回是一件一件改回；第 11 點接丙的 `kb versions undo` 逐項檢查，D-296 的「別人之後改過先問」照留。
  - D-323：原檔留團隊雲端硬碟、每台登記成來源，D-292 的來源別名與每台實際位置照用（第 9 點）。
  - D-324：多人時暫存區整個放團隊雲端（第 9 點的接法）。
  - D-327：只在開場做的檢查改到每句開頭或這台每天第一句（第 3 點）。
  - D-328：檔案卡的「開原檔」是 willy Obsidian 外掛連結、只帶清冊編號，卡上沒有每台的路徑；外掛問 kb 這份在這台哪裡，照第 9 點的每台位置解析，所以 `locate` 之後不用重寫卡。
  - D-334(3)(4)：多人時團隊雲端的來源預設 `shared: true`（甲 五.1b 的欄），**暫存區例外**：暫存區雖在團隊雲端，AI 在裡面搬、刪、放草稿不用先告知（使用者 11-02：那是放還不知道歸哪的東西，搬進搬出是日常），只有團隊自己的夾才告知；共用夾裡比對出的變動說「可能是同事動的」、不說「你」（第 10 點）；只在雲端的佔位檔只比大小與時間、不讀內容（丙 1-2b，第 3 點新同事的 `learn` 同樣適用）。
- **設計自定（11-02 對齊時定）**：
  1. **暫存區在多人時怎麼接上**：暫存區當成一個保留別名 `暫存區` 的來源（清冊的 uri 本來就是 `file://暫存區/…`，甲第二輪 8），共用的 `spec` 是團隊雲端那個夾，每台位置照 D-292 記在 env 的 `source_paths`；`kb intake`、`kb output save` 落暫存區時照這個別名解析（有登記走登記、沒登記照舊是知識庫裡的 `暫存區/`）。知識庫裡的 `暫存區/` 照第 1 份第 7 點進 `.gitignore`。
  2. `line_who` 跟丙 3b-1 那批一起放每句開頭（不只開場）：客戶多半不開新對話（D-327），單人轉多人那天改了人數，同一個對話下一句就會問。
  3. 多人時所有登記在知識庫外的來源都是團隊雲端的夾，`folders add` 沒給 `--shared` 就當 `yes`；單人照甲（沒給當 false，AI 問一次）。
  4. 共用夾或 pull 進來的變動，照它記的口述 `who` 留空（出處只寫日期），不算到這台的人頭上（同新定 4 的理由：不知道是誰就不猜）（第 10 點）。
- **這份 spec 新定（要使用者看過說可以）**：
  1. **「幾個人用」放第五節**：第五節標題多人時寫「五、關於你們（公司與團隊成員）」，表格上面一行「幾個人用：6」；單人照舊「五、關於你」、那行寫「幾個人用：1」。不另開一節（D-191 怕的「改了沒作用」現在有作用了，但多一節客戶要多看一節，放在跟人有關的那節最順）。
  2. **團隊成員就是第五節「本人」那幾列**：現在第五節本來就分公司／本人（D-120），多人時「本人」改顯示「成員」，名單就是這幾列；`kb who set` 自動加一列（來源「確認」）。不另做一份名單。
  3. **名字預設**：先拿 `git config user.name`，沒有 git 或沒設就拿 Windows 登入的使用者名稱；問的時候帶這個當預設。
  4. **口述出處寫人名**：多人時 `kb statement add` 的那行帶 `who`，出處顯示「小王 11/01 說的」；升級前寫的沒有名字，**只寫日期、不寫「你」也不猜是誰**，免得把舊的全部算到某一個人頭上。
  5. **舊版停寫怎麼講版本**：讀到 `app` 比自己新的行，句子講那個版本號（「同事已經用 0.33 記過東西了」）。
