## 做法（不加新子指令、不加狀態檔，改兩個現有的）

1. **A：`office copy` 自己補記清冊**：清冊沒有、在登記的來源裡、檔在 → 掃那一個來源補記（`inventory_cli.scan_and_apply`，同 `kb inventory scan --source`），再照原本的判斷給副本。（已做）
2. **B：`office copy --unpack`**：給副本、解開，印「副本：…」「解開到：…」；夾旁寫 `<夾名>.json`（副本、原檔編號、原檔名）——`output save` 靠它知道原檔是哪份、照哪份打包，不另開狀態檔。（已做）
3. **C：`output save <解開的夾>`**：
   1. 打包（照副本 `--like`）、驗：改過的 XML 能解析；xlsx 有公式就重算、錯誤 0；xlsm 不自動重算。（已做）
   2. 原檔那個夾裡找「<主檔名>（版本一…N）.<副檔名>」，把現在的原檔複製成下一號（中文數字）。
   3. 先寫同夾暫存檔再整份換上原檔；被鎖（開著）→「檔案正開著，改視窗裡那份」，exit 3，這次的版本檔與暫存檔拿掉、原檔不動，AI 改走 #24。
   4. 成功句：「已改好 <位置>，改之前那份存成「<主檔名>（版本 N）」（說「退回」可以換回來）」，下一行「驗過：…」，再一行「回答最後問她一句要不要刪掉之前的版本」。
4. **版本檔就是備份，退回怎麼走**（照現有退回程式；`versions.py` 只加 sha256 比對）：
   - 版本檔記進回合當「這一句新建的檔」（manifest `create`）。
   - 原檔記進回合當「這一句改的檔」（manifest `modify`），它的回合備份**不另外複製，硬連結到那個版本檔**（`turn.backup`／`backup_source` 加一個參數 `link_from`）：同一份位元組，`.system/versions` 不多佔空間。
   - 「退回」這一句：現有程式從回合備份換回原檔（＝版本 N 的內容），再把這一句新建的版本 N 拿掉。結果：原檔回到改之前，夾裡少掉這次那一號。
   - 硬連結做不到（原檔在別的磁碟、隨身碟、網路磁碟）或原檔／版本檔有雲端屬性（OneDrive 這類同步夾：重解析點、占位、釘選，OneDrive 可能把它換成只在雲端）才複製一份——這時才有兩份，換的是「退回一定換得回」。
   - 連上時 manifest 那行記 sha256；退回前比對，版本檔被原地改過（備份跟著變）就不拿它蓋原檔、那份版本檔也不拿掉，印「沒換回 N 檔：改之前那份（版本檔）之後被直接改過…」（主管疑慮一，`versions.py` 加兩個小判斷，退回流程不變）。
   - 回合 30 天／200 句清掉後退不回那一句，但版本檔還在夾裡（她自己刪的除外）。
   - 原檔在知識庫裡（暫存區）時，現有退回對「這一句新建的檔」照成品規則先留著（D-074），所以退回後版本 N 還在、原檔換回；照舊說「要刪再跟我說」。在登記的來源裡（多數客戶原檔）新建的照退回拿掉。
5. **版本檔不做卡**：記進清冊時標現有的 `skip_kind`（D-113，設定檔說不整理的那一欄），整理不做卡。
6. **刪之前的版本**：她說好才用現有 `kb source-edit trash <那幾份>`（丟資源回收筒、有紀錄、說退回會回來）。
7. **D、E：說明**（`skills/produce/SKILL.md`、`references/make.md`，3000 字內）：
   - SKILL 第 47 行：關著三步（指令＋參數照寫）、「看內容 Grep／Read 解開的夾，不用 python」、「開著的照知識庫 CLAUDE.md 改視窗裡那份、不備份」、「改完問一句要不要刪之前的版本」；拿掉「載入文件技能」。
   - make.md「改她原本的檔」：關著／開著兩條路；拿掉作者「AI 助理」、修訂範例、「（AI 修改）」檔名；Excel 改成「save 會自己重算」。範本、舊檔照寫新的不變。
8. **G 不做**：`turn note` 是第二題（willy優化）。

### 每條新規則：拿掉會不會少保護

| 規則 | 拿掉會怎樣 | 留不留 |
|---|---|---|
| copy 自己補記清冊 | 不少保護，只是多一次失敗、多叫一次 scan；這題就是要少叫 | 留（這題的目的） |
| 夾旁的 `<夾名>.json` | save 不知道原檔與副本，要 AI 自己給 `--like`、`--to`（現在漏過） | 留 |
| XML 能解析 | 壞的 XML 蓋回原檔，Office 打不開 | 留 |
| Excel 重算、錯誤 0 | 錯的數字進原檔（jacky 定） | 留 |
| xlsm 不自動重算 | 重算程式存檔可能弄掉巨集 | 留 |
| 先寫暫存檔再換上 | 寫到一半失敗留半份壞檔 | 留 |
| 版本檔＋硬連結當回合備份 | 退回換不回 | 留 |
| 版本檔標不整理 | 不少保護，但每個版本都做一張卡、`lookup` 會找到舊版 | 留（用現有欄位，不加東西） |
| 「改完問要不要刪」那行 | jacky 要的 | 留 |
| ~~copy 時先判斷開著沒~~ | save 換上時一樣會擋、原檔不動；只是 AI 白改一次 | **拿掉**（開著時多半她已說開著，AI 本來就走 #24） |
| ~~密碼保護另給一句~~ | 現有「這不是 Office 檔（解不開）」一樣擋、原檔不動 | **拿掉**（第 2 版做了，退掉） |
| ~~「沒改到任何東西」~~ | 多一個跟原檔一樣的版本檔，她可以刪 | **拿掉**（第 2 版做了，退掉） |
| ~~成功句列「改了 N 個部件」~~ | AI 回答本來就講改了什麼 | **拿掉**，只留重算結果 |

## 風險（jacky 問 Office 更新會不會讓這套出錯）

| 情況 | 會怎樣 | 測試 |
|---|---|---|
| 密碼保護的檔（加密後是 OLE 不是 zip） | `copy --unpack` 照現有的「這不是 Office 檔（解不開）」擋，原檔不動 | 有 |
| 巨集檔 .docm／.xlsm／.pptm | `--like` 打包，`vbaProject.bin` 沒改就逐位元留著、副檔名不變，巨集還在；xlsm 有公式不自動重算（重算程式存檔可能弄掉巨集），照放並說公式要打開才更新 | 有（docm） |
| 檔案開著 | `output save` 換上時被擋：「檔案正開著，改視窗裡那份」，原檔不動、不留版本檔與暫存檔；AI 換成 #24 的附著改 | 有（真的開著測不了，用 mock 鎖） |
| 硬連結 | 版本檔與回合備份是同一份位元組：Office 存檔是整份換掉（連結斷開），回合備份照舊是舊的；有程式「原地改」版本檔才會一起變——退回前比 sha256，明講沒換回、原檔與版本檔照留 | 有（同一份、Office 式存檔、原地改） |
| Word 的「復原」（Ctrl+Z） | 只管她在 Word 裡的編輯；關著時 AI 改的 Word 退不回，要退說「退回」或開版本檔 | — |
| 開著改（#24）的退回 | 不備份，只能靠 Office 的復原／版本記錄；關掉 Word 後復原就沒了（OneDrive 上的檔有雲端版本記錄） | — |
| OneDrive 只在雲端（沒下載） | `copy` 照舊擋，不會觸發整份下載 | 已有 |
| OneDrive 同步中 | 有雲端屬性就不連、複製一份備份；換上是一次 `os.replace`，同步程式看到整份新檔；版本檔也會被同步上去；同步衝突時 OneDrive 自己另存「-電腦名」，下次掃描看到多一份 | 有（屬性用 mock；真的 OneDrive 沒測：寫進去會同步到雲端） |
| Office 更新改了檔內格式 | 我們只解開、打包、比位元組、檢查 XML 能解析，不解讀內容，跟 Office 版本無關 | — |
| 打包出來的檔 Office 打不開 | XML 能解析不等於 Office 認得；這層驗不到，說「退回」或開版本檔 | — |
| 版本檔越來越多 | 每次改完問一句要不要刪；她不刪就一直留著 | — |
