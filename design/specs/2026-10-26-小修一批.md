~~~~markdown
# 整理成卡

程式算哪些檔要做卡、切成批次、排好要問客戶的事；製卡交給背景的製卡助手（子代理 card-maker），你管派工、問客戶、回答。

用 Bash 工具這樣叫：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" <子命令> …
```

`${CLAUDE_PLUGIN_ROOT}` 代換不了（找不到 kb.py，或路徑開頭變成 `/scripts`）時，用開場段「kb 指令」那行的前綴；程式輸出裡 `kb ` 開頭的指令也換成這個前綴。

## 分辨

- 開場有「有變動：…」那行，或客戶說「我加了」「我改了」「我刪了」「搬了」「有新東西嗎」「整理」→ 照骨架做。
- 開場有「設定檔有改」、客戶說「設定檔改好了」「套用」→ 照 commands.md 的 profile 節。
- 「把 D 槽加進來」「不要讀…」「那個資料夾不要了」，或**來源根**（登記的那個資料夾本身）搬了、改名 → 走 manage；manage 加完問要不要整理，客戶說要才回到這裡。來源**裡面**的檔或子夾搬了、改名 → 這裡。
- 拖檔、貼圖說存、貼一段說「存起來」→ 骨架的「收件」；貼的文字沒說存是口述（note），像整份文件才問存不存（D-049）。
- 說「我改了報價單」但 `changes` 查無變動 → 跑 `cards todo --json`，`plan` 有 `dispatch` 或 `cards` 就照骨架做（之前可能沒做完）；沒有就問「是不是還沒存檔？」；說的是口頭的事（付款條件談好了、會改期）照 note 做。
- 問卡裡的內容（「上次那份報價在哪」）不是整理，直接讀卡回答。
- 「先整理報價那夾就好」→ `cards dispatch --source <那個來源的別名>`；「整理到哪了」→ `cards status`；「先停」「今天先到這裡」→ 骨架的「客戶說停」。
- 「剛剛那批整理得不對」「全部退回」「退到整理之前」→ 照 `references/redo.md`，不用 `versions revert` 一句一句往前退。

## 原則

- **開場有變動先派整理，做完再完整回答。** 先整理的答案包含剛進來的新檔（D-156、B-058）；整理在背景跑，客戶不用乾等，做完再補上完整的答案（D-196）。
- **製卡交給製卡助手，自己不讀原檔。** 原檔內容進主對話會讓對話被摺疊、做不完也多花額度；交給背景的子代理，客戶照常能問（D-022、D-196）。只有 `plan` 的 `cards` 那步（線上文件、密碼檔，子代理做不了）自己做。
- **派工照程式給的 prompt，不自己拆批。** 批次、認領、算在哪一句由程式記，自己拆會重做、漏做、退不回來（D-197）。
- **子代理的回報不轉述檔案內容。** 檔案內容只該進卡，轉述就把原檔內容帶回主對話、也可能講出不該講的；客戶問內容就讀卡回答（D-022）。
- **照程式給的做。** 要做的事在 `plan`、要問的事在 `asks`，指令與參數都是程式寫好的；自己拼容易打錯，也會漏掉程式的保護（D-104、D-132）。
- **守門或程式拒絕，照它的理由句做。** 拒絕本身就是保護，繞過去等於替客戶決定；要改的綜合卡比平常多，程式會給問句與指令，客戶說好才照跑（D-073、D-075）。
- **刪除只認明確確認。** 原檔不見常只是搬走或還沒存檔，順口一句「好」不該變成刪卡；標 `strict` 的結果只認編號或明確說出那個結果，「好」「嗯」「可以」都不算，再問一次（I-082、D-134）。
- **一次最多 3 個問題。** 問太多客戶答不完；這句話需要的先問（「是哪一份報價」），剩下的名額照 `asks` 的順序從前面取，沒問到的下一句程式還會列；你自己的問題照平常問、不編號（D-135）。她說「這個先不要」就 `kb asks set-aside <那題的 key>`，先放著的程式不再列（D-226）。
- **被打回照理由句改一次，還被打回就停。** 檔頭是機器檢查的，換方法只會越改越偏；停下來告訴客戶這份沒做好與原因（D-104）。
- **卡只寫原檔有的，數字以原檔為準。** 卡是索引不是副本，抄錯的數字比沒有更糟（D-032）。

## 骨架

開場有變動時先派整理再回答（D-156、D-196）。下面是做事的順序，不是要跟客戶講的話：過場不唸段名、不說英文，對客戶只說程式給的句子（`announce`、`say`）與最後的回答。

- **收件**：照 `references/intake.md` 跑 `intake`，照輸出說一聲；拿不到照它那句講，不重打（D-243）；有「接著整理」就跳到「拿計畫」，她說了放哪就整理完照 `source-edit move` 搬（D-244）。
- **看變動**：跑 `changes`；最後一行寫「要套用請跑 kb inventory scan」才跑 `inventory scan`。從 manage 交棒，或客戶明說「整理」但沒變動時，直接往下。
- **拿計畫**：`cards todo --json`，看 `plan` 與 `announce`；`announce` 有句子先照貼。`asks`、`tell` 留到「回答」才用（背景做完會變）。
- **照計畫做**：照 `plan` 一步一步做，有 `read` 的先讀（相對於本 skill 資料夾），再照 `do` 做。
  - `names`：照 carding.md 第十一節判斷每個新名字，有把握的跑 `entity accept`，有疑慮的不動（`asks` 會問）（D-202）。
  - `dispatch`：跑 `cards dispatch --json`，照「讀派工結果」做；先用現有資料回答這句、末尾說還在整理。
  - `cards`（線上文件、密碼檔）：照 carding.md 自己寫卡；打回後還是不行、或讀不到又沒記進待處理，只停那一份、告訴客戶。
- **讀派工結果**（`cards dispatch --json`）：`batches` 每一批用 Agent 工具派（`subagent_type` 照 `agent`、`description` 與 `prompt` 原樣、背景跑）；`say` 有句子照講一次，收到通知之後對客戶只說 `say`、不另外加話。`done` 是做完了，到「回答」；`batches` 空、沒有 `approval`、`done`、`stopped` 才是還在跑，等通知；每收到一個製卡助手做完或停了的通知，再跑一次 `cards dispatch --json`（範圍程式記著，不用再加 `--source`）。`failed` 是製卡助手回報沒做成的，程式不會再派它們，你也不要再派，原因留到「回答」講。`approval`、`stopped`、`done` 與回報裡字典外那行，照 `references/commands.md` 的 cards dispatch 一節做。這期間客戶問別的照常回答、末尾一句還在整理；問進度跑 `cards status` 照講。
- **客戶說停**（「先停」「今天先到這裡」）：跑 `cards stop --json`，`agents` 每個用 TaskStop 停掉，再跑 `cards status` 照它那句講（停下前在寫的卡會寫完）；這個對話之後不自動整理。客戶說「整理」「繼續整理」就直接跑 `cards dispatch --json`（`plan` 最前面的 `resume` 就是這步，D-200）。
- **回答**：`plan` 做完（有 `dispatch` 就等到 `done`），重跑 `cards todo --json`，完整回答派工那一句客戶問的，答案在前；問資料的照 answer 的做法答（粗估、核對、`kb tally`、短標）。一句講做了什麼（檔名最多列 5 個，多的講份數），`failed` 裡 `tell` 沒帶到的照原因講；`tell` 的句子原樣貼；`asks` 從前面照順序取（名額是 3 減去你自己問的題數），問 `question`，結果的 `label` 列成選項，回答裡說的回覆方式要跟畫面上的一致；`n` 不給客戶看。
- **客戶回了**：
  - 回覆要對到你上一句列出的唯一一個結果才照做，對不到或有兩個可能就問清楚，這句不做；對之前不要重跑 `cards todo --json`，結果會變。對到了照它的 `do` 依序執行，`fill` 的空格填客戶說的：帶 `rule` 的照 `rule` 寫成一句白話，其他有空白或特殊字元加雙引號；客戶沒給就先問。
  - 有 `note` 照做；`do` 空又沒有 `note`，不跑指令，白話複述這個結果、請客戶自己處理。
  - 帶 `then`（份數多時客戶說「現在做」）就照 `then` 從「照計畫做」做；份數仍多而 `plan` 只剩搬卡、或同一題又出現，不用再問。
  - 清單沒有的事照實說這版做不到，不自己發明做法。
  - 其餘結果執行完回「拿計畫」，確認名字這類結果會帶出新的事。
- **收尾記做了**（D-084），一句白話、不含 `" $ ` \` 這四種字元：`dispatch` 給了 `note_cmd` 就把 `{做了什麼}` 換成這句照跑，這一句沒另外改知識庫就不再跑 `turn note`；其他時候改了知識庫，送出最終回答前最後跑 `turn note "<白話一句>"`（再跑會蓋掉前一次）。
~~~~
