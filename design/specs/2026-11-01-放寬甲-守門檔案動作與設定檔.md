## 給 spec 乙的介面摘要

乙改 skill、核心規則時照這裡的名字與句子，不另外發明。

**一、守門擋下時的句子（寫給 AI，`kb guard` 與 ledger 的 reason 欄）**：每句都以「不用跟使用者提這一步。」結尾（常數 `AI_TAIL`）。AI 照「改用」那段換做法接著做完。

| 代號 | 什麼時候 | 句子（`{}` 代入） |
|---|---|---|
| `delete` | 指令要刪檔或刪有東西的夾 | `這會刪掉「{name}」，刪了救不回來：改用 kb source-edit trash <路徑>（可以一次給多個、整個夾也收），會先進資源回收筒。` |
| `overwrite` | 搬或複製到已有同名檔的地方 | `「{dest}」已經有同名的「{name}」，這樣會蓋掉它：改用 kb source-edit move <來源> --to <夾>，同名時它會告訴你內容一不一樣，再選 --replace 或 --name。` |
| `content` | 用指令改既有檔的內容（`>`、`>>`、Set-Content、Out-File、Add-Content、tee、sed -i、perl -i、truncate、dd of=） | `這會直接改「{name}」的內容、改之前留不了一份：文字檔用 Edit 或 Write 改（會先留一份），Word、Excel 這類用 kb office。` |
| `batch` | 看不出目標的批次搬、複製（迴圈、變數、萬用字元） | `批次搬檔看不出會不會蓋掉同名檔：mv、cp 加 -n，Move-Item 不加 -Force，Copy-Item 先用 Test-Path 跳過已有的；或用 kb source-edit move 一次給多個檔。` |
| `code` | 直譯器程式碼（`-c`、heredoc、執行的腳本檔內容）有刪檔或覆蓋寫法 | `這段程式會刪檔或覆蓋檔，來不及先留一份：刪檔用 kb source-edit trash，寫或改檔用 Edit／Write，搬檔改名（os.rename、shutil.move）可以照跑。` |
| `willy` | 寫 willy 自己的檔（綜合卡、檔案索引用指令寫；系統、`.system`、`.claude`、`.obsidian`、知識庫 CLAUDE.md、總目錄） | `「{name}」是 willy 自己的檔：{hint}。`；hint 照區：綜合卡、檔案卡「用 Edit 或 Write 改」；客戶設定檔「用 Edit 改，改完跑 kb profile apply」；其他系統檔與總目錄「是程式產生的，從源頭的 kb 指令改」；`.system` 等「用對應的 kb 指令改」 |
| `excluded`（改句） | 使用者設成不讀的夾 | `「{alias}」使用者說過不讀，不讀也不寫；使用者要重新納入時跑 kb folders include <路徑>。` |
| `excluded_inside`（改句） | 範圍底下有不讀的夾 | `這個範圍底下有使用者說過不讀的夾，縮到不含它的子資料夾再做。` |
| `error`（改句） | 守門出錯 | `守門出錯，這次沒放行，已記在 hook-errors.log：改跑 kb selftest 看原因，修不好照核心規則請服務人員。` |

`credential`、`run_file`、`vault_move`、`secret_action`（要按允許）照舊，只把「跟我說」「請客戶」這類對使用者的口吻改成對 AI（句子照上表的格式，實作照改、在回報列出新句）。

**二、kb 指令（新的與改的）**

| 指令 | 改了什麼 |
|---|---|
| `kb source-edit move <目標>… --to <夾> [--contents] [--name <新名>] [--replace] [--check] [--json]` | 目標可以多個；`--to` 收任何使用者的夾（見「要做的事」二）；`--contents` 只搬夾裡的東西；`--name` 搬過去順便改名（只收一個目標）；同名不再直接拒絕，回 `conflict`（見資料格式） |
| `kb source-edit trash <目標>… [--permanent] [--check] [--json]` | 目標可以多個，收檔也收夾；空夾直接拿掉；唯讀的先取消唯讀再丟；進不了回收筒先留進回合備份再刪；`--permanent` 只在連備份都放不下、使用者說確定時用（待你決定 1） |
| `kb intake <路徑>… [--to <夾>] [--replace] [--title <名>]` | `--to` 直接收進使用者的夾；同名回 `conflict`，不再加 (2) |
| `kb output save <檔> --to <夾>/<檔名> [--replace]` | `--to` 收任何使用者的夾，不限 AI 產出；同名回 `conflict` |
| `kb cards skip <id> [--kind <種類>]` | `--kind` 可以省略（記成 AI 看過、不用卡）；種類不在設定檔就自己加進第三節 |
| `kb profile apply` | 不再因型別底下有實體拒絕：回 `pending_types`；解析錯誤寫給 AI |
| `kb profile add …` | 設定檔有手改還沒套用時先套用再加，回 `applied_first: true`；`型別` 多一欄 `夾名=` |
| `kb profile type remove <型別>` | 只看實體，不看夾裡有沒有別的檔 |
| `kb entity merge <來源> --into <目標>` | 型別不同自動換成目標的；舊夾的檔搬進目標的夾、同名的回 `conflict`、空了拿掉（待你決定 2） |
| `kb config show [--json]`、`kb config set <鍵> <值>`、`kb config reset <鍵>` | 新：使用者說一句就改的門檻與頻率 |
| `kb folders exclude <路徑> --kind …` | 路徑可以在知識庫裡（使用者的夾） |
| `kb folders locate <別名> [--json]` | 新：找搬走的來源夾，回候選 |

所有收路徑的參數多收「`%` 編碼的清冊 uri」（`file://<別名>/<相對路徑>`，`"`→`%22`、`$`→`%24`、反引號→`%60`、`\`→`%5C`、`%`→`%25`）：名字有這些字元時，kb 給的指令一律用這種寫法，不再叫使用者去改名。

## 目的

使用者叫 AI 搬檔、刪空夾、存逐字稿、拆型別、標不整理時，kb 與守門現在擋下來、叫使用者自己去檔案總管或手改設定檔（審查報告 `design/reports/放寬限制-審查.md`）。這份把**程式**放行：AI 動使用者的檔一律做得完，救不回的先留一份；willy 自己的區照舊只經 kb。說明文字（skill、核心規則）由 spec 乙照這份的介面改；事後對上與改回由 spec 丙做。

使用者時刻：「把收件匣那個空夾刪掉」「把講師那個夾搬進殷曉琪」「逐字稿存到王宅」「人脈拆成增員和 BNI」「這種不用整理」，各一句話做完，使用者沒聽到「被擋」「設定檔第幾節」。

## 決策

D-305、D-306、D-307、D-309、D-312(3)、D-317、D-319(1)、D-322 第 2、8、10、12、22、23、24、25 件；第二輪 D-324、D-325。**全部待 jacky 在 issue #29 留言同意（process 第八節第 3 條），同意前不派實作。** 碰守門、hooks，不走輕流程，要另開測試 session。

設計自定（不是使用者決定的，實作照做；有更好的寫法回報）：
- 守門判「救不回」用的是指令的動詞與目的地現況（目的地已有同名檔、目標是有東西的夾），不追蹤執行時才發生的事；判不出目標的批次搬只認得「不覆蓋」的寫法（`-n`、Move-Item 不加 `-Force`），其餘叫 AI 加上（`batch` 句）。這是 D-306「看不出來的放行」的收窄：看不出目標**又可能蓋掉**的才擋，因為加 `-n` 對使用者沒有任何差別。
- 直譯器程式碼：有刪檔或覆蓋寫法，**而且**可能碰到知識庫或來源（效用 cwd 在知識庫或來源裡、或程式碼裡有指到知識庫或來源的路徑、或有相對路徑）才擋；全在外面（例：寫到 scratchpad 的絕對路徑）放行。腳本檔讀不到或超過 `guard_script_max_bytes` 照 D-306(4) 放行、ledger 記一行 `script_unread`。
- 守門放行的使用者區指令寫入，記進這個回合的 `shell_writes.jsonl`（給 D-306(5) 的工作日誌與丙的改回用），本份只記不用。
- `_extras`（Z12，丙改名 `_個人`）的指令寫照使用者區規則，跟其他使用者的夾一致。**這修訂了 jacky 定的 D-510「指令寫擋」**，不算設計自定，列進給 jacky 的清單、跟其他條一起等他同意。
- 搬到沒登記的地方（桌面）：清冊那份的位置記成知識庫外的可攜 spec（`~/Desktop/…`），狀態 `outside`；不掃描、卡留著，開原檔連結照指過去。
- 拿掉型別後，型別夾裡剩下不是實體的檔：夾名照舊留著，當成使用者的夾。
- 跨磁碟搬：複製 → 比內容指紋 → 原檔進資源回收筒；回收筒進不了先留進回合備份再刪（待你決定 1）。
- 第二輪：守門的 Z3 併進 Z4（暫存區），Z3 不再出現；升級前的回合備份不改寫路徑，升級前那些回合要退照 D-215 的升級前快照；升級時同名內容不同的檔程式不判斷、留在 `AI 產出/` 交給 AI（D-324 說同名照 D-309 由 AI 判斷）。

## 資料與介面格式

**`conflict`**（source-edit move、intake、output save 共用；exit 3、`--json`）：
```json
{"refused": "<句子>", "conflict": [{"name": "順稿.docx", "dest": "01 案子/王宅", "same_content": false,
  "existing": "file://知識庫/01 案子/王宅/順稿.docx"}]}
```
多目標時放在 `results[i]`：`{"target": "<uri>", "ok": true, "to": "<uri>"}` 或 `{"target": …, "ok": false, "refused": …, "conflict": […]}`。

**`shell_writes.jsonl`**（`versions/<回合>/`，一行一次放行）：`{"time": "YYYY-MM-DDTHH:MM:SS", "tool": "Bash", "head": "<指令前 200 字，遮值後>", "targets": ["<正規化路徑>", …], "rule": "U1|U5|U6"}`。`targets` 推不出時空清單。

**manifest 的 Z9 備份行**：`{"path": "_src/<別名>/<相對路徑>", "uri": "file://<別名>/<相對路徑>", "action": "modify|create", "time": …}`。

**ledger**：新 reason_code `delete`、`overwrite`、`content`、`batch`、`code`、`willy`、`script_unread`（只記不擋，decision 欄 `pass`）。

**`profile apply --json`** 多 `pending_types`: `[{"type": "人脈", "entities": ["殷曉琪", …]}]`；`profile add --json` 多 `applied_first`（bool）；`profile.json` 型別列多 `pending_remove`（bool，預設沒有這欄）。

**清冊**：`skip_kind` 多一個值 `"AI 判斷"`；位置在知識庫外沒登記的地方時 `status: "outside"`、`uri` 記可攜 spec（`file://~/Desktop/…`）。

**config 新鍵**：`guard_script_max_bytes`（1048576）、`relocate_search_depth`（4）、`relocate_search_seconds`（20）、`trash_backup_margin_mb`（500，進不了回收筒先留一份時要多留的空間，待你決定 1），各帶 `_why_`。

**`kb config show --json`**：`{"keys": [{"key": "ingest_auto_max", "value": 20, "default": 20, "why": "…"}]}`。

**intake 結果**（第二輪）：多 `restored_place`（bool）；升級遷移結果多 `left_in_output`（`[{"name": …, "existing": "file://暫存區/…"}]`）；清冊條目選填 `duplicate_of`（清冊編號）。

**`kb folders locate --json`**：`{"alias": "…", "candidates": [{"path": "…", "hit": 18, "sampled": 20}], "searched_seconds": 7.2}`。
