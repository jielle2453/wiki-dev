# 開檔與「開著的 Office 一起改」不要擋
日期：2026-10-30
狀態：定稿
版本：（發行後填）
來自：issue #24；併入 issue #18（同一個根因，做完一起關）
區域：守門與密碼

## 目的

做完文件要打開給客戶看、建置完要另開一個視窗測試，現在都被守門當成「寫」擋下來；客戶把 Word 開著跟 AI 邊看邊改，往後改守門也不能把它收緊。

使用者時刻：
- 她說「報價單做好打開給我看」→ AI 跑 `Start-Process "<知識庫>\AI 產出\報價\王宅.docx"`，Word 跳出來。現在：deny `output_shell`。
- 服務人員建置完，AI 跑 `Start-Process powershell -ArgumentList '-NoExit','-Command','claude --name 問答測試'` 開新視窗。現在：deny `unparsed`（#18 回報時是 Z8，0.28.0 實測變成 unparsed，根因相同）。
- 她開著 `王宅.docx` 說「第三段改成下週交」→ AI 附著到她的 Word 改，畫面當場變。現在：pass，要維持。

**前提（spec 定稿前要拿到）**：D-514 放寬守門，照 process 第八節第 3 條要 jielle2453 在 issue #24 留言同意。

## 決策

D-514、D-515（2026-10-30）。

| 決策 | 選了 |
|---|---|
| D-514 | 開檔動詞開的是資料夾、網址或白名單內的文件 → 目標照讀判，不算碰 AI 產出；導向輸出的目標照寫判；開的不是文件 → 當跑程式，程式名加參數接成一行照直接下那行判；那個程式檔在知識庫或來源裡 → 擋 `run_file` |
| D-515 | COM 附著到開著的 Office 改：守門不表態、不問、不備份；語料鎖住 |

根因（2026-10-30 在 0.28.0 用 `kb guard decide` 實測，知識庫 C003）：
- `cmdparse.WRITE_WORDS` 收了 `start-process`，`SHELL_WRAPPERS` 收了 `start-process`、`saps`、`start` → 這一段被判成寫，又找不到寫入目標 → `unparsed`；有路徑時路徑套寫入欄（第一層 Z8 `protected`、系統 Z6 `system_render`、原檔 Z9 `readonly_source`）。
- `guard._touches_output` 的第 (2) 條：不是只讀動詞的那一段，參數在 AI 產出就擋 → `Invoke-Item`、`ii`、`explorer`、`cmd /c start` 開 AI 產出都 `output_shell`。

| `Start-Process '<V>\AI 產出\x.docx'` | deny Z3 output_shell | 不 deny |

| Bash `cmd //c start "" "<V>/AI 產出/x.docx"`、`start "<V>/AI 產出/x.docx"` | deny Z3 output_shell | 不 deny |
| `explorer '<V>\AI 產出'` | deny Z3 output_shell | 不 deny |
| `Start-Process '<V>\總目錄.md'` | deny Z8 protected | 不 deny |
| `Start-Process '<V>\系統\x.md'` | deny Z6 system_render | 不 deny |

## 要做的事

1. **開檔段** `scripts/kb/_lib/cmdparse.py`：
   - 新常數 `OPEN_VERBS = {"start-process", "saps", "invoke-item", "ii", "start", "explorer", "open", "xdg-open"}`（比對照 `_base`，`explorer.exe` 也算）。`cmd`／`cmd.exe` 後面接 `/c`（Git Bash 是 `//c`）、`/c` 後第一個字是 `start` 的，整段當 `start …` 看。
   - 新常數 `OPEN_DOC_EXT`（文件白名單，不分大小寫比）：`.pdf .doc .docx .xls .xlsx .csv .ppt .pptx .odt .ods .odp .rtf .txt .md .log .json .xml .html .htm .png .jpg .jpeg .gif .bmp .tif .tiff .webp .heic .svg .mp3 .wav .m4a .mp4 .mov .avi .zip .msg .eml .dwg .dxf .stp .step`。巨集檔（`.docm .xlsm .pptm .dotm .xltm`）刻意不收。
   - 新函式 `open_stage(verb, words, powershell)`：不是開檔動詞回 None；是的話回 dict：
     - `targets`：要開的東西。`Start-Process`／`saps`：`-FilePath` 或第一個位置參數；`Invoke-Item`／`ii`：`-Path`／`-LiteralPath` 或位置參數（逗號分開的每一個）；`start`：跳過 `/b /wait /min /max /i` 這類開關與 `/d <夾>`，**第一個帶引號的字當視窗標題跳過**（cmd 的行為）；`explorer`：位置參數，`/select,<路徑>` 取逗號後；`open`／`xdg-open`：位置參數。
     - `kind`：每個目標都是資料夾（磁碟上存在且是夾）、網址（`http:`、`https:`、`mailto:`）或副檔名在 `OPEN_DOC_EXT` → `"open"`；否則 `"run"`。
     - `program`：`kind` 是 `"run"` 時，程式名加 `-ArgumentList` 的值接成的一行（陣列的每個元素用空白接、含空白的元素加雙引號，跟 Start-Process 一樣）；`Invoke-Item`、`start`、`explorer` 是目標本身加其餘參數。
     - `verb_flag`：`-Verb` 的值；不是 `open`、`edit`、`print`、`openasreadonly`（不分大小寫）的 → `kind` 改 `"run"`。
     - `writes`：`-RedirectStandardOutput`、`-RedirectStandardError` 的值；`reads`：`-RedirectStandardInput` 的值。
     - `cwd`：`-WorkingDirectory`（`start` 是 `/d`）的值，沒有是 None。
     - `opaque`：`targets`、`-ArgumentList`、`-FilePath` 有展不開的變數（`$x`、`%X%`）或指令替換 → True。
   - `stage_kind`：`open_stage` 回的 `kind` 是 `"open"` 而且沒有 `writes` → 回 `"read"`；有 `writes` → `"write"`，寫入目標只有 `writes`（不是整段的參數）。`kind` 是 `"run"` → 交給 guard 遞迴（下一條）。
   - `WRITE_WORDS` 拿掉 `start-process`；`SHELL_WRAPPERS` 拿掉 `start-process`、`saps`、`start`（改由開檔段處理）。`WRAPPER` 與 `inner_verb` 裡 `(".", "start", "exec")` 的例外照新清單調，除此之外行為不變。
2. **守門** `scripts/kb/guard.py`：
   - `_analyze`：開檔段的 `targets`（kind open）加進讀取路徑（`read_paths`），**不**加 `read_dirs`（開一個夾不是讀整夾，不走第三道；跟 `cd_targets` 同理）；`writes` 加 `write_targets`；`reads` 照讀；`opaque` → `unparsed`（照舊擋）。
   - `_touches_output`：開檔段（kind open）跳過第 (2) 條（跟 `READONLY_VERBS` 同一個 `continue`）；`writes` 落在 Z3 照第 (1) 條擋。
   - `_shell_tool`：開檔段 kind run → 把 `program` 當內層指令，cwd 用 `cwd` 或這段的效用 cwd，照 `_inner_commands` 那套遞迴（`depth + 1`，超過 `SUBST_DEPTH_MAX` 照 unparsed）；內層 deny 就 deny。遞迴之前先看：程式檔（`program` 的第一個字）解出的路徑在 `VAULT_ZONES` 或 `SOURCE_ZONES`（檔存不存在都算）→ deny，新常數 `RUN_FILE = ("deny", "run_file", "知識庫與原檔夾裡的程式或巨集檔不直接執行；要打開給客戶看，請用 PDF、Word 這類文件")`，zone 用那個路徑的區。
   - 開檔段 kind open 的目標照讀那欄判：Z10 排除夾 deny `excluded`、Z10b deny `excluded_inside`、憑證第一、二道照做（密碼檔名照擋，有「可以讀」裁示照放）。
   - 檔頭 docstring 補一段「開檔（D-514）」，三四行。

## 確認情境

1. 自動：AI 產出有一份 Word。「報價單打開給我看」→ AI 用 `Start-Process`（或 `Invoke-Item`）開，`.system/ledger.tsv` 沒有這句的 deny。`-p` 看不到 Word 視窗，判準只看 ledger 與回答沒說被擋。
2. 自動：「開一個新視窗讓我測問答」（服務人員的話）→ AI 跑 `Start-Process powershell …`，ledger 沒有 deny。
3. 人眼：Word 開著 AI 產出那份，說「第二段最後加一句『下週三前回覆』」→ AI 附著改、Word 畫面當場出現，沒有 willy 的詢問（Claude Code 自己對 PowerShell 的允許詢問不算），回答沒說備份；她按 Ctrl+Z 退得掉。
4. 人眼：同 3，改的是開著的原檔（登記來源裡的 Excel）→ 同樣直接改，AI 不改走 `kb office copy`。

## 不做

- `Start-Process winword <檔>`、`notepad <檔>` 這種指定程式開文件：照跑程式判（內層 `winword <檔>` 碰 AI 產出照擋）。AI 用 `Start-Process <檔>` 就好。
- 包在殼裡的開檔：`powershell -Command "Start-Process '<V>\AI 產出\x.docx'"` 照現在的殼規則（碰 AI 產出擋）。
- `-ArgumentList` 用變數（`$cmd = "…"; Start-Process … $cmd`）：照 unparsed 擋，AI 把字寫在指令裡。
- `Remove-Item Env:X` 被當成 unparsed（PowerShell 的 Env:、HKCU: 這類不是檔案的磁碟）：另一個問題，結案時記 backlog。
- 直接執行知識庫裡的腳本（`& '<V>\x.ps1'`、`bash x.sh`）：B-423 那一族，不在這題。
- 附著改的內容退回：交給 Office（D-515），`versions revert` 不管。
- 附著改原檔後清冊與卡：照現在的變動偵測（下次開場報「修改」、整理時重做卡），這題不另做。
