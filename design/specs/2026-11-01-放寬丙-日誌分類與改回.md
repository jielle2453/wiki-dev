## 查證

### B-527：比對的成本（2026-11-01，main `5ea83e0`）

假來源用腳本產生（四種檔輪流：200 段的 docx、400 行的 txt、200 KB～2 MB 的 jpg、100～800 KB 的 pdf），`kb init` 建知識庫、`kb folders add` 登記，直接呼叫 `inventory.scan` 量時間（腳本在設計 session 的 scratchpad，不進 repo；來源夾放在 `<測試環境>\b527-scan`，量完刪掉）。檔剛寫完，作業系統的快取是熱的；冷快取（重開機後第一次）沒辦法可靠模擬，大檔會比下表慢，SSD 估 2～3 倍。

| 份數 | 大小 | 情況 | 全比 | 快速（開場那條） |
|---|---|---|---|---|
| 500 | 180 MB | 第一次登記入冊（含算全部指紋） | 0.5 秒 | — |
| 500 | 180 MB | 沒變動 | 0.03 秒 | 0.03 秒 |
| 500 | 180 MB | 搬一夾（13 份）＋ 20 份 | 0.04 秒，搬動 26 | 0.04 秒 |
| 3000 | 1.1 GB | 第一次登記入冊 | 0.6 秒 | — |
| 3000 | 1.1 GB | 沒變動 | 0.11 秒 | 0.10 秒 |
| 3000 | 1.1 GB | 搬一夾（75 份）＋ 20 份 | 0.17 秒，搬動 95 | 0.18 秒 |
| 3000 | 1.1 GB | 再搬三夾（約 250 MB）＋ 改 30 份 docx | 0.52 秒，搬動 320、修改 30 | 0.36 秒，**沒比完**：讀取上限 200 MB 用完，137 份被當成新增 |

結論：沒變動時只比大小與時間，幾千份也在 0.1 秒內；成本只跟「搬過、改過的檔有多大」有關，跟總份數關係小。快速模式碰到讀取上限時會把搬動誤報成新增（`changes_quick_hash_budget_bytes`），所以每句比對沒比完時**不能**把那批當新增處理，要等下一次接著比完（要做的事 1-4）。

## 資料與介面格式

### `.system/versions/<回合>/detected.jsonl`（新）

一行一筆，`schema_version` 不另帶（跟 `moves.jsonl` 同一層級）：

```json
{"op": "move", "kind": "file", "from": "file://來源/王宅/報價.docx", "to": "file://來源/2025 結案/報價.docx", "id": "f-1a2b3c4d", "by": "turn", "time": "2026-11-05T10:12:03"}

{"op": "added", "kind": "file", "from": null, "to": "file://來源/王宅/新會議.docx", "id": null, "by": "outside", "time": "..."}
{"op": "modified", "kind": "file", "from": "file://來源/王宅/進度.xlsx", "to": null, "id": "f-...", "by": "turn", "time": "..."}
```

`op`：`move`、`missing`、`added`、`modified`；`by`：`turn`（這一句、AI）、`outside`（兩句之間）。`missing` 的檔 willy 沒留一份，改回時回 `gone`（在資源回收筒的話說一句去那裡拿）。

### 工作日誌 `actions` 欄（新，`.system/journal/YYYY-MM.jsonl` 回合行與程式行）

```json
"actions": [
  {"item": "20261105-101203-ab12#3", "op": "move", "kind": "file", "from": "file://來源/王宅/報價.docx", "to": "file://來源/2025 結案/報價.docx", "by": "kb"},
  {"item": "20261105-101203-ab12#4", "op": "rename", "kind": "file", "from": "file://來源/王宅/報價.docx", "to": "file://來源/王宅/報價-定稿.docx", "by": "turn"},
  {"item": "20261105-101203-ab12#5", "op": "set", "kind": "record", "file": ".system/agenda.json", "key": "a-77", "field": "date", "old": "2026-11-05", "new": "2026-11-12", "by": "kb"}
]
```

`by`：`kb`（kb 或守門記的）、`turn`、`outside`。只抄位置類（move、rename、make、remove、trash）與 JSON 條目的單欄改動（`set`，舊值、新值只記 `journal_value_max` 200 字以內的，長的記 `"old": null`）；檔內容不抄。舊行沒有這欄照讀。

### `kb versions items --json`

```json
{"items": [
  {"item": "20261105-101203-ab12#1", "turn": "20261105-101203-ab12", "said": "11-05 10:12 那句「把報價搬去結案」",
   "op": "move", "kind": "file", "what": "報價.docx", "from": "file://來源/王宅/報價.docx", "to": "file://來源/2025 結案/報價.docx",
   "by": "kb", "copy": false, "undoable": true}
]}
```

`copy`：有沒有留一份（modify、delete、蓋掉的有）；`undoable`：false 時帶 `why`（`expired`、`gone`、`purged`）。

### `kb versions undo --json`

```json
{"done": ["20261105-101203-ab12#1"],
 "conflict": [{"item": "20261105-101203-ab12#4", "why": "later",
               "then": {"from": "報價.docx", "to": "報價-定稿.docx"},
               "later": [{"item": "20261106-090000-cd34#2", "side": "self", "said": "11-06 09:00 那句「搬去李宅」", "op": "move", "to": "file://來源/李宅/報價-定稿.docx"}],
               "now": "file://來源/李宅/報價-定稿.docx"}],
 "skipped": [{"item": "...", "why": "expired", "said": "..."}],
 "turn": "20261107-150000-ef56"}
```

exit 0：至少做了一項或全部是 conflict（交 AI 判斷，不算失敗）；exit 3：一項都沒做而且不是 conflict（全部 expired、gone、路徑不對）。人讀輸出照現在 revert 的白話（「把報價單搬回王宅了」；conflict 一項一句「報價單後來搬到李宅了，名字沒改回」）。

2. （自動）三句：改名、搬另一份、記日程；第四句「第一句那個名字改回來就好」→ 只改回名字，回答講改了什麼，沒提其他兩件。
3. （自動）兩句之間用檔案總管（測試用 `mv`）把一個案子的夾整個搬進「2025 結案」，下一句問「王宅的合約是哪天簽的」→ 照常答出，不問要不要改分類、不報變動數字。
4. （自動）兩句之間把一份明顯是王宅的報價搬進「李宅」夾，下一句問李宅的事 → 回答最後最多一句問「這份看起來是王宅的，要放李宅嗎？」（D-308(3)）。
5. （人眼）開場訊息：還有沒整理的檔、收件匣有放很久的檔 → 開場沒有任何份數。
6. （自動）刪掉一張早就結案、半年沒提的綜合卡，下一句隨便問 → 照 D-311 講「發現你刪了…，我看它結案很久了，之後不再整理它」，不追問；刪掉一張進行中、上週還在問的 → 問一次。
7. （人眼）Obsidian 打開一張綜合卡：最下面的檔案清單照種類分、「其他」與舊版是收起來的框，點了到檔案卡；總目錄兩節、有圖示。
8. （人眼，市集安裝）舊版知識庫升級後 `_extras` 變 `_個人`，裡面的檔還在，Obsidian 樹上看得到新名字。

## 不做

- 甲的守門、`kb source-edit` 新動作、`kb intake`／`kb output` 放到使用者的夾（丙只認它們寫的紀錄）。
- 乙的說明文字、`kb asks` 一次一件、偏好優先、升級提醒。
- 排程（B-522）：問 1 定了 (a)，不併。
- 多人共用（#5）的改回：D-296 的「別人改過的改重做或問」由多人共用 spec 接上這裡的 `conflict` 輸出。
- 已經清掉的回合備份不補救；`missing`（使用者自己刪、沒經 kb）的檔 willy 沒有複本。
