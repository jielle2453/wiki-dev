## 要做的事
根因：`hooks/_checks.refresh_lines` 每句先問 `git.is_repo`、`rebase_in_progress`、`refresh.head_changed`，裡面是 4 個 `git rev-parse` 子行程（pull 那句再多幾個，同一句 rev-parse 共 9 次），有負載時一個就 0.1～0.5 秒；`turn_lines` 的 1.5 秒檢查預算從 import 起算，git 用掉的時間擠掉後段檢查，pull 那句有負載時超過 hook 的 5 秒上限，整句被取消。
1. `scripts/kb/_lib/git.py`：`.git` 是夾而且有 HEAD、objects、refs（一般 clone）時，`is_repo`、`_git_dir`（`merge_in_progress`、`rebase_in_progress` 用）直接看檔；`head` 讀 `.git/HEAD` → 分支檔 → `packed-refs`，讀不懂（`.git` 是檔的 worktree、symref、reftable、壞夾、unborn）才照舊叫 git。
2. 9c 最少改動：refresh 本體、檢查順序、預算都不動（量過 pull 那句有負載時在 3 秒內，不用另外延後重畫）。
3. 測試：`test_lib_git` 一般 clone 讀檔不叫 git（含 packed-refs、detached、rebase-merge）、`.git` 是檔照舊叫 git、unborn 與只有 HEAD 的壞夾；`test_refresh` `QuietTurn`：HEAD 沒變時 `refresh_lines` 一個子行程都不叫（修前失敗）。

## 可以動 / 不可以動
- 可以動：`git.py`、上列測試、`ops/map-lib-platform.md` git 列、本 spec。
- 不可以動：`_checks` 的檢查順序與預算、`refresh.run`、Stop／開場 hook。
- 相關測試：test_lib_git、test_refresh、test_git_two_clones、test_streams_skeleton、test_lib_skeleton、test_lint_sizes、test_hooks_turn、test_repo_hygiene。

## 驗收準則
1. `python -m pytest -q tests/test_refresh.py -k QuietTurn`：過；git.py 還原失敗。
2. 真 hook 程序量測（`量測.py hook 20`，20 個佔滿 CPU 的程序）：pull 之後那句不超過 5 秒、有交給 AI；每句開頭不比 main 慢。
3. 相關測試加 hygiene 全綠。
