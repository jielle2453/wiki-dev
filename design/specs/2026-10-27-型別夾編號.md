# 型別夾編號
日期：2026-10-27
狀態：測試中
版本：發行時填
來自：issue #16；併入 B-449
區域：設定與知識、升級與發行、狀態檔格式、skill 文字

## 目的

客戶在 Obsidian、檔案總管打開知識庫時，型別夾（案子、業主…）跟程式的區（收件匣、AI 產出、檔案索引、系統）照字母混在一起，看起來亂。改成型別夾前面加兩位數編號（`01 案子`、`02 業主`），排在一起、排在程式的區前面；對話、卡片、設定檔裡的型別名稱照舊是「案子」，客戶看不到編號。

## 決策

- D-246：型別夾取名「兩位數編號、半形空格、型別名」（`01 案子`）；型別名稱照舊不帶；程式多一層「型別 → 資料夾」。
- D-247：預設照型別表順序給（第一列 01）；程式記每個型別用哪個夾；她在檔案總管自己改了夾名，程式照夾裡的實體認出是哪個型別、記下她的名字，不改回去、不問；拿掉型別或調順序時，只把還是預設名字的夾重新編號，維持 01 到 N。
- D-248：調順序跟 AI 說，note 用 `kb profile add 型別 名稱=<型別> 序號=<第幾列>`，不另寫指令；AI 先講哪些夾會改名、她說好才做；新加的型別排最後。
- D-249：舊知識庫升級時，夾名就是型別名的型別夾照順序補上編號；算大升級（拍快照），走 `_lib/migrate`。
- D-250：她自己建的夾後來加成型別，改成預設的編號名字、說一聲。
- D-251：`AI 產出/` 底下的分類夾不編號。

## 要做的事

### 1. 設定檔記每個型別的資料夾（`scripts/kb/_lib/profile.py`）

- `profile.json` schema 6 → 7：型別表（`types`）每列多選填欄 `dir`（磁碟上那個型別夾的名字）。
- 沒有 `dir` 的列是「升級前」：夾名就是型別名（舊知識庫、既有測試的假知識庫都是這樣，照常能用）。
- 新函式（名稱可調，回報寫明）：
  - `default_dir(index, name)`：`f"{index+1:02d} {name}"`。
  - `type_dir(data, type_name)`：那個型別現在的夾名（有 `dir` 用 `dir`，沒有用型別名）；找不到型別回 None。比對照 `entities.key`（NFKC casefold）。
  - `dir_type(data, folder)`：反查，資料夾名 → 型別名；同時認 `dir` 與沒有 `dir` 時的型別名。
  - `is_default_dir(name, folder)`：夾名是不是「兩位數、空格、型別名」（任何編號都算預設）。D-247 的「她改過的」就是 `dir` 不是預設名字。
- `load` 讀 schema 6 時在記憶體照舊（不補 `dir`）；`write` 有 `dir` 照寫、沒有照舊不寫。`kb init` 的設定檔升級（`init._upgrade_profile`）把 schema 升到 7 時**不補 `dir`、不動夾**；補編號只走第 5 點的遷移。
- `type_name_problem` 的長度上限扣掉編號的 3 個字（夾名最長的那個限制不變）。
- 設定檔 md 不顯示 `dir`；型別表的列序就是編號順序。第一節的提示句「型別名會變成知識庫第一層的資料夾名」改成「型別名前面會加上編號當資料夾名（例：01 案子）」。

### 2. 型別 → 資料夾一律經這一層

照下面的清單把「照型別名算夾名」與「照夾名認型別」改成經第 1 點的函式（清單來自設計 session 的全庫掃描；實作時再 grep 一次，有漏的照同一個做法補、回報列出）：

- `scripts/kb/_lib/entities.py`：`card_rel`（所有綜合卡路徑的源頭；要拿得到對照，呼叫端照現有讀設定檔的方式傳，或 `card_rel` 自己讀一次，實作選一種、回報寫明）、`_drift_kind`（`moved_type` 用 `dir_type` 認上層夾是哪個型別）、`clean`、`_move_card`（缺型別夾時建的是 `type_dir`）、`merge`。
- `scripts/kb/_lib/profile.py`：`folder_check`（`to_create`、`unlisted`、`removed_*` 都照 `type_dir`；用了她自訂名字的夾不算 `unlisted`）、`status`。
- `scripts/kb/profile_cli.py`：`_apply_locked`、`_remove_empty_dirs`、`_make_dirs`、`_edit_locked`、`_file_cards`、`_name_refusal`、`_plan_rename`、`_plan_merge`、`_plan_remove`、`_rename_type`、`_merge_type`、`_remove_type`、`_pending_rename`。`AI 產出/<型別>` 照舊用型別名（D-251）。
- `scripts/kb/_lib/synthesis.py`：`_question`（顯示時把夾名換回型別名）；其餘經 `card_rel` 的自動跟上。
- `scripts/kb/_lib/plan.py`：`_drift`（`moved_type` 的 `--type` 給型別名、不是夾名）、`_inbox_places`（推薦的實體夾是 `type_dir/名稱`）。
- `scripts/kb/_lib/cards.py`：`prefill_entities`（uri 裡的夾名經 `dir_type` 換成型別）。
- `scripts/kb/_lib/source_edit.py`：`_types`（型別夾名的集合改成照 `type_dir`）、`missing_entity_dir`（`--to` 收「01 案子/信義王」也收「案子/信義王」，建的是實際的夾）。
- `hooks/session.py` 的 `line_profile`：見第 4 點。
- `scripts/kb/entity.py` 的說明文字範例改成 `01 案子/王宅/王宅.md`。
- 守門（`scripts/kb/guard.py`）、清冊認卡（`inventory._is_card`、`_iter_root`）、`journal.changed_text`、`purge`、`versions` 只看層數或保留區，**不改**。

### 3. 預設編號與重新編號（D-247、D-248、D-250）

新函式 `profile.dir_plan(vault, data)`（名稱可調）算「每個型別應該用哪個夾」與要做的改名：

- 依型別表順序走：`dir` 是她自訂的（不是預設名字）而且夾在 → 照用；其他（沒有 `dir`、或 `dir` 是預設名字）→ 應該是 `default_dir(第幾列, 名稱)`。
- 回要做的改名清單 `[(現在的夾名, 應該的夾名)]`，加上每列新的 `dir`。兩個改名互換（`01 業主` ↔ `02 案子`）時先改成暫名再改回，不撞名。
- 要改成的名字已經被一個不是這個型別的夾佔了 → 那一步拒絕，照現有型別改名的撞名句子說。

用到它的地方，都在設定檔寫入的同一套 `_Undo` 裡做、改名經 `profile_cli._move`（記 `folders.jsonl`、可退回），做完照 `_follow` 重掃清冊、`cards.sync`、總目錄、綜合卡快取：

- `kb profile apply`（她手改型別表順序、拿掉型別）。
- `kb profile add 型別`：新型別排最後、建 `default_dir`。**多收 `序號=<n>`**：名稱已經在型別表時是「把它移到第 n 列」（照第六節偏好 `序號=` 的寫法，D-504），接著照 `dir_plan` 改夾名；`--check` 回會改名的夾（「01 案子 → 02 案子、02 業主 → 01 業主」）、問題與結果清單，跟 `type rename --check` 同一種格式。
- `kb profile type rename`：預設名字跟著換成新型別名、編號不變（`01 案子` → `01 工程`）；她自訂的夾名不動。
- `kb profile type merge`、`remove`：被併掉、拿掉的型別夾照現在的做法處理，後面還是預設名字的夾往前補號。
- D-250：加型別時第一層已經有同名的夾（她自己建的「合約」，現在列在「不在型別表」），改名成 `default_dir`，成功句多一句「合約這個夾改叫 04 合約了，跟其他型別放一起」。

### 4. 她自己改了型別夾的名字（D-247）

- 偵測（唯讀，放在 `profile.status` 與 `folder_check` 共用的地方）：某型別的 `dir` 在磁碟上找不到，而第一層剛好有一個「不在型別表」的夾，裡面的實體夾（`<夾>/<名稱>/<名稱>.md` 的綜合卡，或實體清單記的實體）全是那個型別的 → 認成她把那個型別夾改了名。
- 開場（`hooks/session.py` 的 `line_profile`）：有偵測到時印一行（取代那個夾的「不在型別表」）：「型別夾「案子」你改名叫「工程案」了：跑 kb profile apply 記下來（不用問）。」最多列 3 個。
- `kb profile apply`：把偵測到的寫進那個型別的 `dir`（她自訂的名字），成功句多一行「照你改的名字記下了：案子 → 工程案」；不改夾、不重新編號別的夾（她改的名字就是她選的）。
- 認不出（她改名的是空夾、或夾裡混了不同型別）→ 照現在的做法：那個夾列「不在型別表」，缺的型別夾照 `dir` 補建。
- note 的 `references/preference.md` 加一句：開場有「你改名叫…了」那行，照指示跑 `kb profile apply`，講成功句，不問。

### 5. 舊知識庫升級補編號（D-249）

- `scripts/kb/_lib/migrate.py` 的 `STATE_FILES` 加一列（不是 profile 的 schema 那列；`kb init` 已經可能把 schema 升到 7）：`stored` 是「型別表有沒有哪一列沒有 `dir`」（有 → 6，沒有 → 7），`current` 是 7。
- `rewrite`：對沒有 `dir` 的列——磁碟上有跟型別名同名的夾 → 照 `dir_plan` 改成預設名字並寫 `dir`；沒有夾 → `dir` 寫預設名字（之後 `folder_check` 照常補建）；第一層有個「不在型別表」、照第 4 點認得出是它的夾 → `dir` 記那個夾（她以前改過的，不動）。設定檔與夾的改動在同一套 `_Undo`、寫前備進回合；做完照 `_follow`。
- 設定檔 md 有手改未套用時照 `_rewrite_profile` 的做法丟 `Skip`（說先 `kb profile apply`）。
- 升級時照 D-215 拍快照（`upgrade.finish` 現有的大升級流程，不用改）。`lint.json` 的 `synthesis_fix[].path`、`batches.json` 裡指到舊夾的路徑一起換成新夾名（重新編號、型別改名時也一樣；現在的型別改名若已經有做，沿用）。
- 背景整理在跑時（`batches.live`）照現有型別改名的做法拒絕或等。

## 資料與介面格式

- `profile.json`（schema 7）`types[]`：`{"name", "category", "source", "date", "dir"?}`；`dir` 是夾名，例 `"01 案子"`、`"工程案"`（她自訂）。
- 預設夾名：`f"{n:02d} {型別名}"`，n 是型別表的列序（從 1 起）。
- `kb profile add 型別 名稱=業主 序號=1 [--check] [--json]`：型別已存在時是移位置。`--check --json` 回 `{"renames": [{"from","to"}], "question", "results"}`；做了的成功句：`已把業主排到第 1 個：01 案子 → 02 案子、02 業主 → 01 業主；不對可以說退回`。
- 開場那行：`型別夾「案子」你改名叫「工程案」了：跑 kb profile apply 記下來（不用問）。`
- `kb profile apply` 多的兩種句子：`照你改的名字記下了：案子 → 工程案`、`合約這個夾改叫 04 合約了，跟其他型別放一起`。
- 升級（`kb upgrade --finish`）的「轉成新格式」照現有格式列出這一列，另一行講改了哪些夾：`型別夾補上編號：案子 → 01 案子、業主 → 02 業主`。

## 驗收準則

測試放 `tests/test_type_dirs.py`，每條一個測試：

1. **新知識庫**：`kb init` 後 `kb profile add 型別 名稱=案子 大類=事`、`名稱=業主 大類=對象` → 第一層多 `01 案子`、`02 業主`，沒有 `案子`、`業主`；`profile.json` 兩列 `dir` 是 `01 案子`、`02 業主`、schema 7。
2. **綜合卡路徑**：登記實體「信義王」（案子），`cards todo --json` 給的綜合卡 `path` 是 `01 案子/信義王/信義王.md`；照它寫的卡 `synthesis.validate` 過、PostToolUse 照常重渲染。
3. **對話與卡片看不到編號**：`kb entity list`、`kb lookup 信義王`、綜合卡檔頭的 `型別` 都是「案子」。
4. **調順序**：`kb profile add 型別 名稱=業主 序號=1 --check --json` 回 `renames` 兩筆（`01 案子`→`02 案子`、`02 業主`→`01 業主`），什麼都沒動；不帶 `--check` → 夾名換好、夾裡的實體與綜合卡跟著、總目錄連結點得到新位置、清冊 uri 換成新夾名；`kb versions revert` → 夾名與設定檔都回到原樣。
5. **拿掉型別補號**：三個型別 `01 案子`、`02 業主`（空）、`03 工班`，拿掉業主 → `03 工班` 改名成 `02 工班`，工班的實體與卡跟著。

7. **合併**：`type merge` 後被併掉的夾不見、後面的預設名字往前補號。
8. **她改了夾名**：手動把 `01 案子`（裡面有信義王的綜合卡）改名成 `工程案` → 開場那行出現 `型別夾「案子」你改名叫「工程案」了…`、沒有「不在型別表」那行；`kb profile apply` → 印 `照你改的名字記下了：案子 → 工程案`，`dir` 是 `工程案`，`cards todo --json` 的路徑是 `工程案/信義王/信義王.md`；接著拿掉別的型別、調順序都不動 `工程案` 這個夾。
