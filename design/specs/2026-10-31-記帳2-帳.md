## 目的

做生意的錢與商品數量有一份程式管的帳，她說的、檔案裡讀到的都記進去，庫存、已收、未收由程式算。這份做帳的資料與指令、分店與調貨、報帳、帳關著時錢的話怎麼記與加總、改開時補帳、note 怎麼記、問的時候怎麼答、製卡讀到錢怎麼記、建置怎麼設開關。畫面（帳頁、卡底下、日程畫面、首頁）在第 3 份。

使用者時刻：
- 「賣李小姐 2 瓶精華液、1 盒膠囊，共 5,000」→ 記一筆收 5,000、精華液 −2、膠囊 −1；「精華液剩 4 瓶，低於安全庫存 5」。
- 「信義王尾款 120,000，11/30 要收」→ 未收、到期 11/30；「王先生先付了 10 萬，剩下下個月」→ 拆成已收 100,000 與未收 20,000。
- 「11/30 交屋，交屋時付尾款」→ 日程「交屋」加帳「應收尾款」；「交屋改 12/10」→ Claude 問「尾款也一起改到 12/10 嗎？」
- 小王（平常在北店）用手機說「賣了兩盒益生菌」→ 記益生菌 −2 盒（北店）；「從北店調 5 盒去南店」→ 一筆、兩個品項。
- 小王說「我墊了文具 3,200」→ 一筆付、墊的人小王、未付；他的首頁多一行「公司還欠你 3,200」（畫面在第 3 份）。
- 領薪水、帳關著的人說「今天幫公司收了王先生 5,000」→ 記成口述；問「這個月幫公司收了多少」→ 程式加總答。
- 「李小姐還欠多少」「這個月收多少」「今年第三季跟去年比」→ 程式算，Claude 照著答。
- 整理到原廠開給她的進貨單 → 記一筆付、標推測，回答末尾說一句；讀到客戶的保單保費 → 不記。

## 決策

- D-271 錢與數量同一筆；D-272（D-281 定案）應收應付也在帳；D-273 錢的部分進帳、其他進日程、改日期列另一邊；D-274 只記做生意的錢、AI 判斷流向、行業專用走客製（開關與建置由 D-343 修訂，多倉由 D-342 修訂）；D-275 部分收付拆兩筆記「拆自」；D-276 去重；D-277 多品項一筆、沒單價按售價估；D-282 庫存低當下說；D-284（4）任何區間由 kb 算。
- D-339：帳照流水檔存（`streams.KINDS` 登記 `money`，收回欄 `status: cancelled`，`history` 照 D-337 只往後加）；帳全隊看得到、不分誰的；誰都能改已收付、不做核准，誰改的照流水檔每行的「是誰」答；開關全隊一份。帳的一筆不另存 `recorder`。
- D-338：報帳記一筆付、多一欄 `advanced_by`（墊的人，成員名單上的名字）；還他時改已付、日期是還錢那天；全隊看得到，墊的人自己的首頁與開場多一行（第 3 份）；問「還欠小王多少」由程式照墊的人加總。單人知識庫沒有這欄。
- D-342：品項多「在哪」（第十節地點型別的實體，不是就擋）；調貨一筆不涉及錢、兩個品項；庫存照商品 × 地點算加合計；成員記帳沒講地點照第五節平常在哪填、成功句講出地點；安全庫存只看合計。
- D-341：C002 的手機的人經「C002-手機分人網址」對 willy 說話記帳；這份不碰那個客製，只要 note 的成功句講清楚記了什麼（手機頁顯示回覆）。
- D-343：三種開關的效果——**關**：錢的話記成口述（掛講到的實體），口述多內部記號 `money`（收付、金額），有後續的進日程；不擋、不問開帳、不說「帳沒開」；問加總由程式照標過的口述算；帳的寫入指令關著時程式擋（保險，exit 3，句子給 AI 不給她）。**只記我講的**：她講的進帳；製卡不抽錢（程式擋，材料不帶抽錢說明）。**開**：都記，檔案抽錢照「用在整理」的偏好細分（D-503、D-504）。**改成開或只記我講的**：標過、還沒進帳的口述（改開時加舊檔案卡）一起問一次要不要補，照當初那天記、出處寫補自那句口述，補之前照 D-276 查重複。**建置**：AI 照訪談知道的判斷，明顯的直接設並說一句、有會計軟體或記帳士的設只記我講的、領薪水的設關不提、看不出才問具體的。
- 使用者 11-08 說可以（原「這份 spec 新定」，照新編號）：
  1. 名字：程式 `scripts/kb/_lib/money.py`、指令 `kb money`、衍生副本 `.system/money.json`（`_lib/ledger.py` 已是守門留痕，不能叫 ledger）；正本在流水檔（D-339）。
  2. 程式認得的數字欄名：`售價`、`進價`、`安全庫存`、`每<單位>`（`每箱`、`每盒`）；第九節提示句與 note 照這幾個名字建議。
  3. 「金額未知」只准還沒收付的；改成已收付時一定要有金額。
  4. 兩種新的待處理：**可能同一筆**（D-276 看不出的）、**看不出是不是她的錢**（D-274 看不出流向的）；她答了照答案做。
  5. 數量只在東西真的進出時填（賒帳先拿貨的照填；先訂還沒出貨的不填，出貨那天再記一筆只有數量的）；庫存算所有沒取消的筆，不管收付了沒。
  6. 開關的效果照 D-343；數字欄的值不管開關都照抽。
  7. 帳的金額出處是她說的，回答照說「你 10/30 說的」不找原檔；出處是卡的照 R-03 回原檔核對。寫在 answer 的 reference，不改核心規則（常駐總量 5,021／5,050 已近上限，`test_budget.py`）。
  8. 關改開時舊卡補抽錢：份數超過 `ingest_auto_max` 照現有多量先問。
  9. 建置照 D-343（AI 判斷，不固定問一題），順便照 D-342 補地點的型別。
- 改 spec 時定（不另開 D）：note 的 description 要改——開頭明寫帳（「日程、帳與事」）、例句換一句跟日程無關的錢話（例「收到尾款 12 萬」），換掉哪句照 `skill-creator` 的指引定，總長 150 字內；測試 session 照 D-091 重跑 note 的路由測試。抽錢說明照材料裡用在整理的偏好做。她講一次性的價格寫成那筆品項的單價，不加數字欄。
- 小事預設（使用者 10-31 說好）：盤點記一筆調整（金額 0）不直接改庫存；「進 2 箱」照「每箱」欄換算，換算不了照 D-344（11-09 改）；每月重複的付款照日程重複那套；已建知識庫日程原有的付款條目不搬；退回照日程（一句話一個回合）。

| `cancel`／`reopen <m-…>` | | |
| `attach <m-…> --card f-…` | | 補出處 |
| `merge <留的> <併掉的>` | | |
| `count <商品> --actual <數>[單位] [--place <地點>]` | | 盤點 |
| `unsure --card f-… --text "…"` | | 開 money_unsure |
| `scanned <f-…>` | | 記清冊 |
| `list` | `--open`、`--entity`、`--from --to`、`--advanced-by` | |
