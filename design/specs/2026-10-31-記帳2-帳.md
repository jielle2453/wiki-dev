## 目的

做生意的錢與商品數量有一份程式管的帳，她說的、檔案裡讀到的都記進去，庫存、已收、未收由程式算。這份做帳的資料與指令、note 怎麼記、問的時候怎麼答、製卡讀到錢怎麼記、建置時問一題。畫面（帳頁、綜合卡底下那段、日程畫面讀帳、首頁）在第 3 份。

使用者時刻：
- 「賣李小姐 2 瓶精華液、1 盒膠囊，共 5,000」→ 記一筆收 5,000、精華液 −2、膠囊 −1；「精華液剩 4 瓶，低於安全庫存 5」。
- 「信義王尾款 120,000，11/30 要收」→ 記一筆未收、到期 11/30。之後「王先生先付了 10 萬，剩下下個月」→ 拆成已收 100,000 與未收 20,000。
- 「11/30 交屋，交屋時付尾款」→ 日程「交屋」加帳「應收尾款」；之後「交屋改 12/10」→ Claude 問「尾款也一起改到 12/10 嗎？」
- 「李小姐還欠多少」「這個月收多少」「今年第三季跟去年比」→ 程式算，Claude 照著答。
- 整理檔案時讀到原廠開給她的進貨單 → 記一筆付、標推測，回答末尾說一句；讀到客戶的保單保費 → 不記。

## 決策

- D-271 錢與數量同一筆；D-272（D-281 定案）應收應付也在帳；D-273 錢的部分進帳、其他進日程、改日期列另一邊；D-274 只記做生意的錢、AI 判斷流向、開關、規則另放 reference、行業專用走客製；D-275 部分收付拆兩筆記「拆自」；D-276 去重；D-277 多品項一筆、沒單價按售價估；D-282 庫存低當下說；D-284（4）任何區間由 kb 算。
- 小事預設（使用者 10-31 說好）：盤點記一筆調整（金額 0）不直接改庫存；「進 2 箱」照「每箱」欄換算，沒有就問、答了設成欄；每月重複的付款照日程重複那套；已建知識庫裡日程原有的付款條目不搬；退回照日程（一句話一個回合）；note 描述多半句、重跑路由測試。
- **這份 spec 新定（要使用者看過說可以）**：
  1. 名字：程式 `scripts/kb/_lib/money.py`、指令 `kb money`、資料檔 `.system/money.json`（`_lib/ledger.py` 已是守門留痕，不能叫 ledger）。**存法暫定整份一個 JSON，跟 `agenda.json` 一樣；多人共用定了存法後照它改。**
  2. 程式認得的欄名（第 1 份的數字欄，名字對了程式才拿來算）：`售價`、`進價`、`安全庫存`、`每<單位>`（`每箱`、`每盒`）。設定檔第九節的提示句與 note 照這幾個名字建議。
  3. 「金額未知」只准還沒收付的；改成已收付時一定要有金額。
  4. 兩種新的待處理：**可能同一筆**（D-276 看不出的）、**看不出是不是她的錢**（D-274 看不出流向的）；她答了照答案做。
  5. 數量只在東西真的進出時填（賒帳先拿貨的照填；先訂還沒出貨的不填，出貨那天再記一筆只有數量的）；庫存算所有沒取消的筆的數量，不管收付了沒。
  6. 開關（第 1 份）：「關」時 `kb money` 的寫入指令拒絕（「帳沒開，要開跟我說」），讀的照用；「只記我講的」時帶 `--card` 的寫入拒絕；製卡只在「開」時抽錢。**數字欄的值不管開關都照抽**（數字欄不是錢）。
  7. 帳的金額出處是她說的，回答照說「你 10/30 說的」，不去找原檔；出處是卡的照 R-03 回原檔核對。寫在 answer 的 reference，不改核心規則（core.md 已近字數上限）。
  8. 關改開時，舊卡要補抽錢：份數超過 `ingest_auto_max` 照現有多量先問的做法先問。
  9. 建置訪談多問一題「你的錢怎麼記」，照答案設第十節。

## 資料與介面格式

`.system/money.json`（schema 1；存法等多人共用定了再改）：
```json
{"schema_version": 1,
 "items": [
  {"id": "m-1a2b3c4d", "dir": "in", "amount": 5000, "status": "done", "date": "2026-10-30", "due": null,
   "entities": ["李小姐"], "lines": [{"entity": "精華液", "qty": -2, "unit_price": null}, {"entity": "膠囊", "qty": -1, "unit_price": null}],
   "text": "賣出", "note": "", "split_from": null, "repeat": null, "repeat_of": null,
   "source": "confirmed", "origin": null, "cards": [], "recorder": "", "created_turn": "t-…",
   "history": [{"date": "2026-10-30", "change": "記下", "by": "ai", "turn": "t-…"}]},
  {"id": "m-5e6f7a8b", "dir": "in", "amount": 20000, "status": "open", "date": null, "due": "2026-12-31",
   "entities": ["信義王", "王先生"], "lines": [], "text": "尾款（剩下的）", "split_from": "m-9c0d1e2f", "…": "…"}
 ]}
```

指令（`--json` 都有；寫入的都收 `--card f-…` 表示從那張卡讀到、來源推測）：

| 子命令 | 參數 | 說明 |
|---|---|---|
| `add` | `--dir 收｜付｜無`、`--amount <數>`（可省＝未知，只准沒收付的）、`--date <收付日>` 或 `--due <到期日>`（都沒給＝今天已收付）、`--entity <名稱>`…、`--item "<商品> <±數量>[單位][@單價]"`…、`--text`、`--note`、`--repeat month｜year｜week`、`--new`、`--unsure <m-…>` | 有候選又沒帶 `--new` → exit 3、回 `candidates`、不寫 |
| `settle <m-…>` | `--amount`（少於原額就拆）、`--date`（預設今天）、`--due <剩下的到期>` | 收付了 |
| `edit <m-…>` | `--amount --date --due --entity… --item… --text --note` | 改 `--due` 時回 `related_agenda` |
| `cancel`／`reopen <m-…>` | | |
| `attach <m-…> --card f-…` | | 補出處（同一筆） |
| `merge <留的> <併掉的>` | | 可能同一筆答是 |
| `count <商品> --actual <數>[單位]` | | 盤點 |
| `unsure --card f-… --text "…"` | | 開 money_unsure |
| `scanned <f-…>` | | 記清冊 |
| `list` | `--open`、`--entity`、`--from --to` | |
| `candidates` | 同 `add` 的 `--dir --amount --date --entity` | 只列不寫 |
| `sum` | `--from --to`、`--entity`、`--vs-from --vs-to` | 區間與比較 |
| `stock` | `[商品]` | |

`add` 的 `--json`：`{"item": {...}, "created": true, "low_stock": [{"entity": "精華液", "stock": 4, "min": 5, "unit": "瓶"}], "tell": "記下：10/30 收 5,000（李小姐；精華液 −2 瓶、膠囊 −1 盒）"}`；有候選時 exit 3：`{"refused": "candidates", "candidates": [{"id", "dir", "amount", "date", "due", "status", "entities", "text", "open": bool}]}`。

`sum --json`：`{"from","to","in","out","net","open_in","open_out","by_type": {"顧客": [{"name","in","out"}], …}, "products": [{"name","qty","amount","estimated": bool,"margin": null|數}], "vs": {同上} | null, "diff": {"in","out","net","pct": {...}} | null}`。

成功句（人讀）：金額千分位、日期帶星期、數量帶單位；拆帳講兩筆；低庫存一句；拒絕句講原因與下一步。
