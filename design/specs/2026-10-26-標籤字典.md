# 標籤字典
日期：2026-10-26
狀態：定稿
版本：（發行後填）
來自：issue #1；併入 無
區域：設定與知識、整理成卡、回答、建置、狀態檔格式、skill 文字

## 目的

保險業務問「在意醫療、還是準客戶的有誰」時，現在 AI 只能把 200 張客戶綜合卡一張一張讀：一次約 20 萬 token、每問一次付一次，寫法不一（「在意醫療」「怕生病」）還會漏（issue #1）。這題讓她在設定檔定一份「標籤字典」（某些欄只能從固定的詞挑），AI 更新綜合卡時順便照字典在檔頭標詞，找人時程式先篩、AI 只讀篩出來的卡。

## 決策

- D-231：字典的詞，建置時 AI 從她的綜合卡提候選、她挑；日常遇到字典外的再問她加，不自己加。
- D-232：標籤照型別定；每個型別都可以有，只給她會拿來篩的型別定；事類的進度不另做成標籤。
- D-233：字典放客戶設定檔第八節「標籤」；設定檔 schema 升 5（大升級）。
- D-234：標籤寫在綜合卡檔頭，欄名直接當一行；有行而空是「看過、沒有」，沒有這行是「還沒標過」；字典外的詞驗卡時擋；只標綜合卡。
- D-235：`kb entity list --tag 欄=詞[,詞]`，不同欄且、同欄或，第一句照實說幾個符合、幾個還沒標過。
- D-236：舊卡補標：標成要更新、原因「補標籤」，製卡助手只讀綜合卡、只改標籤行。
- D-237：改字典（詞改名、合併、拿掉，欄改名、拿掉）由程式直接改每張卡的檔頭，先 `--check`、說好才做、可以退回，合併與拿掉是 strict。
- D-238：每次更新綜合卡順便標（字典跟著材料給）；回答末尾一句講標了什麼；標籤不另帶出處；字典不進常駐；建置在綜合卡（與收舊 wiki）之後、交付報告之前多一步「標籤」，可以跳過。
- 相關：D-110（手改 md 開場問套用）、D-111（JSON 為真、md 是渲染）、D-134（結果清單與 strict）、D-143／D-144（型別改名、合併、刪除與 note 改設定檔的介面）、D-199（多量先問）、D-227（健檢的「為某個原因標成要更新」）。
- 這題自己發一版（大升級），排在 issue #6、#7 那版之後。

## 要做的事

### 一、設定檔第八節「標籤」：`scripts/kb/_lib/profile.py`、`scripts/kb/profile_cli.py`、`scripts/kb/init.py`

1. `SCHEMA_VERSION` 4 → 5；`profile.json` 多一個清單 `tags`：每筆 `{"type": 型別名, "field": 欄名, "words": [詞…], "multi": true|false, "source": 來源, "date": 日期}`。
2. md 第八節（照第七節「範本」加進來的做法，子代理查到要動的地方：`defaults`、`load` 的記憶體遷移〔`version < 5` 補 `tags: []`〕、`LISTS` 與各版的子集、`SECTIONS_OF` 補 `4: 7`、`NUMERALS`、`BASE_COLUMNS`、`SECTION_NAMES`、`TITLES`、`PROMPTS`、`TABLE_HEADS`、`_parse_tags`、`parse_md`〔`legacy=4` 缺第八節不算錯〕、`diff`、`merge`、`render_text`、`SECTION_SPECS`、`COLUMN_RULES`、`flat_rows`、`sections_schema`、`edited` 與新的 `_edit_tags`、`card_types_for_todo`、`counts`）：
   - 標題 `## 八、標籤`；提示句：`想照什麼條件找人或找案子？一列一個欄，詞用頓號分開；只能從這些詞挑，字典外的我會先問你。不用的型別不用填。`
   - 表頭 `| 型別 | 欄名 | 可選的詞 | 可多選 | 來源 | 日期 |`；可多選打 ✓ 或空白。
   - 驗證（`parse_md` 與 note 改都走這支，錯了丟 `ProfileError` 帶節與列）：型別要在第一節；同一型別的欄名不重複；欄名照型別名的字元規則（含 `SHELL_CHARS`），而且不准是綜合卡檔頭既有的鍵（`synthesis.KEYS`）或「標籤」；每欄 1～30 個詞，同一欄的詞不重複（比對照 `entities.key`），詞的字元照實體名稱的規則、不收 `[`、`]`、`,`、`、`；一列寫多個詞用頓號分開。
3. `kb profile add 標籤 型別=<型別> 欄名=<欄> 詞=<詞、詞…> [可多選=✓]`：那個型別沒有這個欄就加一欄；已經有就把詞加進去（可多選照原本的）。加完照第三節把那個型別的綜合卡標成「補標籤」。
4. `kb profile remove 標籤 …`：拒絕，句子 `拿掉標籤的詞或欄用 kb profile tag remove（會先算有幾張卡用到）`，跟第一節「拿掉型別用 kb profile type remove」同一套。
5. 她手改 md 第八節後 `kb profile apply`：加欄、加詞照常套用並標「補標籤」；拿掉或改名的詞、欄如果有綜合卡用到 → 拒絕，回問題與結果清單指到 `kb profile tag …`（照「刪有東西的型別那列擋」的做法）；沒有卡用到的照常套用。
6. `scripts/kb/init.py` 的 `UPGRADE_LINES` 補 `4: "設定檔升級：補第八節"`；schema 4 而 md 沒改過升 5、重渲染，改過請先 apply（照現有）。
7. `profile_cli.py` 的 `_detail_lines`、`show` 與節名的說明字串、`SECTION_HEADS` 跟著多第八節。

### 二、改字典：`kb profile tag rename|merge|remove`（`scripts/kb/profile_cli.py`）

照 `type rename|merge|remove` 的做法（`_guard_pending`、`--check` 回 `{"op","type","field","word","target","impact","question","results","refusal"}`、`entities._guarded` 加 `_Undo`、兩個設定檔與每張改到的綜合卡先 `turn.backup`、終端機記程式段）：

| 指令 | 做什麼 | strict |
|---|---|---|
| `kb profile tag rename <型別> <欄> <詞> --to <新詞> [--check]` | 第八節換詞；每張卡那一行換詞 | 否 |
| `kb profile tag merge <型別> <欄> <詞> --into <詞> [--check]` | 第八節拿掉前者；卡上前者換成後者，重複的只留一個 | 是 |
| `kb profile tag remove <型別> <欄> <詞> [--check]` | 第八節拿掉那個詞；卡上拿掉那個詞（剩空清單就寫 `[]`） | 是 |
| `kb profile tag rename <型別> <欄> --to <新欄名> [--check]` | 欄改名；每張卡那一行換鍵 | 否 |
| `kb profile tag remove <型別> <欄> [--check]` | 拿掉整欄；每張卡拿掉那一行 | 是 |

- `impact`：`{"cards": 用到的綜合卡張數, "both": 合併時兩個詞都有的張數}`；人讀第一行例 `客戶卡有 23 張標了健康，其中 9 張也標了醫療`。
- 改卡檔頭走 `synthesis.replace_front` 那一類只動那一行的寫法（新函式 `synthesis.retag(text, field, fn)`），不動其他行與內文；改完叫 `inventory.follow_redo`（若有）與綜合卡快取的既有收尾。
- 新詞、新欄名照第一節的驗證；`--to` 是同一欄已有的詞時拒絕並指到 `merge`。

### 三、綜合卡上的標籤：`scripts/kb/_lib/synthesis.py`、`rules/synthesis.md`

1. **寫法**：檔頭在 `相關實體` 之後，照第八節那個型別的欄、照第八節的順序，一欄一行：可多選寫清單 `在意: [醫療, 子女教育]`，單選寫一個詞 `階段: 準客戶`；看過沒有符合的寫空清單 `在意: []`（單選也寫 `[]`）。沒有這一行表示還沒照字典標過。
2. **驗證**（`synthesis.problems`／`validate`，PostToolUse 寫卡時已經會跑）：
   - `KEYS` 以外的鍵，必須是第八節裡這個型別的欄，否則擋：`檔頭的「X」不是這類卡的標籤欄（第八節沒有）`。
   - 詞要在字典裡，否則擋：`「寵物」不在「在意」的字典裡：先問客戶要不要加（kb profile add 標籤 …），不要自己加`。
   - 單選欄寫了兩個以上的詞擋。
   - 讀不到設定檔時不驗標籤行（其他照驗），寫 log。
3. **重寫不洗掉標籤**：`header_for`／`_front_text` 與 `_stale_item`、`synthesis_broken` 的 `header` 帶上卡上現有的標籤行（照第八節的順序；欄已不在第八節的不帶）；`synthesis_new` 的 `header` 照第八節列出那個型別的欄、值留空給 AI 填。`rules/synthesis.md` S-06、S-24「照給的 header 換掉整個檔頭」照舊成立。
4. **`rules/synthesis.md` 加一條 S-33「標籤」**：每次寫或更新綜合卡，照材料裡的字典（`profile.tags`）把那個型別的每一欄都寫出來；只能用字典裡的詞；內文寫得到才標，看過資料沒有就寫 `[]`；遇到字典外、但她明顯在意的條件，不寫進檔頭，回報裡列出來（主對話會問她要不要加）。
5. **補標籤的批次**：`profile add 標籤`、`apply` 加了欄或詞時，對那個型別每張有綜合卡的實體記一筆健檢那套的「為某個原因要更新」（`kb.lint.state.add_fix`，`reason` 是 `補標籤（在意）`，括號裡是這次新加的欄，或「欄：新詞」），不另開新的派工帳。`buckets` 照現有把它併進 `synthesis_stale`；`skills/ingest/references/carding.md` 材料的欄位那節寫明：原因是「補標籤」的，只讀 `existing_card`、只改括號裡那幾欄的標籤行，內文與其他行不動，不讀檔案卡（S-21 的例外）。份數多時照現有的多量先問（D-199）；大改動門檻（`big_change_synthesis_max`）對只改標籤行的批次不算（`batches._approval` 不數 reason 只有「補標籤」的項目）。
6. 材料：`profile.card_types_for_todo` 回的 `profile` 塊多 `tags`（照型別分組的字典），做卡、綜合卡、補標籤的批次都帶得到（`batches.batch_view` 現成的 `profile`）。

### 四、照標籤篩：`kb entity list --tag`（`scripts/kb/entity.py`、`scripts/kb/_lib/entities.py`）

1. `entity list` 多可重複的 `--tag <欄>=<詞>[,<詞>…]`（逗號或頓號都收）。不同欄是「且」，同一欄的多個詞是「或」；比對照 `entities.key`。
2. 只看 active 的實體；型別沒有這些欄的不列。讀每個實體的綜合卡檔頭（`entities.locate` → `cards.parse_front`）：有那一行且詞對得上算符合；沒有綜合卡或沒有那一行算「還沒標過」；有那一行但沒對上算不符合。
3. 人讀：照型別一段，第一句 `客戶 200 個中 12 個符合；另有 15 個還沒照字典標過`（「另有…」那半在 0 時不印），接著只列符合的，每行照現在的格式。`--json`：`{"entities": [符合的…], "counts": [{"type","total","matched","untagged"}], "tag": [{"field","words"}]}`。
4. 拒絕（exit 3、一字不差）：欄不在第八節 `第八節沒有「X」這個標籤欄；有：…`；詞不在那欄的字典 `「X」的字典沒有「Y」；有：…`；`--tag` 寫法不對 `--tag 要寫成 欄=詞（多個詞用逗號分開）`。
5. 沒帶 `--tag` 跟現在一模一樣。
6. `kb lookup <名稱>`（`_lib/lookup.py`）的實體那段多帶這個實體的標籤（人讀一行 `標籤：在意 醫療、子女教育；階段 準客戶`，`--json` 多 `tags`），沒有就不印。

### 五、回答末尾的一句：`scripts/kb/_lib/plan.py`

`_tell` 多一句：這一回合（含這個對話這一句派出去、這一句收尾的整理回合，照 `_judged_tell` 找回合的做法）寫過的綜合卡，標籤行跟備份比有變的，一張一句 `<名稱>標了：在意 醫療、子女教育`（只列新加的詞；拿掉的不講），超過 3 張併成 `另外 N 張也照字典標了`。`kb asks`（`tell_all=False`）也帶這一句。比對讀回合帳的備份（`turn.backup` 的檔），只讀不寫。

### 六、建置多一步「標籤」：`scripts/kb/_lib/build.py`、`scripts/kb/build.py`、`skills/build/`

1. `STEPS` 在 `adopt` 與 `finish` 之間插 `tags`，`STEP_TEXT` 是「標籤」；沒登記資料夾時跳過（加進 `SOURCE_STEPS`）。

3. `_check`（`done tags`）：補標籤的批次還在跑就擋（同 synthesis 那步的判法）；第八節空的也可以 done（她說不用）。
4. `skills/build/references/steps.md` 新增 `## 標籤` 一節：AI 照型別讀一輪綜合卡（一個型別超過 `tag_suggest_cards_max` 張就抽那麼多張），提出「最常出現的幾類條件與各自的詞、各有幾張」，她刪、改名、說好之後用 `kb profile add 標籤 …` 一欄一欄加；她說不用就 `kb build done tags`；加完等補標籤做完再 done。`skills/build/SKILL.md` 列步驟的地方跟著多這步。

## 資料與介面格式

`profile.json` 的 `tags`：

```json
{"schema_version": 5,
 "tags": [
   {"type": "客戶", "field": "在意", "words": ["醫療", "意外", "旅遊", "子女教育", "退休"], "multi": true, "source": "confirmed", "date": "2026-10-26"},
   {"type": "客戶", "field": "階段", "words": ["準客戶", "保戶", "流失"], "multi": false, "source": "confirmed", "date": "2026-10-26"}
 ]}
```

md 第八節：

```markdown
## 八、標籤
想照什麼條件找人或找案子？一列一個欄，詞用頓號分開；只能從這些詞挑，字典外的我會先問你。不用的型別不用填。

| 型別 | 欄名 | 可選的詞 | 可多選 | 來源 | 日期 |
|---|---|---|---|---|---|
| 客戶 | 在意 | 醫療、意外、旅遊、子女教育、退休 | ✓ | 確認 | 2026-10-26 |
| 客戶 | 階段 | 準客戶、保戶、流失 |  | 確認 | 2026-10-26 |
```

綜合卡檔頭（`相關實體` 之後）：

```yaml
相關實體: [王太太]
在意: [醫療, 子女教育]
階段: 準客戶
```

`kb entity list --tag 在意=醫療 --tag 階段=準客戶`（人讀）：

```
客戶 200 個中 12 個符合；另有 15 個還沒照字典標過
- 王先生（客戶，確認）掛 8 張，有綜合卡
…
```

`kb profile tag merge 客戶 在意 健康 --into 醫療 --check --json`：

```json
{"op": "merge", "type": "客戶", "field": "在意", "word": "健康", "target": "醫療",
 "impact": {"cards": 23, "both": 9},
 "question": "客戶卡有 23 張標了健康，其中 9 張也標了醫療；併起來 23 張都只剩醫療。要併嗎？",
 "results": [{"n": 1, "label": "併成醫療", "do": ["kb profile tag merge 客戶 在意 健康 --into 醫療"], "strict": true, "fill": []},
             {"n": 2, "label": "先不要", "do": [], "strict": false, "fill": []}],
 "refusal": null}
```

   - 「先不套用」→ `do` 空。
