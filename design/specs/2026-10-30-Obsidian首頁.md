## 目的

客戶一打開 Obsidian 就看到首頁：手上的事的時間軸、待辦、要她確認的，看到不對的順手改；找檔用一個智慧搜尋框。外掛的寫入一律叫 kb（D-106）。日程第二題（開始與工期、接、屬、原定、要徑、順延、工作天）跟這題一起設計、分開做（spec `2026-10-30-日程排程.md`）：這題的外掛畫現有的資料，那題再多畫子項、連線、基準線、要徑，加拖拉。兩題共用 `kb home --json` 的時間軸格式（本 spec「資料與介面格式」第 1 節），這裡就照那題要的形狀定好。

使用者時刻：她早上開 Obsidian，首頁最上面一句「今天也辛苦了」，時間軸看到信義王的水電晚了兩天標橘色；待辦「今天」有「確認窗簾款式」，她打勾；「王先生」那件的日期點開改成下週一；搜尋框打「王先生 報價 上個月」按 Enter，點那份報價直接用 Excel 開。

畫面：設計稿 https://claude.ai/artifact/JgBHRRnC7jr238bwpqLnkb 的「Generic」板（兩種預設資料各一張）。spec 與設計稿不同時以 spec 為準。

### 預設照做（小決定，不另問；使用者 10-30 說好）

1. `kb home --json` 一支給齊首頁（鼓勵句、件數、時間軸、待辦、要你確認的、其他要處理的、最近）。
2. 「最近」合併兩個來源照時間排：她從首頁開過的（外掛記的卡編號，D-262）、最近放進來的（清冊 `first_seen`）。
3. 點名字看總覽叫 `kb lookup <名稱> --json`。
4. 「到對話問 Claude」：把「幫我找：<她打的字>」複製到剪貼簿，提示「已複製，貼到 Claude 的對話裡」。
5. 鼓勵句由 kb 從固定清單照日期挑（有逾期與沒有逾期各一組，每句 12 字內），不叫 Claude。
6. 程式產生的頁被重新產生時認出手改（不經外掛，例如記事本改的、或她打字時 Claude 剛好改了日程）：認得出的照做，記在觸發那次的回合（歷程 `by: hand`），認不出的照 D-263 搬進那段。這條讓 D-223 的「AI 照意思做」改成程式直接做；看不懂的才問。

## 要做的事

1. **外掛本體** `obsidian/`（新）：`manifest.json`（id `wiki-with-willy`、`isDesktopOnly: true`、version 跟 plugin.json 一樣）、`main.js`（CommonJS、`require('obsidian')`、不打包）、`styles.css`（含藏「檔案索引」夾的規則，見 spike 的 CSS）。
   - 載入：照 D-258 找 kb.py 與 Python；`vault.setConfig('showUnsupportedFiles', true)`；開首頁分頁（`ItemView`，type `wiki-with-willy-home`，一個知識庫只開一個）；`fs.watch` `.system/` 的 agenda、pending、entities、inventory、profile.json，300 ms 去抖後重叫 `kb home`。
   - 叫 kb：`execFile`、`windowsHide: true`、cwd 是知識庫、env `PYTHONIOENCODING=utf-8`；一律帶 `--via obsidian`；exit 3 的那行印在 toast（kb 的句子原樣）；其他失敗 toast「沒做成：<stderr 第一行>」並寫 console。
   - 首頁各區照設計稿：鼓勵句與件數 → 時間軸（時間軸／月曆切換，每個事類實體一塊可收合，「全部展開／收起」，圖例）→ 兩欄：左「待辦」（已經過了／今天／這週，三組各自可收合、這週預設收起）、右「要你確認的」與其下可收合的「其他要處理的」。
   - 搜尋框在首頁頂端：按 Enter 叫 `kb find`；結果下拉：「照這樣找」那排（點掉一個就把那段字拿掉重搜）、實體、檔；點檔那列開原檔（`shell.openPath`；link 條目開網址），列尾小圖示開檔案卡；最後一列「到對話問 Claude」（預設照做 4）。搜尋框空著按 Enter 不搜。注音選字中（`compositionstart` 到 `compositionend`）按 Enter 不搜。
   - 「最近」：搜尋框下方一列（沒打字時顯示），資料從 `kb home` 的 `recent`；從首頁開過的卡編號存 `data.json`（`{"opened": [{"card","at"}]}`，最多 30 筆、只存編號與時間，D-262），叫 `kb home --opened f-…,f-…` 帶過去。
   - 實體總覽：點實體名稱開右側抽屜，叫 `kb lookup <名稱> --json`；最上面「← 回上一頁」（B-050 第 8 列）。
   - 動作（D-254、D-256），每個按完 toast 一句加「復原」：

     | 動作 | 指令 | 復原 |
     |---|---|---|
     | 打勾 | `kb agenda done <a-…>` | `kb agenda reopen <a-…>` |
     | 點日期改日期、時間 | `kb agenda edit <a-…> --date … --time …` | `kb agenda edit` 改回原值 |
     | 記成確認 | `kb agenda edit <a-…>` 不帶欄位 | 不給復原 |
     | 新增日程（小表單：種類、日期、時間、要做什麼、哪件事） | `kb agenda add …` | `kb agenda cancel <新的 a-…>` |
     | 取消（日期旁選單） | `kb agenda cancel <a-…>` | `kb agenda reopen <a-…>` |
     | 「其他要處理的」不用管 | `kb pending dismiss <p-…>` | 不給復原（D-226 的 back 只收先放著的） |
     | 「要你確認的」選一個結果 | 那個結果的 `argv`（見格式第 1 節） | 不給復原 |
     | 結案、改回進行中 | 先 `kb entity progress <名> 結案 --check --json` 跳確認框，按好才不帶 `--check` | 改回原狀態 |
     | 改名 | 先 `kb entity rename … --check --json` 跳確認框 | 改回原名 |
     | 合併 | 先 `kb entity merge … --check --json` 跳確認框 | `kb versions revert`（帶 `--via obsidian`，只挑 Obsidian 那組，D-255）；被 D-508 擋就把拒絕句印在框裡 |
     | 加、拿掉別名 | `kb entity alias <名> --add\|--remove …` | 相反 |
     | 改標籤 | `kb entity tag <名> 欄=詞 … --said` | 改回原標籤 |

   - 程式產生的頁（D-263）：總目錄、工作日誌、健檢報告用 `file-open` 事件把那頁切到閱讀模式，最上面一條「這頁由程式產生；要改請在首頁改，或直接跟 Claude 說」；日程、待處理、裁示照常可編輯，她離開被改的那一行（游標換行）或切到別頁時叫 `kb renders apply <頁>`；她開著的頁被外部改寫（`vault.on('modify')` 而不是她在打字）時 toast「這頁剛被更新了」，`renders apply` 回報有搬進那段的就說「你剛在這頁改的我留在最下面『你加的』」。

   - 自己的檔換了（磁碟上的 manifest.json 版號跟載入時不同）：首頁上方一條「首頁更新了，按這裡重新載入」，按了 `app.plugins.disablePlugin` 再 `enablePlugin`。

2. **`kb home --json`**（新，`scripts/kb/home_cli.py`、本體 `_lib/home.py`）：只讀、不開回合；格式見第 1 節。時間軸、逾期、今天、這週照 `_lib/agenda` 既有的算法（`counts`、`overdue_items`、`_window`），要你確認的跟 `kb asks` 同一支（`plan.build(…, tell_all=False)` 與 `plan.visible`），其他要處理的是 `pending` open 而不在 asks 裡的。一支行程裡算完，不 subprocess 叫別的 kb。`--opened` 收逗號分隔的卡編號（不在清冊 active 的略過）。人讀模式不做（`--json` 必帶，沒帶 exit 3「這個指令給外掛用，要帶 --json」）。

3. **`kb find "<字>" --json`**（新，`scripts/kb/find_cli.py`、本體 `_lib/find.py`）：照 D-257 拆字與比對（第 2 節），只讀卡與綜合卡，不讀原檔（彈性區不盤點、沒有卡，不會出現在結果裡，D-511）；人讀模式一行一筆（標題、卡型、日期、原檔所在的夾），給終端機與對話用。

4. **`kb renders apply <頁> [--json]`**（新，`scripts/kb/renders_cli.py`）：頁只收 `系統/日程.md`、`系統/待處理.md`、`系統/裁示.md`。在那份狀態檔的鎖裡跑 D-223 的比對，認得出的直接做：

   | 頁 | 打勾 | 刪掉一行 | 改日期 |

   | 日程 | `done` | `cancel` | `edit --date` |
   | 待處理 | `resolve`（how「在待處理.md 打勾」） | `dismiss` | — |
   | 裁示 | — | `remove`（收回） | — |

   認不出的（新打的行、改了某行的字）記進 `renders.json` 那頁的 `carried`（格式第 4 節），重新產生時放在那頁最底下「## 你加的（還沒處理）」，`kb asks` 每筆出一題（`kind: carried`）。做完重新產生那頁。歷程 `by: hand`，日誌「照你在日程.md 改的：記成完成『…』」。人讀一行一件，沒改什麼印「這頁沒有要照做的」。

5. **重新產生時的手改**（預設照做 6）：`agenda.render`、`pending.render`、`rulings.render` 認出手改時，改叫第 4 點同一支做（不再只 `handle_list` 開 handedit）；存不下她那份照舊 `KEEP_FAILED` 不蓋。`renders.diff` 的 `ignore_sections` 加「你加的（還沒處理）」那段；她在那段刪掉一行 = 不用了（從 `carried` 拿掉）。總目錄、工作日誌照舊 `keep_only`。

6. **`carried` 的處理**：`kb renders drop <c-…>`（不用了）；`kb asks` 那題的結果：日程那頁「加成日程」（`fill` 帶原文，AI 在對話裡 `agenda add` 後跑 `renders drop`；外掛開新增表單、原文填進「要做什麼」，存了再 drop）、「不用了」；待處理與裁示那頁「不用了」與「跟 Claude 說」（只在對話裡）。

7. **`--via obsidian`**（D-255）：`cli.py` 全域旗標（跟 `--turn`、`--session` 同一層、`--help` 不列；值只收 `obsidian`，其他 exit 3）。`turn.current()` 有它時開新回合（代號尾 `obsd`，回合檔 `source: "obsidian"`，不讀 `current.json`、不併進對話）；同一次呼叫內沿用。工作日誌程式段抬頭「你在 Obsidian 按的」（`journal.program_label` 認 `source`）。`versions`：有 `--session` 時候選不含 `source: obsidian` 的回合；有 `--via obsidian` 時候選只有 Obsidian 的；都沒有（終端機）照舊看全部；`list` 人讀標「（Obsidian）」，`--json` 每筆多 `source`。守門：模型自己帶 `--via` 照 `SELF_FLAGS` 擋（只有外掛帶）。

8. **清理**（D-264）：`_lib/clean` 數回合上限時跳過 `source: obsidian`；它們只照 `versions_keep_days`。

9. **`--check` 補三支**（D-256）：`kb entity progress <名> 結案|進行中|擱置 --check`、`kb entity rename … --check`、`kb entity merge … --check`：什麼都不寫，人讀一句後果（例「信義王記成結案：『施工』這段期間會在今天結束，還開著的 2 件日程照舊」「王先生改名叫王大明：夾、綜合卡、12 張檔案卡跟著改」），`--json` 回 `{"effects": [句子…], "refuse": null|句子}`。`kb agenda cancel <期間> --check` 同樣格式。

## 資料與介面格式

### 1. `kb home --json`（`willy-home/1`）

```json
{
  "schema": "willy-home/1",
  "version": "0.29.0",
  "today": "2026-10-30",
  "cheer": "今天也辛苦了",
  "counts": {"overdue": 2, "today": 1, "week": 4, "confirm": 3, "other": 2},
  "timeline": {
    "from": "2026-10-23", "to": "2026-12-31",
    "rows": [
      {"key": "e-1a2b3c4d", "label": "信義王", "type": "案子", "progress": "active",
       "marks": [
         {"id": "a-…", "shape": "bar", "kind": "period", "start": "2026-10-01", "end": "2026-11-20",
          "time": null, "text": "施工", "status": "open", "late": false, "inferred": false,
          "repeat": null, "hard": false, "entities": ["信義王"],
          "baseline": null, "critical": false, "slack": null, "derived": false, "children": []}
       ],
       "pauses": [{"start": "2026-10-10", "end": "2026-10-14"}],
       "links": []}
    ]
  },
  "todo": {"overdue": [], "today": [], "week": []},
  "confirm": [{"key": "…", "text": "…", "results": [{"label": "…", "argv": ["agenda", "done", "a-…"], "fill": null}]}],
  "others": [{"id": "p-…", "kind": "missing_file", "text": "…", "dismiss": true}],
  "recent": [{"card": "f-…", "title": "…", "type": "報價", "date": "2026-10-02", "why": "opened|added", "at": "…",
              "open": {"path": "C:/…/報價.xlsx"}, "card_path": "檔案索引/…/報價-1a2b3c4d.md"}]
}
```

- `rows`：每個 active 的事類實體（擱置的也列、`progress: paused`）有 open 條目或期間在 `from`～`to` 裡就一列；沒掛事類的條目放 `key: "_other"`、`label: "其他"`；照最近一個日期排。`from` 是今天往前 7 天，`to` 是 `home_timeline_days`（新鍵，預設 60）天後；月曆照同一份 marks。
- `marks`：`shape` 是 `bar`（有 start 或期間）或 `point`；`end` 是 `date`（期間的結案用 `ended`）；`late` 照 D-129（TRACKED 過了還 open）；`hard` 是到期與會議（日程第二題用）；`todo` 每件同 marks 一筆的欄位。
- 這題一律給：`baseline: null`、`critical: false`、`slack: null`、`derived: false`、`children: []`、`links: []`；日程第二題填。`links` 每筆 `{"from","to","gap","critical"}`。外掛遇到不認得的 `shape` 或 `kind` 不畫那筆、不報錯。
- `confirm.results[].argv`：給外掛的指令陣列（不含 `kb`、不含 `--via`），跟 `do` 字串同一個意思；`fill` 有值時外掛先開輸入框，`{name}` 換成她填的。只有 AI 才做得了的結果（例「跟 Claude 說」）`argv` 是 null，外掛顯示「到對話跟 Claude 說」。
- `recent`：`opened` 照 `--opened` 的順序、`added` 是清冊 active 條目 `first_seen` 最新的，合併照 `at` 排、同一張卡只留一筆，最多 20 筆；`open` 是 `{"path"}`（清冊第一個存在的位置，絕對路徑）或 `{"url"}`（link 條目）。

### 2. `kb find "<字>" --json`

```json
{"q": "王先生 報價 上個月",
 "parsed": [{"kind": "entity", "text": "王先生", "label": "實體 王先生", "value": "王大明"},
            {"kind": "type", "text": "報價", "label": "卡型 報價", "value": "報價"},
            {"kind": "time", "text": "上個月", "label": "時間 9/1～9/30", "value": ["2026-09-01", "2026-09-30"]},
            {"kind": "word", "text": "…", "label": "字 …", "value": "…"}],
 "entities": [{"name": "王大明", "type": "業主", "why": "名稱"}],
 "files": [{"card": "f-…", "title": "…", "type": "報價", "date": "2026-09-12", "entities": ["王大明"],
            "open": {"path": "…"}, "card_path": "…", "hit": "title|body|filter"}],
 "total": 3, "more": false}
```

拆字：先 NFKC 加 casefold（`entities.key`）；在整串裡由長到短找實體名稱與別名（合併轉址到目標、只認 active）、設定檔卡型、第八節標籤詞、時間詞（D-257 的清單；「10 月」是今年 10 月、今年還沒到就是去年）；剩下的照空白切成字。比對：不同種類「且」、同種類「或」；實體 → 掛它的卡；標籤 → 標了那詞的實體的卡；時間 → 卡的日期在範圍；字 → 標題（`hit: title`）或內文（`body`），綜合卡內文有字的實體列進 `entities`。排序：標題命中在前，再照日期新到舊；最多 50 筆、`more` 說還有沒有。只讀卡與綜合卡，排除與 purge 照現有範圍。

### 3. `--check` 的 `--json`

`{"effects": ["…"], "refuse": null}`；`refuse` 有字時 exit 3（`--json` 照印）。

### 4. `renders.json` 的 `carried`（選填）

`"carried": {"系統/日程.md": [{"id": "c-<8hex>", "kind": "added|changed", "text": "測試", "orig": null, "at": "2026-10-30T09:12:00+08:00"}]}`；`changed` 帶 `orig`（原本那行）。那段渲染：

```
## 你加的（還沒處理）
這段是你在這頁寫、我還沒看懂的；在首頁或對話裡回我，或刪掉這行就是不用了。
- 測試
- 原本「水電預計完成」→ 你改成「水電預計完成（延一週）」
```

### 5. 外掛的 `data.json`

`{"opened": [{"card": "f-…", "at": "…"}]}`，最多 30 筆；不存路徑、標題、搜尋過的字。

### 6. `defaults.json` 新鍵

`home_timeline_days`（60）、`home_recent_max`（20）、`find_results_max`（50）、`find_recent_days`（30，「最近」）。各帶 `_why_`。
