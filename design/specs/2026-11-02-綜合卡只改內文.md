# 綜合卡只改內文、檔頭交給程式
日期：2026-11-02

版本：（發行後填）

區域：整理成卡、hooks

## 目的

整理一份檔時，要更新的綜合卡每張都被 AI 整張重寫。#32 實測（C003 演練庫，0.31.1）：整理 1 份 md 筆記約 12 萬 tokens，其中更新 5 張綜合卡佔 8.3 萬。最大一張（GS-3V-NM，掛 168 張檔案卡）21 KB 裡，檔頭佔 73%（「整理到」「檔案卡」各 168 行），全是程式算好的清單，AI 每次照抄一遍；抄錯還會被 hook 打回「整理到不是現行的」，重跑一次。

使用者時刻：客戶丟一份會議筆記說「整理一下」，用 Pro 方案的額度撐得住；綜合卡照樣跟著更新。

做法：更新綜合卡時 AI 只用 Edit 改內文（現況、紀事、要改的標籤行），不碰其他檔頭欄；改完跑 `kb entity render <名稱> --synced`，由程式把檔頭換成現行的。

## 決策

- D-518（新增，修訂 D-121 的寫法與 `rules/synthesis.md` S-24）。待 jielle2453 在 issue #32 留言同意（process 第八節第 3 條）；jacky 2026-11-02 定先開工，她不同意就回頭改。
- 照 D-121：「整理到」是寫卡時依據的卡與指紋，`kb cards todo` 拿它比對、列待更新。這題不改它的意思與格式，只改由誰寫進卡裡。
- 照 D-147(4)：answer 可以直接改綜合卡一句。這題之後，那種改法不會再因為「整理到不是現行的」被打回；「整理到」維持舊的，所以下次整理仍會列待更新。

## 要做的事

1. **`kb entity render` 加參數**（`scripts/kb/entity.py` 的 `render` 子命令與 `_render`）
   - 新增位置參數 `名稱`（0 個以上，可以是別名）與旗標 `--synced`。
   - 不帶 `--synced`：照現在的行為；給了名稱就只處理那幾個實體，沒給就全部（`synthesis.render_cache(vault, names or None, turn_id)`）。
   - 帶 `--synced`：至少要一個名稱，沒給就印錯誤、exit code 2，不寫任何檔。對每個名稱：先找得到實體，而且實體有合法綜合卡（`problems` 只剩 `STALE_CODE` 或什麼都沒有），才把檔頭的 `整理到`（照 `header_for` 同一算法：`synced_lines(掛的卡, 口述, 裁示, redo_ids, 推算)`）、`更新日`（今天）、`檔案卡`、`相關實體` 四欄換成現行的。其他檔頭行（含標籤行）與內文一字不動。寫前 `turn.backup(by="program")`，日誌照 `_render` 記。
   - 找不到實體、沒有綜合卡、或綜合卡還有別的錯：不寫那張，列進 `skipped`，`reason` 帶第一個錯的原因（沒卡寫「還沒有綜合卡」，找不到寫「找不到這個實體」）。有 skipped 時 exit code 1。
   - 實作建議：在 `_lib/synthesis.py` 加 `mark_synced(vault, names, turn_id)`，回 `(written, skipped)`，寫完照 `render_cache` 呼叫 `_follow_fixes`（B-463）。
2. **hook 不再因「整理到」打回**（`hooks/output_log.py` 的 `_check_synthesis`）
   - `synthesis.validate` 的結果只剩 `整理到不是現行的` 這個錯時，當成通過：照通過的路走（`_record_base`、`set_card`、`render_cache`、`copy_tags`），不 block。其他錯照現在打回；同時有別的錯時報那個別的錯。
   - 實作建議：`validate(..., allow_stale=False)` 加參數，hook 傳 `True`；其他呼叫的地方不變。
   - 紀事只增的檢查（`_lost_events`）照舊。
3. **`rules/synthesis.md`**
   - S-24 改成：「用 Edit 改現況、紀事加一行（要改標籤行也用 Edit 改那幾行），其他檔頭行與不改的段不動，不整張重寫；改完跑 `kb entity render <名稱> --synced`，由程式把整理到、更新日、檔案卡、相關實體換成現行的。指令回 skipped 就照 reason 改好再跑一次；還是 skipped 就停，回報那張沒更新好與原因。」
   - S-06 加一句：「`整理到`、`更新日` 照抄只用在新建（S-19）與有問題的卡（S-28）；待更新的照 S-24，不抄。」
   - S-21 不改（照樣先 Read 舊綜合卡）。

## 資料與介面格式

- 綜合卡檔頭格式不變（`整理到` 每行 `<編號> <指紋前 12 碼>`，口述、裁示、推算 `<編號> -`，redo 的指紋欄 `redo`）。
- `kb entity render [名稱 ...] [--synced] [--json]`
  - 文字輸出：`重寫了 N 張綜合卡的檔頭`；有 skipped 時每張多一行 `沒寫 <名稱>：<reason>`。
  - `--json`：`{"written": ["案子/王宅/王宅.md"], "skipped": [{"name": "王宅", "reason": "…"}]}`；不帶 `--synced` 時 `skipped` 是 `[]`。
  - exit code：全寫好或沒有要寫的 0；有 skipped 1；`--synced` 沒給名稱 2。
- hook（PostToolUse，Write／Edit 綜合卡）：只差整理到時不輸出 block；其他照舊 `{"decision": "block", "reason": "綜合卡有錯：<原因>。改好再寫一次。"}`。

## 驗收準則

1. `kb entity render 王宅 --synced`（王宅綜合卡只差整理到）→ 印「重寫了 1 張綜合卡的檔頭」、exit 0；之後 `synthesis.validate` 回 `(True, "")`，`kb cards todo --json` 的 `synthesis_stale` 沒有王宅；卡的內文與標籤行跟跑之前逐字相同，`更新日` 是今天。
2. 同上再跑一次 → 「重寫了 0 張綜合卡的檔頭」、exit 0、檔沒變（mtime 不變）。
3. `kb entity render --synced`（沒名稱）→ exit 2、沒有檔被寫。
4. `kb entity render 不存在 --synced --json` → exit 1，`skipped` 有 `{"name":"不存在","reason":"找不到這個實體"}`；有實體但沒綜合卡的 → reason「還沒有綜合卡」；綜合卡少了 `## 現況` → reason 是「正文要有 # 王宅 與 ## 現況」，卡沒被改。
5. 用別名跑 `--synced` 跟用名稱跑結果一樣。
6. `kb entity render`（不帶參數）行為與輸出跟改之前一樣（`test_scripts_entity_cli.py` 現有的 `test_render` 照過）；`kb entity render 王宅` 只重寫王宅那張的兩欄。
7. hook：綜合卡掛上新檔案卡後，用 Edit 改內文（整理到沒換）→ 不 block；`set_card`、`render_cache` 照跑（檔案卡欄已有新卡）；`kb cards todo` 照樣把它列在 `synthesis_stale`。`tests/test_hooks_output_log.py` 第 459 行那條改成驗「不 block」。
8. hook：只差整理到、同時名稱抄錯 → block 的原因是「「名稱」照 kb cards todo 給的檔頭抄」；紀事少了一行 → 照舊被紀事檢查打回。
9. `synthesis.validate(vault, rel)`（不帶 `allow_stale`）結果跟改之前一樣（`test_lib_synthesis.py` 第 88、310 行照過）。
10. `rules/synthesis.md` S-24 含「Edit」「kb entity render <名稱> --synced」「不整張重寫」；`agents/card-maker.md`、`carding.md` 各有一處 `--synced`（`test_rules_synthesis.py` 加檢查）。
11. 相關測試全綠（commit 之後跑，看 exit code）。

### 實作疑義（2026-11-02，實作 099a3d1）

1. `carding.md` 補的那句放在 `synthesis_stale` 整個物件的 code span 之後（不塞進 JSON 的 code span 裡）：照實作的放法。
2. `card-maker.md` 補的那句放在「（R-08，少了會被打回）」括號之後：照實作的放法。
3. hook 的 `allow_stale` 不分新建或待更新：新建綜合卡時整理到抄錯也放行，下次 `cards todo` 列成待更新，再照 S-24 用 Edit 加指令補上。照 spec，不改：比打回、整張重寫便宜，也不會漏。
4. `mark_synced` 只差更新日也寫：照字面，不改。AI 只在改完內文後跑，那天本來就是更新日。

### 測試第 1 輪後（2026-11-02，報告 43a0f2e，發現 #1～#7 皆低）

6. 發現 #1 **要修**：`整理到` 不是清單（寫成字串）時，`problems` 回自己的錯（code 不是 `STALE_CODE`，原因「整理到 照 kb cards todo 給的檔頭抄（一行一項）」），hook 照打回、`--synced` 照列 skipped；`cards todo` 不再把它列進 `synthesis_stale`（列 `synthesis_broken`）。只有清單內容不是現行的才算只差整理到。
7. 發現 #2：broken 的卡整張重寫時整理到抄錯也放行，下次列待更新。跟裁定 3 同理，照現在。
8. 發現 #3 **要修**：`--synced` 沒給名稱時，帶 `--json` 印 `{"error": "--synced 要給至少一個實體名稱"}`，exit 2 不變。
9. 發現 #4 **要修**：`mark_synced` 先檢查卡，寫了或確定 skipped 才記進 `seen`；同一個實體用名稱和別名各給一次時，結果只算一筆，但第一個被 skip 不會讓第二個消失（兩個都 skip 時列一筆）。
10. 發現 #5：照實作（格式節為準），不帶 `--synced` 的 `--json` 也有 `skipped: []`；驗收 6 的「輸出一樣」指文字輸出。
11. 發現 #6 **要修**：`skills/ingest/references/commands.md` 加進「可以動」（只 `entity render` 那列）：改成「改完待更新的綜合卡跑 `kb entity render <名稱> --synced`，程式換整理到、更新日、檔案卡、相關實體；不帶名稱與 `--synced` 是重寫全部綜合卡的檔案卡、相關實體兩欄，平常不用」。
12. 發現 #7：照現在。
