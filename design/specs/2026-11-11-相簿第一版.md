## 目的

AI 用守門認不出的寫法改了、刪了檔（例：`$f = Get-Item 報價.docx; $f.Delete()`、`python 自己寫的腳本.py`），沒有回合備份，她說「退回」退不掉。相簿在每台電腦另外照一份，接住這些。

客戶的時刻：她說「把舊報價刪掉」，AI 不管用什麼寫法刪了；她說「退回」，檔回來。她不知道有相簿，也不會多被問。

## 決策

D-347（方向）、D-349（第一版）：

1. **只當安全網**：回合備份、`kb versions revert`／`undo`、搬動偵測照舊。退回時，這句話裡被改了、刪了卻**沒有回合備份**的檔，從相簿拿這句「動檔前」那張的版本放回。
2. 每個要保護的資料夾（知識庫、每個登記的來源）一本相簿：git dir 在 `%LOCALAPPDATA%\wiki-with-willy\album\`，不在知識庫、不在雲端夾。
3. 什麼時候照：AI 這句第一次叫會寫檔的工具前（檔案工具、Bash、PowerShell）、答完、背景排程每 10 分鐘。第一次整本照只在背景做。
4. 不照：50 MB 以上、憑證樣式、Office 暫存 `~$`、`.git`、`.system/`、Obsidian 一直在寫的檔、使用者說不讀的夾、雲端「只在線上」的檔。**不管知識庫或來源裡的 `.gitignore`**（暫存區等也要照）。
5. 留 30 天，背景每週清一次；清法不改舊照片的雜湊（album.json 記的雜湊對得上）。
6. 沒有 git 的電腦：相簿不開、照回合備份走；健檢提醒一次；建置時裝 Git for Windows。
7. 守門照舊（D-347），另外擋 AI 碰相簿夾、下指向相簿的 git 指令。
8. 相簿出錯、逾時一律不擋工具、不擋回答：記 log，這張不照。

## 要做的事

### 一、相簿本體（新 `scripts/kb/_lib/album.py`）

1. **位置**：`album_dir(vault, root)`：環境變數 `WIKI_WITH_WILLY_ALBUM_DIR` 有值就用它，否則 `%LOCALAPPDATA%\wiki-with-willy\album`（沒有 LOCALAPPDATA 用 `~/.local/share/wiki-with-willy/album`，同 `office.tools_dir`）；夾名 `<vault id>-<要保護的根 realpath（Windows casefold）sha1 前 8 碼>.git`。沒有 vault id 回 None（不開）。每次現算，不寫進狀態檔（D-019 同理，照 `card_index.db_path`）。
2. **要照的根** `roots(vault)`：知識庫，加上 `sources.load(vault).entries` 每個的 root（用真實大小寫：`turn._realcase` 或 realpath）；`.unresolved`、磁碟不在（`versions._drive_gone`）的跳過；巢狀的（來源在知識庫裡、來源套來源）只照外層。
3. **建一本** `ensure(root)`：git dir 不在就 `git init`（`--git-dir`、`core.worktree`），設定照 `design/reports/git保護-spike.md`：`core.autocrlf=false`、`core.quotepath=false`、`core.longpaths=true`、`gc.auto=0`、`maintenance.auto=false`；`info/attributes` 寫 `* -text -filter -diff`。
4. **不照的清單**：`.git/`、`.system/`（整個）、`.obsidian/workspace*.json`、`.obsidian/cache`、`.obsidian/plugins/wiki-with-willy/data.json`、`inventory.SKIP_NAMES`、`credentials.CREDENTIAL_PATTERNS`、那個根的排除夾（`vault_excludes`、各來源 `excludes`）、`album_file_max_mb` 以上、只在線上的檔（`inventory.PLACEHOLDER_ATTRS`）。**樹裡的 `.gitignore` 不算**：用 `add -f` 加自己的排除（pathspec `:(exclude)` 或暫存 index，實作選；結果要跟上面這張清單一樣）。
5. **只在線上的檔**：**照 OneDrive 實測報告（`llm-wiki-test\git保護-spike\OneDrive報告.md`）補**：未追蹤的不讀；已照過、後來變成只在線上的保留最後一版、不算刪掉。用 `os.scandir` 看屬性（不會下載）。
6. **照一張** `snapshot(vault, budget, why)`：每個根 `add`＋有變才 `commit`（訊息寫 why 與回合代號），回 `{根鍵: commit}`；沒變回上一張的 commit。`budget` 是秒數（None＝不限）：還沒有第一張的根在有 budget 時**跳過**（第一張只在背景照）；超過 budget 剩下的根這次不照。git 用自己的小 runner：不重試、逾時短，不用 `git.run`（它遇 `index.lock` 會重試 5 次、每次 2 秒）。相簿自己一把鎖（相簿夾裡的鎖檔，O_EXCL，拿不到就這次不照）。
7. **差異** `changed(root, a, b)`：`git diff --name-status -M -z --no-textconv a b`，回 `[{"path","status","old"}]`。
8. **放回** `restore(root, commit, paths)`：`git restore --source=<commit> --worktree -- <paths>`；放回後驗 sha256 等於那張裡的 blob。
9. **清舊的** `prune(root, keep_days)`：照 spike 的清法 B（shallow，不改留下來那些照片的雜湊，清完刪 `commit-graph`），再 `reflog expire`＋`gc --prune=now`。相簿夾記上次清的時間，滿 7 天才清。
10. **根鍵**：`album.json` 裡不寫絕對路徑，根用 `vault` 或來源 alias。

### 二、什麼時候照

1. **動檔前**（`hooks/guard.py` `_judge`）：decision 不是 deny、工具是 Write／Edit／MultiEdit／NotebookEdit 或 Bash／PowerShell、找得到知識庫、不是子代理的回合、這句還沒照過 → `album.snapshot(vault, budget=album_hook_seconds, why="before")`，把各根的 commit 與 `git.head(vault)`（團隊 git 的 HEAD，沒有就 None）記在這個 session 的回合檔（`turn` 的 session 檔，照 `mark_session` 的寫法）。放在備份（`before_write`）之前、拿完相簿鎖就放掉。整步包 try：任何例外或逾時記 `.system/hook-errors.log`（source `album`），**照常回原本的 decision**，不讓 `onFailure: block` 生效。Codex 經 `_codex_main` 逐檔跑 `_judge`，同一句只照一次。
2. **答完**（`hooks/stop.py`，`_finish` 之後、`_jobs` 之前）：這句有「動檔前」那張 → `snapshot(budget=album_hook_seconds, why="after")`；算每個根的 `changed(before, after)`；扣掉這段時間團隊 git 拉進來的（`git.changed_by_others(vault, 前 head, 後 head)`）；還有剩的才建這句的回合夾（`turn.turn_dir`）寫 `album.json`（格式見下）。沒變不建回合夾（不佔 `versions_keep_turns`）。失敗只記 log。
3. **背景**（`scripts/kb/changes.py` `_background`，`card_index.groups` 之後）：`snapshot(budget=None, why="background")`（還沒有第一張的根在這裡照）；滿 7 天 `prune`。例外照現有那段記 log（source `album`）。`background_scan_minutes` 是 0 或不是 Windows 時，第一張在每天第一句那批用 detached 子行程照（照 `lint/runner.py` 背景健檢的做法）。

### 三、退回

1. **`kb versions revert`**（`scripts/kb/versions.py`）：
   - `_changed` 把有 `album.json` 的回合算進候選（全用 Bash 改檔的回合現在沒有 manifest，看不到）。
   - `_touches` 與 `items.Ledger._build` 收 `album.json` 的路徑，D-508 的重疊檢查一起看（後來那句用 Bash 改了同一檔也擋得到）。
   - 還原 manifest 那段之後（夾的收尾之前）：`album.json` 裡**不在 manifest、moves、folders** 的改、刪、新增：先把現在的檔照 `turn.backup` 備進這次退回的回合（退錯能再退）；現在的檔跟「答完」那張的 blob 不一樣 → 之後被人改過，不放回、在輸出說一句；一樣 → 改的、刪的從「動檔前」那張放回，新增的移到資源回收筒（照 `kb source-edit trash` 的做法）。
   - 人讀與 `--json` 輸出多一類 `album_restored`（放回幾份、哪幾份沒放回與原因）。
2. **`kb versions undo`**（逐項）：`items` 多一種 `src: "album"` 的項目（照 `_undo_file_item` 的做法新寫 `_undo_album_item`）；衝突照 `items.conflicts_of`／`later_than`，另比「答完」那張的 blob。
3. 回合夾清掉（`clean.plan`，30 天／200 回合）與相簿清舊的（30 天）各清各的；album.json 指到已清掉的照片時，那幾份照「退不回」說。

### 四、守門（`scripts/kb/guard.py`）

1. 相簿夾（`album_dir` 的上層 `…\wiki-with-willy\album\`）底下新一區 `Z14`，讀寫都 deny，理由句「這是 willy 的保護紀錄，不讀不改」（加 `AI_TAIL`）。現在 `%LOCALAPPDATA%\wiki-with-willy\` 落在 Z11 全放行；`tools`、`index` 照舊。
2. git 指令：`_shell_tool` 分析完，動詞是 git 而且參數有 `--git-dir`／`--work-tree`、或環境設 `GIT_DIR`／`GIT_WORK_TREE`、或參數含相簿夾 → deny（同一句理由）。
3. #25 守門補洞先發行；這題從那之後的 main 開。

## 驗收準則

1. **守門漏掉的刪、改退得回來**：一句話裡用 `$f = Get-Item '<暫存區>\a.docx'; $f.Delete()`（守門放行、沒有回合備份）刪掉一份、用 `python <腳本>` 改掉一份 → `kb versions revert` 後兩份都回來、sha256 等於動檔前；`--json` 的 `album_restored.restored` 列這兩份。
2. **全用 Bash 改檔的回合也是候選**：那句沒有 manifest，`kb versions list` 看得到它、revert 退得了。
3. **D-508**：後來另一句又改了同一份（不論用檔案工具或 Bash）→ 那份不放回、說原因；undo 逐項同樣。
4. **之後被人改過不放回**：答完之後在 Obsidian 手改那份 → revert 時那份不放回，`skipped` 寫原因。
5. **新增的移到資源回收筒**、退錯能再退（退回那句自己的回合有現況備份）。
6. **團隊 git 拉進來的不算**：兩個 clone，這句中間另一台推了一份、這台拉進來 → album.json 沒有那份、revert 不碰它。
7. **不照的都不在相簿**：`.system/`、憑證樣式、`~$x.docx`、50 MB 以上、排除夾、只在線上的檔（測試用替身設屬性）都不在任何一張；`暫存區/`（知識庫 `.gitignore` 排除的）**在**。
8. **時間**：3000 份、1.1 GB（spike 的產生程式）已有第一張時，動檔前與答完各 ≤ `album_hook_seconds`；還沒有第一張時 hook 跳過、不擋；故意讓 git 卡住（替身）→ 工具照常、hook-errors.log 一行。
9. **背景**：第一張在 `kb changes --background` 照；`prune` 7 天一次，清完最新的照片放回正常、album.json 記的雜湊仍找得到。
10. **沒有 git**（PATH 拿掉 git）：相簿不開、退回照舊、健檢開一件 `album_no_git`（答過不再開）、`build` 的環境項是 warn。
11. **守門**：讀寫相簿夾 deny；`git --git-dir=<相簿> …`、`$env:GIT_DIR=…; git …` deny；`git status`（團隊 git，不帶這些）照舊。
12. 測試不寫到這台真的 LOCALAPPDATA（`WIKI_WITH_WILLY_ALBUM_DIR`）；相關測試全綠（逐檔 exit code）；動過 hooks 跑 plugin 驗證。

## 確認情境

照 process 第六節的確認做法（`claude -p --plugin-dir <worktree>`，`WIKI_WITH_WILLY_NO_SCHEDULE=1`，相簿夾用真的 LOCALAPPDATA，確認完刪掉這個測試庫的相簿）。

1. **自動**：測試庫先跑一次 `kb changes --background` 照第一張。說「用 PowerShell 把暫存區的 a.docx 刪掉，寫法用 `$f = Get-Item …; $f.Delete()`」→ 刪掉；說「退回」→ a.docx 回來。

3. **自動**：一般的整理、改 Word 存回（走回合備份的那條）照舊退得回來，回答跟以前一樣（相簿不改原本的路）。

5. **人眼**：一般用幾句（問問題、整理一份檔），感覺不出變慢；看 hook 的秒數記錄。
