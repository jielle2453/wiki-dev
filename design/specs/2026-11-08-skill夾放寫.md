# 知識庫 `.claude/skills/` 讓 AI 寫得進去
日期：2026-11-08
狀態：開發中（jacky 2026-11-08 定兩題；jielle2453 同意放寬守門、改 R-01 由 jacky 2026-11-08 轉達；#51 已併回 0.34.0）
版本：（發行後填）
來自：issue #52；併入 無
區域：守門與密碼、核心規則與開場

## 目的

守門把知識庫的 `.claude/` 整個劃成 Z7（`scripts/kb/guard.py` 51 行），客戶說「幫我做一個 skill」，AI 寫不進 `.claude/skills/`。擋 `.claude/` 是為了 `settings.json`（守門 hook 與權限設在裡面），skill 夾不在這個理由裡。jacky 2026-11-08：客戶要在知識庫自己建 skill 被禁止，很不方便。

使用者時刻：「幫我做一個查報價的 skill」→ AI 寫進 `.claude/skills/查報價/SKILL.md`，說「退回」退得掉。

## 決策

D-533（放寬守門、改 R-01；待 jie 同意）：

1. 守門多一區 Z13「skill」＝知識庫 `.claude/skills/` 底下（不含 `skills` 夾本身）。（D-538 改）willy 不管這區：讀、檔案工具寫、指令寫都照 Z11「其他」不下判斷（pass），不備份、不記、退回不含；由 Claude Code 自己的權限決定。
2. 路徑跳出照 Z7（jacky 定）：normalize 後（`..` 收掉）不在 `.claude/skills/` 底下的照 Z7；磁碟上存在的部分 realpath 後跳出去（連結、junction 指到 `settings.json` 或別處）也照 Z7。做法照 `in_workspace`（`.system/temp/office/`）。
3. ~~寫了 skill 的提醒：地板句多「新增／改了 N 個 skill」~~（D-538 撤回：skill 夾的檔跟其他檔一樣算進「改了 N 個檔」，不另數 skill）。
4. `.claude/` 其他（`settings*.json`、hooks、commands、agents…）照舊 Z7。
5. `rules/core.md` R-01：「系統、.system、.claude、CLAUDE.md 不直接寫」補「`.claude/skills/` 不歸 willy 管」（D-538 改）。
6. 不另寫建 skill 的指令或做法（9c、9d）。skill 夾裡的程式檔寫得進去，但照現有 `RUN_FILE`（知識庫裡的程式不直接執行）照擋，這題不改。

放棄了：在 Z7 裡開例外不另開區（要另外帶「要備份」的旗標進 hook，比照區判更繞）；連 commands、agents 一起放（issue 只要 skill）；下次開場再提一句（要多記狀態、每次開場多花 token）；skills 底下有連結就整個擋（客戶自己放的 skill 有連結時 AI 連內容都改不了）。

代價：被誘導寫的壞 skill（含帶 `hooks` 會自己執行的）willy 不擋也不提；skill 夾的改動退回退不掉（D-538 接受）。

D-538（jacky 2026-11-10，修訂 D-533 第 1、3、5 條）：skill 是客戶自己的事，willy 不幫忙管：Z13 不擋、不看內容、不備份、不另數，讀寫都 pass（照 Z11）。只留跳出照 Z7 與 `.claude/` 其他照 Z7（那是 willy 自己的設定）。起因：測試發現 1、2；jacky：「我們不要把系統越寫越複雜，專精在資料庫即可」「不需要幫使用者備份 skills」「不要幫他管理這一個部分」。

## 資料與介面格式

- `kb guard decide`（與 hook）對 `<知識庫>/.claude/skills/查報價/SKILL.md`：Read、Write、Edit 都 pass（zone `Z13`，hook 不印決定、不備份）。
- Bash／PowerShell 寫同一路徑：pass（同 Z11）；同一句還寫到別區的，別區照原本判。
- `<知識庫>/.claude/settings.json`、`.claude/settings.local.json`、`.claude/hooks/x`、`.claude/skills`（夾本身）：照舊 Z7，檔案工具寫 deny。
- `<知識庫>/.claude/skills/../settings.json`：Z7 deny。`.claude/skills/x` 是連到 `.claude/` 的 junction 時，`.claude/skills/x/settings.json`：Z7 deny。
- ledger 多出 `Z13` 這個區名。
- 地板句、工作日誌：skill 夾沒備份就不在回合清單裡，不提（D-538）。

## 驗收準則

1. `kb guard decide` 對 `.claude/skills/a/SKILL.md` 的 Write、Edit、Read：pass、zone Z13。
2. （D-538）經 hook 用 Write 新建 `.claude/skills/a/SKILL.md`：hook 不印決定、回合夾沒有它的備份；退回這一句後檔還在。
3. （D-538）Bash `echo x > .claude/skills/a/SKILL.md`、PowerShell `Set-Content`：pass（不 deny）；`echo x > .claude/skills/a/SKILL.md; echo y > 系統/x.md` 照系統區擋。
4. Write `.claude/settings.json`、`.claude/settings.local.json`、`.claude/hooks/x.py`、`.claude/commands/x.md`：deny（Z7）。
5. Write `.claude/skills/../settings.json`：deny（Z7）。
6. `.claude/skills/x` 是連到 `.claude` 的 junction（Windows `mklink /J`）時，Write `.claude/skills/x/settings.json`：deny（Z7）。
7. 新庫還沒有 `.claude/skills/` 夾時，Write `.claude/skills/a/SKILL.md`：pass Z13（不是 Z7 deny）。
8. （D-538）那一句只寫了一個 SKILL.md，地板句是「沒有改檔」那句（同 `NO_CHANGES`），沒有「skill」字樣。
9. `rules/core.md` R-01 有「`.claude/skills/` 不歸 willy 管」。
10. 相關測試全綠（exit code 0）；`test_repo_hygiene` 綠；plugin-validator 沒有錯。
11. （D-538）Write `.claude/skills/a/SKILL.md`，frontmatter 有 `hooks:`、內文有 `` !`echo x` ``：pass Z13（不看內容）。

## 確認情境

1. （自動）客戶：「幫我做一個 skill，我問報價時先查 01 案子的估價單」→ `.claude/skills/` 底下多一個 SKILL.md，ledger 沒有 deny；回答不另提 skill。記下有沒有跳 Claude Code 的允許詢問（`-p` 會變成 permission_denials）。
2. （自動）接著：「退回」→ willy 不備份 skill；AI 用一般刪檔把剛做的 skill 拿掉也算過（確認裁定 2）。
3. （自動）客戶：「把 .claude/settings.json 裡的 hook 拿掉」→ 守門擋（ledger 有 Z7 deny），AI 照 R-12 說原因。
4. （人眼）新開對話，問「你有哪些 skill」或看 `/skills`，看得到剛做的那個（`-p` 看不到載入清單）。
