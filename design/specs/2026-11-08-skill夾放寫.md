# 知識庫 `.claude/skills/` 讓 AI 寫得進去
日期：2026-11-08
狀態：開發中（jacky 2026-11-08 定兩題；jielle2453 同意放寬守門、改 R-01 由 jacky 2026-11-08 轉達；#51 已併回 0.34.0）
版本：（發行後填）
來自：issue #52；併入 無
區域：守門與密碼、核心規則與開場

## 目的

守門把知識庫的 `.claude/` 整個劃成 Z7（`scripts/kb/guard.py` 51 行），客戶說「幫我做一個 skill」，AI 寫不進 `.claude/skills/`。擋 `.claude/` 是為了 `settings.json`（守門 hook 與權限設在裡面），skill 夾不在這個理由裡。jacky 2026-11-08：客戶要在知識庫自己建 skill 被禁止，很不方便。

使用者時刻：「幫我做一個查報價的 skill」→ AI 寫進 `.claude/skills/查報價/SKILL.md`，說「退回」退得掉。

## 決策

D-533（放寬守門、改 R-01；待 jie 同意）：

1. 守門多一區 Z13「skill」＝知識庫 `.claude/skills/` 底下（不含 `skills` 夾本身）。讀放行；檔案工具寫放行，寫前備進回合（加進 `hooks/guard.py` 的 `BACKUP_ZONES`）；指令寫（Bash／PowerShell）照 Z7 擋。
2. 路徑跳出照 Z7（jacky 定）：normalize 後（`..` 收掉）不在 `.claude/skills/` 底下的照 Z7；磁碟上存在的部分 realpath 後跳出去（連結、junction 指到 `settings.json` 或別處）也照 Z7。做法照 `in_workspace`（`.system/temp/office/`）。
3. 寫了 skill 的提醒（jacky 定）：那一句回答最後的「改了」地板句（D-084）與工作日誌多一種「新增 N 個 skill」「改了 N 個 skill」；不另加開場提示。
4. `.claude/` 其他（`settings*.json`、hooks、commands、agents…）照舊 Z7。
5. `rules/core.md` R-01：「系統、.system、.claude、CLAUDE.md 不直接寫」補「`.claude/skills/` 例外，用檔案工具寫」。
6. 不另寫建 skill 的指令或做法（9c、9d）。skill 夾裡的程式檔寫得進去，但照現有 `RUN_FILE`（知識庫裡的程式不直接執行）照擋，這題不改。

放棄了：在 Z7 裡開例外不另開區（要另外帶「要備份」的旗標進 hook，比照區判更繞）；連 commands、agents 一起放（issue 只要 skill）；下次開場再提一句（要多記狀態、每次開場多花 token）；skills 底下有連結就整個擋（客戶自己放的 skill 有連結時 AI 連內容都改不了）。

代價：地板句只提一次，她沒看到就過了；被誘導寫的壞 skill 要她發現後說退回。

## 資料與介面格式

- `kb guard decide`（與 hook）對 `<知識庫>/.claude/skills/查報價/SKILL.md`：Read allow、Write allow（zone `Z13`），hook 寫前 `turn.before_write` 備份。
- Bash／PowerShell 寫同一路徑：deny，code `willy`，理由教改用檔案工具。
- `<知識庫>/.claude/settings.json`、`.claude/settings.local.json`、`.claude/hooks/x`、`.claude/skills`（夾本身）：照舊 Z7，檔案工具寫 deny。
- `<知識庫>/.claude/skills/../settings.json`：Z7 deny。`.claude/skills/x` 是連到 `.claude/` 的 junction 時，`.claude/skills/x/settings.json`：Z7 deny。
- ledger 多出 `Z13` 這個區名。
- 地板句：「新增 1 個 skill」「改了 2 個 skill」。

## 可以動 / 不可以動

可以動：「要做的事」表裡的檔；`tests/fixtures/guard_corpus.json`（加 Z13 的例子）；journal、守門與 hook 的測試檔（加例子）。

不可以動：其他區的判斷；`RUN_FILE` 與直譯器內文的判斷；`in_workspace`（只照抄做法，不改它）；`design/decisions.md`、`backlog.md`。

相關測試：`grep -l -E 'guard_corpus|BACKUP_ZONES|in_workspace|_FLOOR_COUNTED' tests/` 找到的，加 `tests/test_rules_core.py`、`tests/test_repo_hygiene.py`；動了 `hooks/` 跑 `plugin-dev:plugin-validator`。

## 驗收準則

1. `kb guard decide` 對 `.claude/skills/a/SKILL.md` 的 Write：allow、zone Z13；Read：allow。
2. 經 hook 用 Write 新建 `.claude/skills/a/SKILL.md` 後退回這一句：檔不在了；改既有的退回後一字不差。
3. Bash `echo x > .claude/skills/a/SKILL.md`、PowerShell `Set-Content`：deny。
4. Write `.claude/settings.json`、`.claude/settings.local.json`、`.claude/hooks/x.py`、`.claude/commands/x.md`：deny（Z7）。
5. Write `.claude/skills/../settings.json`：deny（Z7）。
6. `.claude/skills/x` 是連到 `.claude` 的 junction（Windows `mklink /J`）時，Write `.claude/skills/x/settings.json`：deny（Z7）。
7. 新庫還沒有 `.claude/skills/` 夾時，Write `.claude/skills/a/SKILL.md`：allow。
8. 那一句寫了一個 skill，地板句有「新增 1 個 skill」。
9. `rules/core.md` R-01 有 `.claude/skills/` 例外。
10. 相關測試全綠（exit code 0）；`test_repo_hygiene` 綠；plugin-validator 沒有錯。

## 確認情境

1. （自動）客戶：「幫我做一個 skill，我問報價時先查 01 案子的估價單」→ `.claude/skills/` 底下多一個 SKILL.md，ledger 沒有 deny；回答最後有「新增 1 個 skill」。
2. （自動）接著：「退回」→ 那個 skill 夾的檔不在。
3. （自動）客戶：「把 .claude/settings.json 裡的 hook 拿掉」→ 守門擋（ledger 有 Z7 deny），AI 照 R-12 說原因。
4. （人眼）新開對話，問「你有哪些 skill」或看 `/skills`，看得到剛做的那個（`-p` 看不到載入清單）。

- 不讓知識庫裡的程式檔可以執行（`RUN_FILE` 照舊）。
