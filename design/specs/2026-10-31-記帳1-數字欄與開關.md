# 記帳 1：數字欄、記帳開關、格式版本與歷程合併
日期：2026-10-31（11-08 照 D-335～D-343 改寫）
狀態：設計中（11-08 照 D-335～D-343 改寫，待使用者看過定稿）
版本：（發行後填）
來自：issue #27（記帳，三份 spec 的第 1 份）；併入 B-530
區域：記帳、設定與知識、整理成卡、狀態檔格式、升級與發行

## 目的

記帳要算庫存、毛利、還欠多少，得先有程式讀得準的數字，也要先把多人共用時會出事的地基補好。這份做四件：

1. **數字欄**：設定檔第九節按型別定欄（售價、進價、每箱、安全庫存…），值存在實體上、一個數字一欄（D-336），顯示在綜合卡檔頭（Obsidian 屬性欄），她說的值檔案蓋不掉。
2. **記帳開關與地點**：設定檔第十節一列（開／只記我講的／關，加「地點的型別」）；第五節成員名單每人可記「平常在哪」（D-342）。後兩份 spec 照它們決定怎麼記。
3. **格式版本照大升級走**（D-335）：狀態檔自己的版本號不升，舊庫要補的由遷移表看內容判斷；這版遷移表有新列，流水檔格式版本 1→2，發行程式守「遷移表有新列就要升」。
4. **歷程清單合併不算撞到**（D-337，收 B-530）：日程（0.33.0 已發行）與之後的帳每筆的 `history`，兩台各自加的行合起來都留。

使用者時刻：她說「精華液售價 1800、進價 1200、一箱 24 瓶」→ 打開精華液那張卡，屬性欄看到這三個數字；她在 Obsidian 屬性欄把售價改成 2000 → 下一句話 Claude 照她改的記下來。小王改了日程的日期、小美同時在同一條加了備註 → 同步後兩邊都在，不被當成撞到。

**三份 spec 的分工**（各自一次實作做得完，照順序做；使用者 10-31 定）：1 地基（這份）→ 2 帳（資料、指令、分店、報帳、關的時候的口述、note、查帳、製卡抽錢、建置）→ 3 畫面（帳頁、外掛畫的卡底下、日程畫面讀帳、首頁）。實作與測試照份跑；**確認三份做完後一起做一次、發行一次**（0.34.0，大升級）。

## 決策

- D-272（D-281 定案）：程式要算的數字是實體的欄位，正本在實體清單、檔頭由程式顯示；AI 只經 `kb` 設值；改值留舊值；算出來的（庫存、已收、未收）只顯示不是欄。
- D-281：第九節按型別定欄；值由製卡（推測）與她講的設；她講的檔案蓋不掉；兩份檔不一樣日期新的蓋舊的，分不出新舊開待處理問她。
- D-336：實體上一個數字一欄 `欄:<欄名>`，值、來源、出處卡、文件日期、舊值都收在那一欄。
- D-335：狀態檔自己的 `schema_version` 凍結（設定檔 7、實體 3 不動）；新欄新節一律選填；遷移看內容；遷移表有新列＝大升級＝`streams.FORMAT_VERSION` +1，發行程式或測試守。
- D-337：流水檔種類登記時標「只往後加」的欄，合起來時各行的清單聯集、不算撞到，退回只拿掉自己那一行。
- D-343：開關三種的效果（這份只做開關本身；三種各自擋什麼在第 2 份）；數字欄不算錢，不管開關都照記。
- D-339 (3)：記帳開關全隊一份（照 D-290）。
- D-342 (1)(3)：第十節多「地點的型別」；第五節成員多「平常在哪」（怎麼用在第 2 份）。
- 使用者 11-08 說可以（原「這份 spec 新定」）：
  1. 開關放第十節「記帳」：一列的表（狀態、地點的型別），跟其他節同一支解析器。
  2. 預設：`kb init` 新庫是「開」；舊庫升級時由遷移表補第十節，補「只記我講的」（免得一升級就回頭讀幾百張舊卡抽錢）。
  3. 欄名不能是程式算的名字（庫存、累計收、累計付、未收、未付）、不能是檔頭既有的鍵（編號、型別…）、不能跟同型別第八節的標籤欄同名。
  4. 第九節刪掉一欄（`kb profile remove`，或 AI／她直接改 md 再 `kb profile apply`，D-307）：實體上那欄的值拿掉、舊值留著，檔頭那行拿掉，成功句講幾個實體受影響。
  5. 她說清掉（「膠囊不賣了，售價不用記」）：那欄的值設成空，算她說的，舊值留著。
- 改 spec 時定（不另開 D）：她講到第九節沒有的數字（「膠囊會員價 1600」）→ AI 照 D-307 直接加欄、記值、說一聲「在產品加了一欄『會員價』」；一次性的價格（「這次給她算 1,500」）寫成帳那筆的單價（第 2 份），不加欄。

## 資料與介面格式

`profile.json`（`schema_version` 仍是 7）多的兩節與第五節的欄：
```json
"fields": [{"type": "產品", "field": "售價", "unit": "元", "source": "interview", "date": "2026-10-31"}],
"money":  [{"mode": "on", "places": ["分店"], "source": "inferred", "date": "2026-10-31"}],
"about":  [{"name": "小王", "kind": "person", "aliases": [], "place": "北店", "source": "said", "date": "…"}]
```

`系統/客戶設定檔.md` 第九、十節：
```
## 九、數字欄
（提示句）
| 型別 | 欄名 | 單位 |
|---|---|---|
| 產品 | 售價 | 元 |

## 十、記帳
（提示句）
| 狀態 | 地點的型別 |
|---|---|
| 開 | 分店 |
```

實體（`entities.json` 衍生副本，`schema_version` 仍是 3）一筆多：
```json
"欄:售價": {"value": 1800, "from": "said", "card": null, "doc_date": null, "at": "2026-10-31T10:00:00",
           "old": [{"value": 1600, "from": "card", "card": "f-1a2b3c4d", "at": "2026-09-01T09:00:00", "who": "小王"}]},
"欄:每箱": {"value": 24, "from": "card", "card": "f-1a2b3c4d", "doc_date": "2026-09-01", "at": "…", "old": []}
```

綜合卡檔頭（標籤行後面）：`售價: 1800`、`每箱: 24`。

`kb entity field 精華液 售價=1,800 --said --json`：
```json
{"entity": "精華液", "changed": {"售價": [1600, 1800]}, "kept": [], "conflicts": [], "card": "03 產品/精華液/精華液.md"}
```
`kb cards todo --json` 的 `profile` 塊多 `"fields": {"產品": [{"field": "售價", "unit": "元"}]}` 與 `"money_mode": "on"`。

流水檔一行（D-335 之後）：`{"v": 2, …}`；`streams.KINDS` 旁多 `APPEND_ONLY = {"agenda": ("history",)}`。
