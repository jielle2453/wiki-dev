# 帳：錢的話怎麼記

客戶講到收、付、賣、進貨、欠、尾款、繳費、盤點、墊錢、調貨時照這份做（記帳 2，D-271～D-277、D-338、D-342、D-343）。帳由程式算庫存、已收、未收，不要自己心算、不要把數字寫進綜合卡。售價、每箱這類固定數字與「我調到南店了」照 `references/fields.md`。程式輸出裡以 `kb ` 開頭的指令，換成開場段的 kb 指令前綴再跑。

## 一、先看開關

`kb profile show --json` 的 `money_mode`（設定檔第十節）：

| 狀態 | 她講的錢 | 怎麼記 |
|---|---|---|
| `on`（開） | 進帳 | 第二節 |
| `spoken`（只記我講的） | 進帳 | 第二節（檔案裡的錢整理時不抽，程式擋） |
| `off`（關） | 記成口述加記號 | 第三節；不擋、不問要不要開帳、不說「帳沒開」 |

## 二、記進帳（開、只記我講的）

### 怎麼分（D-273、D-274）

- 一句話裡**錢易手的部分**進帳，其他有日期的事進日程（`references/agenda.md`）：「11/30 交屋，交屋時付尾款 120,000」→ 日程「交屋」＋ 帳 `--due 2026-11-30` 應收尾款。沒講金額照記，金額未知（不給 `--amount`）。
- 只記**做生意的錢**（她收客戶的、付廠商工班的、進貨、送客戶的禮、跑業務的油錢）。薪水、生活花費不記，說一句「帳只記生意上的錢」。
- 方向：她收 `--dir 收`、她付 `--dir 付`、只動數量不涉錢（調貨、送人、自用、壞掉）`--dir 無`。

### 指令

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" money add --dir 收 --amount 5000 --entity 李小姐 --item "精華液 -2" --item "膠囊 -1" --text 賣出 --json
```

- `--date` 收付那天；`--due` 到期日（還沒收付）；兩個都沒給＝今天已收付。
- `--item "<商品> <±數量>[單位][@單價][在<地點>]"`，可重複：賣出是負、進貨是正。數量只在東西真的進出時寫（賒帳先拿貨照寫；先訂還沒出貨的不寫，出貨那天再記一筆只有數量的 `--dir 無`）。
- **一次性的價格**（「這次算她 1,500」）寫成那個品項的單價 `@1500`，不加數字欄；固定的售價、進價照 `references/fields.md`。
- 多品項一筆，總價照她講的記（D-277）；各品項沒講單價不要自己拆。
- 成功句是輸出的 `tell`，照它複述，加一句「不對說一聲可以退回」；輸出有 `low_stock` 就照說「精華液剩 4 瓶，低於安全庫存 5」（D-282）。
- 要編號（settle、edit、cancel 用）從 `--json` 取，不唸給她。

### 可能同一筆（D-276）

`add` 回 exit 3、`refused: candidates`：程式找到同實體同方向、金額相同、日期相近的，或同實體同方向還沒收付的（`open: true`）。

| 看起來 | 怎麼做 |
|---|---|
| 明顯是同一筆（她講過，現在又講一次） | 不另記；說「這筆之前記過了」 |
| 她講的是那筆未收付的收付了 | `kb money settle <編號>`（金額不夠照下一段拆） |
| 明顯是另一筆（不同天又賣一次） | 原指令加 `--new` |
| 看不出 | 加 `--new --unsure <那筆的編號>`：記進去並開一條待處理問她 |

`kb money candidates --dir 收 --amount 5000 --entity 李小姐 --json` 可以先查不寫。

### 收付了、部分收付、重複

- 「王先生付了」：`kb money settle <編號>`（`--date` 是收付那天，沒給今天）。金額未知的要給 `--amount`。
- 「先付了 10 萬，剩下下個月」：`settle <編號> --amount 100000 --due <下個月的日期>`，程式拆成已收 100,000 與未收 20,000（D-275），照成功句講兩筆。
- 一次付清好幾筆就每筆各 settle；付的是哪一筆看不出（同一個人兩筆未收）先問她。
- 每月房租、年繳保費：`add … --due <下一次> --repeat 每月`；付了 `settle`，程式另記一筆已付、原筆移到下一次。
- 改：`kb money edit <編號> --amount／--date／--due／--entity／--item／--text／--note`；記錯了不要：`kb money cancel <編號>`。
- 兩筆是同一筆：`kb money merge <留的> <併掉的>`。

### 單位、盤點

- 單位照她講的寫進 `--item`（「進 2 箱」寫 `益生菌 +2箱`，沒講就不寫），不要自己換算；程式照記，算庫存時才換（D-344）。一個商品只用一種單位的照記、不問。
- 程式退回說「換不成同一個單位」（這個商品沒用過、又換不過去的單位才退）：照句子問她一次大的裝幾個小的（一箱幾瓶；哪個大不確定也問她，不要猜），答了設 `每<大的>=<整數>`、欄的單位是小的（先 `kb profile add` 再 `kb entity field`，`references/fields.md`），不設小數；之前沒寫單位的那筆問她是什麼單位，`kb money edit` 補上。再照原句記。成功句會講出換算（「精華液 +2 箱（48 瓶）」），照它複述。
- 成功句或庫存出現「（不知道一箱幾瓶）」：照念，問她一次一箱幾瓶，答了照上面設欄；她不知道就算了，之後不再追問（只會分開列，不會加錯）。
- 盤點（「北店益生菌實際只剩 10 盒」）：`kb money count 益生菌 --actual 10盒 --place 北店`，程式算差、記一筆調整，不直接改庫存。

### 分店與調貨（D-342）

- 設定檔第十節「地點的型別」有值（分店、倉庫）才有地點；品項加 `在北店`。地點要是那個型別的實體，填了別的程式擋。
- 第一次聽她講到分店、倉庫而第十節沒寫：`kb profile add 記帳 地點的型別=分店` 補上、說一聲。
- 調貨（「從北店調 5 盒去南店」）：一筆 `--dir 無 --item "益生菌 -5 在北店" --item "益生菌 +5 在南店" --text 調貨`。
- 多人時成員沒講地點，程式照設定檔第五節他的「平常在哪」填，成功句會講出地點；照它複述讓他看得到。這句講了別的地點就照講的。

### 報帳（D-338，多人才有）

- 「我墊了文具 3,200」：`add --dir 付 --amount 3200 --advanced-by <說話的人> --entity 文具店 --text 文具`，記成未付。
- 還他了：`settle <編號> --date <還錢那天>`。「還欠小王多少」：`kb money sum --from <很早> --to <今天> --advanced-by 小王 --json` 的 `open_out`，或 `kb lookup 小王`。
- 單人知識庫沒有墊的人（程式擋），照一般付款記。

### 改日期問另一邊（D-273）

- `kb money edit <編號> --due <新日期>` 的輸出有 `related_agenda`（同實體、原本那天的日程）：問「交屋也一起改到 12/10 嗎？」，說要才改日程。
- 改日程日期時程式回的 `related_money` 也一樣，問了才改帳。不自動連動。

## 三、帳關著（off）

她講的錢記成口述加記號（D-343）；講到人或案子就掛，沒講到也照記：

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" statement add --text "幫公司收了王先生 5,000" --entity 王先生 --money 收 5000
```

- 有後續要做的（「明天交回公司」）照舊另加日程。
- 問加總（「這個月幫公司收了多少」）：`kb money sum --from <月初> --to <今天> --json`，`source` 是 `statements`，照程式的數字答、附逐筆。不提「帳沒開」。
- `kb money add` 這類寫入關著時會被擋（exit 3）；照上面改記口述，不跟她提。

## 四、改成開或只記我講的：補帳

`kb profile add 記帳 狀態=開` 的輸出有 `backfill`（之前記成口述的錢幾句、要抽錢的舊檔案幾份）：問她一次「之前記下的 N 筆錢要補進帳嗎？」

- 要：`kb money backfill --json` 列出那幾句，每句 `kb money add --from-statement <s-…> --dir … --amount … --entity …`（程式照那天記、標出處）。被 `candidates` 擋就照第二節判斷，已經在帳裡的不補。
- 舊檔案要抽錢的走整理（份數多照整理的規矩先問）。
- 不要：不補，之後她說再補。

## 五、問帳

照 answer 的 `references/find.md`「錢與庫存」：欠多少、收多少、庫存都叫 `kb money` 或 `kb lookup`，不心算。
