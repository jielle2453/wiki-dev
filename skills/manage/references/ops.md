# 整個知識庫的操作參考（備份、還原、清空間、換位置、換電腦、換帳號）

## 共通

- 叫法同本 skill 本文：`python "${CLAUDE_PLUGIN_ROOT}/scripts/kb.py" <子命令> …`。都收 `--json`；人讀輸出不印編號與回合代號，照轉述。
- exit code：0 做了（或只是查）；3 拒絕或沒做成，第一行就是原因，照下面「常見拒絕」那一列做（表裡沒有的：轉述那一句、說這次沒有做成）；2 是不在知識庫裡（`不在知識庫裡：…`）；其他（印出 Traceback）轉述、說這次沒有動到。
- 這些都只管知識庫裡的東西；她原本登記的資料夾（原檔）不在備份裡，要她自己的備份顧（問「備份裡有我的原始檔嗎？」就這樣答）。
- 所有有寫入的（備份、還原、清理、`moved`）送出最終回答前跑 `kb turn note "<白話一句>"`（R-13）；對話裡跑時工作日誌靠這一句，終端機跑的程式自己記一段。

## 退回與還原怎麼分

- 「上一步、剛剛、昨天那次整理」是**退回**（`kb versions`，R-05；`list` 印的就是「10-23 14:05 那句「…」」，照念、不唸代號）；「備份、那一份、整個回到某天」是**還原**。
- 分不清（例如「回到昨天」）就問一句：「是退回剛剛那一步，還是回到某一天的備份？」
- 退回超過保留期退不回：最早能退到哪一句看 `versions clean --check` 印的「最早還能退回到 …」；有備份就提還原。

## backup：備份整個知識庫

`backup [--to "<夾>"] [--check]`

- 第一次沒記過放哪：`backup --check --json` 的 `need_to` 是 true（人讀 `backup` 印 `還沒說備份要放哪`、exit 3）。問她放哪（隨身碟、OneDrive、Dropbox、其他磁碟；不收網路位置，`\\` 或 `//` 開頭的路徑會被拒絕，NAS 請她先對應成磁碟機），
  `--to "<夾>"` 帶上再跑，程式記住；之後不用再給，換位置也是 `--to`。
- `--check --json`：`to`、`need_to`、`files`、`bytes`、`sync_folder`、`refuse`；一律 exit 0。`sync_folder` 是 true 說一句：
  「放在雲端同步的夾，會上傳到雲端，第一次比較久。」`refuse` 有字就照下面拒絕表講，不去跑。
- 成功：`備份好了：<路徑>（1234 份、30 MB）；那裡留最近 3 份。`，下一行接清理那句（見 clean）。照念；她問到才講備份只包知識庫。
- 同一天再做會是 ` (2)`；那個夾裡別人的檔、別個知識庫的備份不碰，只替我們做的備份留最近 3 份。
- 不排程：問「每天自動備份」就說不做，想到說「幫我備份」就好。

## restore：還原（先演練、說好才做）

- `restore list [--from "<夾>"]`：這台電腦記的備份夾與 `--from` 的，加知識庫裡的快照，新的在前。人讀一行一份：`10-15 14:05｜備份｜LIN-PC 做的｜30 MB`
  （不能用的後面接 `｜不能用：原因`）。要路徑與名字取 `--json`（`name`、`path`、`kind`、`created`、`machine`、`bytes`、`usable`、`why`）。
  客戶說「上禮拜那份」就從日期找；找不到就請她用 `--from` 指備份夾（空資料夾還原、備份在隨身碟時）。
- `restore check "<zip 路徑或快照名>"`：**只讀**，不動任何東西。先講完再問，她說好才 `apply`。
  - 第一行 `會回到 10-15 14:05 的樣子`，接 `這份是 LIN-PC 做的備份`；再一類一行，只列有的：`口述：會不見 3 條（「…」、「…」）；會回來 1 條`；
    類別有口述、裁示、日程、推算、實體、檔案卡、綜合卡、AI 產出、工作日誌；最後 `你原本的資料夾不會動`。綜合卡的「會不見」包含內容不同的，講成「會變回舊的版本」。
  - 怎麼講：「會回到 10 月 15 日下午的樣子。這段時間記的口述 3 條、日程 2 條會不見（例如『信義王的設計師換成小陳』），你原本的資料夾不會動。要還原嗎？」
    數字照程式、例子照程式，不自己估；一類都沒有就說「跟現在幾乎一樣」。
  - 多一行 `你設成不想讓 AI 看到的「X」會留著，還原後再清一次`：照講。多一行 `建置會回到做到一半的…那一步`：照講，下次打 build 接著做。
  - 擋住時第一行是原因（exit 3），照下面拒絕表講。
- `restore apply "<zip 路徑或快照名>"`：先拍快照（還原前）、解開驗過、換進去；失敗全部移回、什麼都沒動。
  成功：`已還原到 10-15 14:05 的備份；說「剛剛的還原不要了」可以回到還原前。還原後有 N 份要重新整理。` 照念；N 大於 0 說「還原後開場會看到變動，照常整理就好」。
  沒有還原前快照時（空資料夾，或現在有還沒清完的不想讓 AI 看到的夾、快照整包清掉了）第一句改成 `…這次沒有還原前的快照，回不到還原前。…`，照念、不說「還原不要了」。
  她新增的原檔沒動。後面可能多幾行，照講：`你設成不想讓 AI 看到的「X」留著、也再清了一次`（這夾的卡、清冊條目都會拿掉；那時 `--json` 的 `snapshot` 還在就是還原前快照留著，null 就是清掉了，句尾多 `（還原前的快照也一起清掉了）`）、
  `不想讓 AI 看到的夾還沒清完：…`（照 `references/sources.md` 的 purge 做）、`建置停在「X」那一步，下次打 build 從那裡接著做`、`還原好了，但有一步沒做完：<哪一步>（原因），<怎麼補>`（換進去已經成功，只是後面補骨架之類那步沒做完：照念，先說還原好了、再說哪一步與怎麼補）。「沒做完」的句子都是「沒做完：<哪一步>（原因），<怎麼補>」這個順序。
- **「剛剛的還原不要了」**：`restore list --json` 取最新的、`kind` 是 snapshot 而且名字帶「（還原前）」那份，一樣先 `check` 講、說好才 `apply <快照名>`。
- **知識庫整個被刪**：先請她看資源回收筒；沒有就在原位置開一個空資料夾、在那裡開對話，`restore list --from "<備份夾>" --json` → 拿那一份的 `path` 給 `check`、`apply`（空資料夾裡只收完整路徑，不收檔名）。
  桌面版這次會跳「允許嗎」，請她按允許。沒有備份就照實說救不回，原檔還在，可以重新建置。
- 有知識庫時還原不覆蓋這台電腦的知識庫編號與位置紀錄；空資料夾還原用備份裡的位置紀錄，開場看到「換了位置」或「第一次開」才跑 `kb moved` 補，沒看到就不用。
- `check` 多一行 `這份是另一個知識庫的備份，不是這個知識庫自己的`（`--json` 的 `other_vault` 是 true）：先跟她說「這份是另一個知識庫的備份」，再問要不要繼續；她說要才 `apply`（照樣放行）。

## clean：空間不夠、清放太久的備份

`versions clean [--check]`（備份做完會自動接著跑；說「C 槽快滿了、知識庫怎麼越來越大」先 `--check` 講，她說好才不帶 `--check` 跑：清掉的回合備份就退不回了）

- 回合備份超過 30 天或 200 個就從最舊的清，至少留最近 20 個；快照留 2 份；正在做的不清。
- 成功：`清掉 12 個回合備份、1 份快照，空出 8 MB；最早還能退回到 09-23 10:02 那句「把這份合約存起來」。`；沒得清：`沒有要清的；最早還能退回到 …`。
  `--check` 同格式、不動。講：清掉什麼、空出多少、最早還能退回到哪一句，照程式的數字講，不自己判斷空間被誰佔。
- 問「多久自動清一次」：備份做完會清，說空間不夠也能當場清；沒有排程。

## moved：換了位置、換了電腦

開場出現 `知識庫換了位置：…` 或 `這台電腦第一次開這個知識庫：…` 就跑 `moved`（只是把舊路徑換新路徑，不用先問）；想先看再做才用 `--check`。

- `--json`：`state`（same｜moved｜new_machine｜first）、`from`、`to`、`sources_rewritten`、`cards_relinked`、`missing_sources`、`old_copy`、`env`、`passwords_missing`。
- 人讀一行一件（沒有要補的是 `位置沒變，沒有要補的`、第一次是 `第一次看這個知識庫，位置記下了`），照著逐件處理：
  - `來源「X」的位置換成新的了`、`卡的開原檔連結更新了 N 張`：講一句做了什麼；說「退回」換得回來。
  - `這台找不到的來源：A、B`：一個一個問她新位置（請她從檔案總管貼），用 `kb folders relocate`（`references/sources.md`）接上。
  - `舊位置還有一份：<路徑>；確認新的沒問題就把舊的刪掉（我不代刪）`：照講，不代刪。
  - 換電腦時多的幾行是這台缺的元件（照那句講、跑它給的指令）與「憑證管理員沒有這些密碼，要重新記」：密碼不會跟過來，請她逐個重說（走 note 的 `kb unlock`）。
- 她要搬整個知識庫時**只講步驟，不代搬**：先關這個對話、用檔案總管剪下貼上、在新位置開對話、開場會自動補。守門擋我自己搬時也是這樣講。
- 換電腦：新電腦先裝 Python、Claude、plugin（請服務人員）；知識庫用備份還原（推薦）或直接拷資料夾；第一次開對話跑 `moved`，一次列出要補的。

## 換帳號

`output links [--json]`（只讀）：列存成連結的線上文件，一行 `標題（日期）`；沒有印 `沒有存成連結的線上文件`。講三件事：

1. 知識庫與 plugin 不受影響，照常用。
2. 舊帳號做的線上文件，網址在新帳號打不開：請她在舊帳號分享給新帳號，或下載成檔、放進知識庫（下載的檔怎麼掛回去看 produce）。
3. 隱私設定、外部服務（連結的其他服務）要在新帳號重設。

最後固定說一句：**舊帳號處理過的資料不會因為換帳號而刪掉。**

## 舊電腦送人（只說明，不代刪）

請她自己做：刪知識庫資料夾（她的備份要不要留自己決定）、在外掛畫面移除 plugin、刪 `%LOCALAPPDATA%\wiki-with-willy\` 工具夾、
憑證管理員裡 `wiki-with-willy/` 開頭的那幾筆（或先說「忘掉 X 密碼」讓我用 `kb unlock forget`）。她原本的原檔另外處理。

## 常見拒絕與怎麼跟客戶說

| 第一行含 | 怎麼做 |
|---|---|
| `還沒說備份要放哪` | 問她放哪（隨身碟、OneDrive、其他磁碟），帶 `--to` 再跑。 |
| `備份不能放在知識庫裡面` | 「備份要放在知識庫外面，不然備份會越包越大。放隨身碟或另一個夾好嗎？」 |
| `備份不能放在登記的資料夾「X」裡` | 「放在「X」裡會被當成新檔整理，換一個不在讀的地方好嗎？」 |
| `那個位置寫不進去` | 「那個位置寫不進去，隨身碟有插好嗎？」換一個位置。 |
| `空間不夠：要 N MB，那裡只剩 M MB` | 照講數字，請她換個位置或先清空間（還原時還沒動任何東西，連快照都沒拍）。 |
| `背景整理還在跑，先停掉再…` | 照 ingest 的「停」做（`cards stop`），停好再說一次；不自己換方法。 |
| `另一個備份、還原或退回正在跑` | 「另一個動作還在跑，等它做完再說一次。」 |
| `這份不是 wiki-with-willy 的備份` | 「這份不是我做的備份，換一份。」 |
| `這份備份壞了（…）` | 「這份備份壞了，換一份；備份夾裡有別的日期的嗎？」`restore list` 找下一份。 |
| `這份備份是比較新的版本（V）做的，先升級再還原` | 「這份是比較新的版本做的，請服務人員先把 plugin 升級。」 |
| `這個資料夾不是空的，也不是知識庫` | 「還原要在空資料夾或知識庫裡做，請換一個空資料夾。」 |
| `有檔案開著（X），關掉再說一次；什麼都沒動` | 請她關掉那個檔（Word、預覽）再說一次；沒有東西被改。 |
| `還原沒做完：有東西沒能移回去（…），還原前的東西放在 …` | 照念那個位置，請她先別刪那個夾、找服務人員；不要自己再還原一次。 |
| `備份要放在這台電腦的資料夾或隨身碟；網路上的位置請先對應成磁碟機` | 「備份不能直接放在網路上的位置，請先把它在檔案總管對應成磁碟機，或換隨身碟。」 |
| `找不到這份：X` | 跑 `restore list` 念給她，問是哪一份。 |
| `這裡不是知識庫`、`不在知識庫裡：…` | 「程式找不到知識庫，請在總資料夾開對話。」停下來。 |
| `備份沒有做成：…`、`還原沒有做成：…`、`等不到鎖，沒有寫入`、`狀態檔讀不到或寫不進去：…` | 轉述那一句，說這次沒有做成（還原是什麼都沒動），請稍後再試；還是不行請服務人員看。 |
